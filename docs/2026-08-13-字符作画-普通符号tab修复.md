# 字符作画页：普通符号 tab 修复（bug1 + 两处连带问题）

## 动机

todo bug1「普通符号里也有不少emoji，拖动到画布上就变成普通符号了」。实测拆解为三层问题：

1. **渲染误判**：`isEmojiCharacter` 不识别 U+FE0F 变体选择符，带 `️` 的字符（✂️⬆️✔️〰️ 等 15 个）被误判普通符号 → 拖到画布变 44px 深绿。
2. **判断过宽**：2600-26FF 区间 + `\p{Emoji}` 属性判断把有 text 变体的字符（⚙☯♻ 等）误判 emoji，与其 text 变体用途冲突。
3. **数据分类不纯**：普通符号 tab 手写分组混入 6 个纯 emoji（⚡🌀➰❌❗❓）。

连带发现（用户实测反馈）：
- **素材库显示不一致**：普通符号卡片 font-family 把 `'Segoe UI Emoji'` 放首位，text 变体字符（⬆☀）在素材库显示彩色 emoji，而画布 scene-item 走默认字体显示单色——同一字符两处呈现不同。
- **颜色选择器不显示当前色**：`colorPicker.value` 收到 `rgb(r,g,b)` 格式（经导出/导入往返后）时非法，`<input type=color>` 只接受 hex。

## 分类规则（用户确认）

- 有 text+emoji 两变体的字符 → 普通符号 tab 存 **text 变体**（去 U+FE0F，可上色）。
- 只有 emoji 变体、无 text 变体的 → 清出普通符号 tab，移入 emoji tab。

## 关键判断（实测 Unicode 属性）

- `☀`（U+2600）/`☁`（U+2601）：`Emoji=Yes` 但 **`Emoji_Presentation=No`**（默认文本呈现）→ 有 text 变体 → 保留普通符号 tab。旧逻辑判 emoji 是 2600-26FF 区间误判。
- `⚡➰❌❗❓`：`Emoji_Presentation=Yes` → 只有 emoji 变体 → 清出。
- `🌀`：主 emoji 区 → 清出。

## 踩坑记录

1. **CSS 显式 emoji 字体优先于 Unicode 呈现规则**——`font-family: 'Segoe UI Emoji'` 会强制 text 变体字符（无 FE0F）也显示彩色 emoji，因为 Emoji_Presentation 只影响默认字体回退，不覆盖显式指定字体。素材库与画布字体策略不同 → 呈现不一致。
2. **`<input type=color>` 只接受 `#rrggbb`**——`el.style.color` 经导出/导入往返后是 `rgb(r,g,b)` 格式，直接赋给 colorPicker.value 非法（warning + 不显示当前色）。需先用 DOM probe + `getComputedStyle` 规范化 hex。
3. **CSS 沙盒限制注释插入**——`css-edit-policy.mjs` 强制 CSS 走 css-ast 工具集，`add-rule` 不支持注释，Edit 钩子拒绝含注释的改动，注释只能省去（文档性质不影响功能）。

## 验证

三层流水线全过：

- html-editor 自闭环：JS `node --check`、CSS csstree 0 错误、码位核查（普通符号组无 U+FE0F）。
- verify：FE0F 优先级、码位边界、18 个 text 变体全判普通符号 / 100 个 emoji 全判 emoji、toHexColor 三输入正确、特异性覆盖、5 处调用点兼容。
- testing（Playwright 复用 52330 端口）：8+7 条断言全 PASS——普通符号 tab 卡片像素采样 0 彩色（单色）、emoji tab 彩色（🐶 2032 彩像素）；⬆ 可染色（改红持久）、⚡ 无色、☀ 普通符号行为、🐶 emoji 回归；colorPicker 往返 rgb 后正确显示 hex 无 warning；图层排序、Ctrl+Z/Y、导出导入往返正常，全程 0 console error。
