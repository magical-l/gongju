当时用户反馈「很多字符没有中文名、看不懂」（含谚文/假名/西里尔等文字类），
于是**让子代理分域翻译**，产出九张 `[[码位, "中文名"], ...]` 词表，作为汉化管线

| `zh-sgeom` | 几何形状 | 1032 |

| `zh-sspec` | 特殊符号（电报那 68 条在这张里） | 1365 |
| `zh-smisc` | 杂项符号 | 1400 |
| `zh-combo` | 组合字符 | 631 |
| `zh-num` | 数字 | 602 |

## 2. 它们是怎么死的

1. **v1.28.0（2026-09-11，`2825851`）把生成脚本改成 merge-only**：
   「已有的键一律不动，只写没有的」。从此它们只对**全新码位**有意义。
2. **v1.42.0 / ·013（2026-09-18，`688b010`）改的是引擎**（补修饰符词表、倒序短语表
   `STRUCT_PHRASE`、字形对照…，目标是让"引擎输出 == 数据里的值"**逐字可复现**）。
   那轮**同时**刷了 5 张表和 `官方名直译名.js` —— 也就是从那时起，
   **表和数据是一起被刷成一致的，表是镜像、不是源头**。

## 5. 教训

1. **一份数据存两处，必然漂移。** 68 条陈旧值就是症状 —— 但比漂移更糟的是
   **那张表其实毫无作用**：漂移了也没人会发现，因为没有对账的场景。
2. **「改 A 然后重跑 B」这种指引，会在 B 改成 merge 的那天变成假路**，
   而**原地的文档不会自己更新**。`数据说明.md` §七 教人"改词表重跑"教了很久，
   而 §六 自己就写着 merge-only —— 同一份文档里两处互相矛盾，谁也没发现。
3. **判"某份数据还有没有用"，要跑，不要读。** 「新补 0 条 + md5 相同」一句话就结了，
   比读半天代码和文档都硬。
