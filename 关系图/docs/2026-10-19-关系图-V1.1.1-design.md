# 关系图 V1.1.1：编辑效率（删除提升 + 复制）

日期：2026-10-19
状态：已实现（v1.73.0，2026-10-19）

## 目标

解决建图时两处硬摩擦：

1. 任何有子对象的节点都删不掉（`deletionCheck` 因「有对象以它为原型」直接拒绝），只能先逐个改父级。
2. 铺开同类结构只能一个个新建、改父级、调样式，没有复制。

## 边界

**做：**

- 删除时把直接子对象提升到被删对象的原型下。
- 实体复制 / 粘贴（单选、多选、多选连带内部关系）。
- 实体子树复制（左树行菜单）。
- 键盘 `Ctrl/Cmd+C`、`Ctrl/Cmd+V`；左树行菜单增加「复制」「复制子树」。

**不做（留给后续）：**

- 关系复制（粘贴语义歧义：复制线是叠一条还是建定义）。
- 系统剪贴板、跨页面/跨文档粘贴。
- 颜色预设/实时预览、触屏、自动布局、图库/模板。
- 复制子树时不复制关系、不复制关系的子对象。

## 一、删除时子对象提升

### 规则

- `deletionCheck` 不再因「有对象以它为原型」而拒绝；改为记录**直接子对象**（`prototypeId === 被删对象.id`），删除时把它们提升：
  - 实体子对象 → `prototypeId = 被删实体.prototypeId`（根删除则为 null，子对象成为根）。
  - 关系子对象 → `prototypeId = 被删关系.prototypeId`。
- 只提升一层：孙对象继续挂在原子对象下，不级联改写。
- 实体删除仍连带删除以它为端点的关系（现有行为）；若其中某条关系又被其他关系当原型引用，整次删除仍拒绝并说明原因（少见，保留保护）。
- 提升是模型变化，走现有撤销/自动保存；无确认框。
- `deleteObject` 返回值增加 `promoted`（提升数量），供 toast 汇总。

### 界面

- 右栏删除按钮不再因「有子对象」禁用；只有上述少见阻塞场景才禁用并提示原因。
- 删除后 toast：`已删除「X」，N 个子对象提升到父级`；连带删关系时补一句。
- 批量删除的逐轮重试循环可简化，但「能删的删、被阻塞的汇总提示」行为保留。

## 二、实体复制 / 粘贴

### 复制

- 触发：`Ctrl/Cmd+C`（焦点不在输入框内时），或左树实体行菜单「复制」。
- 选择来源：
  - 有 `selectedIds`（多选）：复制集合内全部实体。
  - 否则选中实体：复制该实体。
  - 选中关系：不响应复制（本版不支持）。
- 复制的内容：
  - 实体：`name`、`prototypeId`、`style`、`position` 深拷贝。
  - 多选时附带**两端都接在选中集内实体上**的关系；外部关系、自由线、半连接线不复制。
  - 选中的实体之间若存在原型指向（A 是 B 的父原型），粘贴时在副本内部重映射，保持结构。
- 剪贴板是页面内存态（`app.clipboard`），刷新即失；每次复制重置粘贴计数。

### 粘贴

- `Ctrl/Cmd+V`：无剪贴板内容时不拦截。
- 生成全新 ID；内部引用（原型指向、关系端点）在副本内部重映射，指向集合外的原型保持原引用。
- 已放置实体：位置 = 原位置 + `24 × 粘贴次数`（同一剪贴板连续粘贴依次错开）。
- 未放置实体：粘贴后仍未放置，只出现在左树。
- 名字：实体名追加「 副本」；在同原型兄弟范围内重名时追加数字（`X 副本`、`X 副本 2`…）。
- 关系标签、样式随副本保留；关系端点重映射到新实体。关系是否可见仍由端点实体是否放置决定，复制不改变这一规则。
- 粘贴后选中新实体（多选时全部选中），一次历史、一次自动保存。

## 三、复制子树（实体森林）

- 入口：左树实体行菜单「复制子树」（无快捷键）。
- 克隆该实体及全部原型后代（`prototypeId` 链向下，带环保护），新 ID，内部原型链重映射。
- 副本根挂在**原根的同一个父级**下（与原根成为兄弟）；与原根同名的兄弟自动追加数字。
- 放置状态保留：原本已放置的成员复制后仍已放置，整体偏移 `(24, 24)`；未放置成员保持未放置。
- 子对象名字保持不变（允许与原子树重名）；只有副本根加「 副本」。
- 只复制实体森林，不复制任何关系。
- 一次历史。

## 四、数据与接口

`model.js` 新增纯函数（保持 Node 可测）：

```js
// 返回可序列化的剪贴板载荷
copyEntities(doc, ids)      // -> { entities: [...], relations: [...] }
copyEntitySubtree(doc, id)  // -> { entities: [...] }

// 把载荷写进文档，返回新建对象 ID
pasteClipboard(doc, payload, offset) // -> { entityIds: [...], relationIds: [...] }
```

- `copyEntities` 与 `copyEntitySubtree` 都做深拷贝；载荷不持有文档内对象的引用。
- `pasteClipboard` 负责：新 ID、原型/端点重映射、名称去重、位置偏移。
- `deleteObject` / `deletionCheck` 语义按第一节调整。

## 六、测试

**模型（Node）：**

- 删除：单层/多级子树提升；根删除后子对象成为根；关系原型删除提升子关系；连带删关系；被引用关系阻塞。
- 复制：单实体载荷；多选只带内部关系；自由线/外部关系不进载荷；载荷与文档解耦。
- 粘贴：新 ID、内部原型重映射、外部原型保持、端点重映射、位置偏移、名称去重、连续粘贴错开。
- 子树复制：后代完整克隆、内部链重映射、根挂到原父级、放置状态保留、环保护。

**运行时（Playwright）：**

- 单选复制粘贴（已放置/未放置）、连续粘贴偏移、刷新后仍在。
- 多选复制粘贴，内部关系跟随、外部连线不复制。
- 子树复制：左树结构、画布位置偏移、撤销。
- 删除有子对象的实体/关系：提升、toast、撤销、刷新持久化；阻塞场景仍提示。
- V1.1 回归：缩放/多选/框选/组拖/对齐分布/搜索/连线/JSON/PNG/缩放平移。

## 实现记录与决策日志（v1.73.0，2026-10-19）

### 交付

- 删除提升：`deletionCheck` 不再因「有对象以它为原型」拒绝；`deleteObject` 把直接子对象提升到被删对象的 `prototypeId`，返回 `promoted`。关系删除同理。被关联关系引用时的阻塞保护保留。
- 实体复制/粘贴：`copyEntities` 产出与文档解耦的载荷；单选/多选均支持，多选只带两端都在选中集内的已放置关系；内部原型指向与关系端点在粘贴时重映射。
- 粘贴：新 ID、位置按 24px × 粘贴次数错开、未放置保持未放置、名字「X 副本」按同原型兄弟去重。
- 复制子树：克隆全部原型后代，内部链重映射，副本根挂到原父级，放置状态保留并整体偏移 24px；不复制关系。
- 接线：`Ctrl/Cmd+C`、`Ctrl/Cmd+V`、左树行菜单「复制」「复制子树」、帮助文案。
- 版本：`MODEL_VERSION=4` 与 app 握手同步；本页五个脚本 `?v=261021`。

### 踩过的坑与修正

1. **资源版本号写成了递减**：计划原定 `?v=261019`，上一版是 `261020`，verify 指出违反「改本页资源时递增」的约定。改为 `261021`；设计与计划同步修正。缓存 URL 虽变化仍会失效，但版本号本身必须单调递增，避免以后按数值判断新旧时出错。
2. **「单选删除」提示实际走多选分支**：选中实体时 `selectedIds.size === 1`，`deleteSelected` 先进入批量分支，所以实体删除 toast 是「删除了 N 个实体，N 个子对象提升到父级」；单选分支实际只覆盖关系删除。两处都已汇总提升数，行为符合设计。
3. **复制载荷必须深拷贝**：载荷若持有文档对象引用，复制后继续编辑源对象会污染剪贴板；`clonePlain` 在复制时切断引用。
