# 符号页：双模变体显示修复 v1.3.1（font-variant-emoji: emoji 失效）

## 动机

用户发现 © ® ☀ ☁ ☂ ☃ 等双模字符，在列表卡片**右侧的 emoji 变体**显示成 text 模式。

## 根因

双模字符卡片渲染两个变体：左侧文本（`.variant.text` 有 `font-variant-emoji: text`）、右侧 emoji（`.variant.emoji` 靠 `css/common.css` 的 `.emoji` 类 `font-variant-emoji: emoji`）。但 **Chrome 里 `font-variant-emoji` 的 `emoji` 值对文本默认类字符不生效**（© ® ☀ ☁ ☂ ☃ 等 Unicode 默认文本呈现、需 VS16 才切 emoji）。

系统性实测（44px，卡片字体栈）：

| 渲染方式 | © | ☀ | ❤（emoji默认） |
|---|---|---|---|
| 裸字符 | 文本 | 文本 | emoji |
| `font-variant-emoji: emoji` | **仍文本 ✗** | **仍文本 ✗** | emoji |
| `font-variant-emoji: text` | 文本 | 文本 | 文本 ✓ |
| **+VS16 (U+FE0F)** | **emoji ✓** | **emoji ✓** | emoji |
| +VS15 (U+FE0E) | 文本 | 文本 | 文本 |

结论：`text` 值有效、`emoji` 值无效；**只有变体选择符 VS15/VS16 可靠**。复制逻辑（copyVariant/copyGridVariant）早已按 VS 实现，本次让显示与复制一致。

## 方案

`符号.js` 新增 `variantText(char, type)`：text 追加 U+FE0E、emoji 追加 U+FE0F。`符号.html` 6 处双模变体显示改用（搜索网格 ×2、标签网格 ×2、详情面板效果预览 ×2）。类名/事件/复制逻辑不动，保留 CSS `font-variant-emoji`（text 值无害冗余）。

## 文件变更

| 文件 | 变更 |
|------|------|
| `符号/符号.js` | 新增 `variantText(char, type)`（cellText 后） |
| `符号/符号.html` | 6 处模板改 `variantText(cellText/char, 'text'/'emoji')`；`符号.js?v=260828→260823` |

## 验证

Playwright（CDP 禁缓存强刷）：
- © ® ☀ ☁ ☂ ☃ ❤ 全部：文本变体 = char+U+FE0E 强制文本、emoji 变体 = char+U+FE0F 强制 emoji（emoji 字形宽 37 vs 文本 24/15/28；像素确认彩色 ©️）
- 详情面板"效果预览"同样生效
- 控制台无新增 JS 错误（仅 Google 广告 403，本地环境正常）

## 踩坑

- **canvas 无 `fontVariantEmoji` 属性**（CanvasRenderingContext2D 不支持，设置是 no-op）——canvas 测不了呈现切换，必须用 DOM 宽度对比（emoji 字形 ≈1em 宽，与文本字形宽度不同）。
- 宽度在 24px 小字号下文本/emoji 字形都约 1em 无法区分，需放大字号（44px）或像素级分析（找 emoji 特征色）。
- 根因是**单一 CSS 属性双向不对称**：text 值可靠、emoji 值不可靠。遇到此类"强制呈现"需求，直接用变体选择符，别依赖 `font-variant-emoji`。
