## 2. 审阅页这条链路最终定型

从 `✓033` 的教训长出来的最终形态（`gen_multi2.py`）：

1. **每批 120 个**，多组时按文字系统分组、每组自己分批
2. **顶部「本组统一形状」+「应用到本批」**——一次点击给整批预勾，用户只改例外。
   用户过去几轮的通过率是 **93%~98%**，所以"逐个勾"里 90% 以上的点击是白费的
3. **整批按钮**：本批全选 / 全清 / 全标删
4. **页面记录 `seen`**（点开过哪几批），提交时上报 → **只落盘点开过的范围**
5. **去重**：只摆「未收且未否决」的，审过的不再出现

## 3. 三个新踩的坑

### ① 多区间的批次不能用 lo/hi 落盘（会误删几万个字符）
切罗基文跨 `13A0-13FD` 和 `AB70-ABBF`，中间隔着大半个 BMP（拉丁扩展、彝文、注音全在里面）。
页面原来只能报"起-止"，落盘时按 `range(lo, hi+1)` 算"看过范围"——
**会把中间所有别的文字系统的字符**算成"他看过"然后判死。

修法：**生成页面时把「批次 id → 码位表」写进 `tabmap.json`，落盘按 id 精确取**。
（实测：改前预估会把几十万字符卷进来，改后正好是 542 个。）

### ②「提交全部」按钮点过之后看着像死了
点一次后按钮变「已提交 ✓」并保持绿色，用户以为不能再点（其实能点）。
修法：**任何勾选变动（单个勾/取消、整批操作）都把按钮恢复成「提交全部」**。

### ③ 刷新页面会清空未提交的勾选
勾选只存在页面内存里，`F5` 就空。用户这次真的被吓到过一次
（"现在页面上全都清零了，我都怕昨天白做了"）——其实**已提交的早就发到服务器了**。
**要刷新之前先点一下提交**。
