## 一、全角/半角兼容：为什么不用 `normalize('NFKC')`

第一反应是用 `String.prototype.normalize('NFKC')` 折查询词。**实测否掉了**，两条硬数据：

**① NFKC 作用在「字符」上，而搜索比的是「名字」。** 名字是这个数据集的自然语言描述，早就把展开式写进去了——`①` 的名字就叫「圆圈数字1」、`Ⅻ` 叫「罗马数字12」、`㎏` 叫「千克」。全表扫 95 个可打印 ASCII 字符 + 若干组合词，NFKC 相对纯宽度折叠**增量是 0**。

**② NFKC 唯一真正生效的地方，恰好是它会做错的地方。** 数据里 51704 个单码位字符，**4866 个（9.4%）会被 NFKC 改写成别的字符**，其中 4851 个会跳到一个"看着对但实际错"的目标：

```
① U+2460 → U+0031 数字一        ㎏ U+338F → U+006B U+0067
Ⅻ U+216B → U+0058 U+0049 U+0049  ㍿ U+337F → U+682A U+5F0F U+4F1A U+793E
```

而「打一个字符直接跳到它」正是这个工具的核心交互。用 NFKC 折查询词 = 搜 `①` 从「精确 1 条、直接跳详情」变成「三千多条噪音里翻」。

**采取的做法：纯宽度折叠。** 只折 `U+FF01–FF5E`（逐位移 `-0xFEE0`）和全角空格 `U+3000`，**不碰 NFKC 的兼容分解**：

```js
const FW_RE = /[！-～　]/;
function toHalfWidth(s) { ... }          // 全角 → 半角
function toFullWidthChar(c) { ... }      // 半角 → 全角（单字符用）
function widthIncludes(hay, q) { ... }   // 折叠后子串包含，内容侧含全角时重试
```

**折叠是单向的（大→小），双向靠两边一起折**：查询词折半角 `q`，内容侧遇到含全角的字符串也折一次再比。这样「输入法全角模式打不出结果」和「输入半角 `(` 命中内容里的 `（`」两个方向都覆盖。

**单字符通道探三种形式**（`{原始, 全角化, 半角化}`），字面导航保持用原始输入——敲 `！` 仍跳 `U+FF01`。

**性能：给纯非 ASCII 查询加了一条可证明等价的短路。** 折叠只能把全角变成 ASCII，所以当 `q` 里没有 `[\x20-\x7E]` 的字符时，`toHalfWidth(hay).includes(q)` ⟹ `hay.includes(q)`，折叠分支恒无新命中：

```js
if (lo.includes(q)) return true;
if (!Q_ASCII_RE.test(q)) return false;   // 纯中文关键词快路径
return FW_RE.test(hay) && toHalfWidth(lo).includes(q);
```

等价性用**对照旧实现的随机 fuzz** 验证（20 万样本、0 不一致）。加这条之前，纯中文查询实测多花约 9ms（`SYMBOL_MAP` 约 1.4 万条 × 4 字段上多跑一次正则）。

**顺带纠正一个我一开始想错的方向**：曾考虑「把 NFKC 展开式当字符别名」来让搜 `xii` 出 `Ⅻ`——那是对的方向（`①` 挂别名 `"1"`，搜 `1` 时它只是众多命中之一，噪音仅 +0.87%）。但它是**另一件事**（扩召回），不在本轮范围。见"遗留"。

## 二、数据文件改名

| 旧名 | 新名 | 旧全局变量 | 新全局变量 |
|---|---|---|---|
| `名字.js` | `unicode官方名.js` | `NAMES_DATA` | `UNICODE_NAMES_DATA` |
| `中文名.js` | `官方名直译名.js` | `ZH_NAMES_DATA` | `ZH_TRANSLATION_DATA` |
| `符号数据.js` | `符号富化数据.js` | `SYMBOLS` | `ENRICHED_SYMBOLS` |
| `build_names.py` | `build_unicode_names.py` | — | — |
| `build_zhnames.py` | `build_zh_translation.py` | — | — |

`符号.js` 顶部对应的内部 `let NAMES/ZH_NAMES` 绑定一并改，保持一致。

**两个实测支撑了这个新名字**：`官方名直译名.js` 里 37396 条单码位名，**95% 是官方英文名的直译或规则生成**（连 Unicode 的叫法问题都照搬）；`符号富化数据.js` 的 `buildSymbolMap` 注释原文就是「旧数据**富化源**」——"人工/富化"是它的真实角色。

**替代顺序陷阱**：`ZH_NAMES_DATA` 含子串 `NAMES_DATA`，必须先替长的；用词边界匹配，别误伤 `SYMBOL_MAP` / `seqSymbolMeta` / `inSymbols` 这类已含 SYMBOL 的标识符。

**没碰的**：`docs/` 下的历史决策日志（改了等于篡改历史）、`.superpowers/`、`.playwright-mcp/`、`*.bak`。`数据说明.md` 的「旧名对照」行**故意保留旧名**并补成完整映射链（`名字.json → 名字.js → unicode官方名.js`），因为 `.json → .js` 是真实发生过的迁移。

## 三、别名显示修复（`ctxAliases` 放宽一行）

**症状**：👵（U+1F475）在页面上只加了别名、没改名字，那三个别名**能搜到**（`meta.aliases` 聚合进了搜索通道）但**详情区不显示**。

**根因**：`ctxGroupKey` 有一道要求——

```js
if (!groupAlive(bk[k]) || !bk[k].name) continue;   // 组必须带 name 才被认成语境组
```

而保存逻辑在「字符还没进 `符号富化数据.js`、只加别名」时会造出 `{"性别、婚姻":{"alias":[...]}}` 这种**只有别名没有组名**的形状。语境键取不到 → `ctxAliases` 里 `cur = null` → 组别名收集不到 → 返回 `[]` → 详情区 `v-if="selectedChar.aliases.length"` 为假、整行不渲染。

**这是既有 bug**：保存逻辑能产出的形状，显示逻辑用不了。`datatool.py` 体检也放行（检查器和渲染器对这个形状的判断不一致）。

**修法**（1 行）：

```js
- if (!key && !Object.keys(meta.byKey).length) return meta.aliases;
+ if (!key && !Object.values(meta.byKey).some(g => g && g.name)) return meta.aliases;
```

从「条目一个组都没有」放宽为「**没有任何组带 name**」，两种都走聚合别名。

**穷举证明这是严格放宽**：遍历 875 个有成员标签 × 3093 个单码位字符 = **270 万组**，新旧两版同页面对跑——带 name 的组输出零变化；只有 **776 个字符**（有组但没有任何组名）从 `[]` 变成显示聚合别名。所以这一行不只救 👵，是救了 776 个字符。

## 五、遗留（下一轮）

1. **NFKC 展开式当字符别名**（扩召回）：给 `Ⅻ` 挂 `"xii"`、`㎡` 挂 `"m2"`、`µ` 挂 `"μ"`。表规模约 5026 字符 / 5978 条 / 86KB，来源是 `UnicodeData.txt` 的 `Decomposition_Mapping`（项目已有）+ UTS #39 `confusables.txt`（需下载）。实测噪音极小（搜 `1` 只 +0.87%），不需要排序引擎。**注意 NFKC 只碰数据、不碰用户输入。**
2. **简繁**：数据里只有 24 条名字含繁体、21 个字种，所以只做**查询侧**即可。做法是查询词和内容**都折到简体**（繁→简是多对一、确定性），一次比较覆盖双向，且避免"折查询词展开成多变体"的组合爆炸。实测预折叠全部 37396 条只要 24ms、真正变化的只有 24 条。**落点极干净**：`widthIncludes` 内加一行折 haystack + 查询侧折叠函数，全部通道自动覆盖。
3. **CLDR 俗名的分层搬移**：`官方名直译名.js` 里 1164 条 emoji 名（+杂项符号区约 60 条）来自 CLDR，是俗名不是译名（`GRINNING FACE → 嘿嘿`）。按"名字表只装官方名的机械直译"的分层原则，应把俗名搬进 `符号富化数据.js`、直译补回名字表。**代价**：`译名词表.py` 现在一个 emoji 词都没有（`FACE`/`SMILE`/`GRIN` 均缺），要先建词表；搬移涉及 441 条补/改 + **723 条新建条目**。新建条目会改变这些字符的改名落盘路由，需一并考虑。
4. **搜索结果排序**（todo 优化 26）：搜 `a` 时 `a` 排第 78039 位、搜「马」排第 371 位。根因是 `computeTokenResult` 先塞标签成员、`charHits` 追加在后，渲染按 Set 插入顺序。搜索「马」第一个出 Ⅰ Ⅱ Ⅲ 是因为标签「数学/数字、数码/罗马数字」名字里含"马"。

## 六、运维提醒

`dev_server.py` 的 `SYMBOL_JS` 等路径是**启动时解析**的模块级常量。改名后必须**重启服务**，否则旧进程内存里还是旧路径——一旦在页面上"保存"，会按旧路径把 `符号数据.js` / `名字.js` / `中文名.js` **凭空写回磁盘**，而页面读的是新文件、表现为"保存没反应"。
