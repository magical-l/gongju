# 符号页 · 数据说明

面向要改 `符号/` 下数据文件的人。**改数据前先读第三节（组键）与第八节（怎么写脚本）。**

写脚本一律 `from datatool import *`，别手写读写（第八节）。改完 `python 符号/datatool.py` 体检。

## 一、文件一览（谁权威）

跟"一个字符叫什么"有关的只有**两份**，其余是只读参考。**下文一律用「统一叫法」这一列的词**，别再造别名。

### 键空间（重要）

这两份数据的 `names` 都是 **映射**，键是**字符串**，两种形态共用一个键空间：

| 成员 | 键 | 例 |
|---|---|---|
| 单码位 | 十进制码点 | `"411"` |
| **序列**（ZWJ / 旗帜） | 连字符连的码位串 | `"128104-8205-9877-65039"` |

**判据：键里有 `-` 就是序列。** 查名字永远是一次表查询，不分支。
`patterns` 只对单码位生效（名 = 前缀 + 码位大写十六进制）。

### 术语对照（避免再乱）

| 曾用过的叫法 | 实指 | 现在怎么说 |
|---|---|---|
| 兜底层 / 默认层 / 中文名层 | `官方名直译名.js` / `unicode官方名.js` | **直译名** / **官方英文名** |
| 富化层 / ENRICHED_SYMBOLS / 符号数据 | `符号富化数据.js` | **符号数据** |
| 语义树 / 标签树 | `标签.js` | **标签树** |
| 主名 | 有时指组名、有时指拼接名 | ❌ 弃用；改说**组名** / **拼接名** / **语境名** |
| 全局名 | 同一字段 | ❌ 弃用（名义上像"权威名"，实则只是个拼接结果）；改说**拼接名**（`joinedName`） |
| 粗名 | 早期手写的宽泛名（如 `C变音`） | **旧粗名** |

## 二、符号数据条目结构

```js
{"char":"♂","groups":{"性别、婚姻":{"name":"男性、雄性"},
                      "天文、太空、宇宙":{"name":"火星"}},
 "alias":["Mars"],"intro":"…","mode":"dual"}

{"char":"ß","name":"双s","alias":["eszett","sharp s"]}     ← 无标签字符：名字写在条目级
```

⚠️ **`groups` 里的组只放 `name`（语境名）**。别名与简介一律在**条目级** —— 见第四节的「有组 = 有语境名」。

- `char`：字符（可为多码位 ZWJ 序列）。
- **条目级 `name` / `alias` / `intro`**：给**没有任何语义标签**的字符用（`ß`、`々`、`🎞`、`Ü`…）。
  它们不属于任何标签，所以不建 `groups`，名字直接挂条目上。
- `groups`：**键 = 标签名**（外连 id），值 = `{name 语境名}`。
  一个字符可以有多个组（= 多标签语境下各叫各名）。**有标签才用 groups**。
  ⚠️ 组里**只放 `name`**；别名/简介是全局的，写条目级。**全库组内别名/简介为 0 条**（见第四节）。
- 注意上面 `alias` 是**文件里存着的**，只属于那一个位置。**界面上显示的别名比这多** —— 还会并上其他组的主名（虚拟合并，不落盘），见第四节。
- `intro` / `mode`：简介 / 双码位序列标记。
- **查名字是串行的、first-wins**：先 `符号富化数据.js`（人工层），没有才落到直译名。
  ⚠️ 同一字符若在 `ENRICHED_SYMBOLS` 里有多条，**只有第一条进内存映射**。
  ⚠️ 但**搜索是并集、不是优先**：字符通道两层都扫，用 `seen` 去重——两层都能被搜到。
- **条目里没有英文名字段**：
  - **单码位** → `nameOf(cp)` 读 `unicode官方名.js`（全局 `UNICODE_NAMES_DATA`）
  - **序列** → 读直译名的序列键（`标签.js` 的 seqs 里**只有码位**，不存名字）
- 与官方名**真正不同**的英文俗称（CLDR 短名、按键名 `Escape`、卢恩名 `Raidho`）写进 `alias`，只当搜索词。只是官方名截短的（`Dollar` vs `DOLLAR SIGN`）不写 —— 搜索通道会匹配官方名。
- `alias` 里现在还有两类**批量生成**的内容，都由脚本写入、可整批重跑：
  - **等价形式**（`build_equiv.py`）：「这个字符还能写成什么样」，只当搜索键。NFKC 展开式
    （`①→1`、`Ⅻ→XII`、`㎏→kg`、`㍿→株式会社`）加 UTS #39 同形字（西里尔 `а→a`）。
    ⚠️ **NFKC 只碰数据、不碰用户输入** —— 折查询词会让「打 `①` 直接跳到它」失效。
  - **CLDR 俗名**（`build_emoji_zh.py`）：从直译名搬回来的 emoji 俗名（`GRINNING FACE →
    嘿嘿`）。直译名只装官方英文名的**机械直译**，俗名归人工层。
- 还有一类**不是**脚本产出的批量别名：**CLDR 关键词**。全库 1742 条别名里有 **1257 条（72%）**
  来自 `参考资料/annotations-zh.json` 的 `default` 字段——那是 CLDR 给每个 emoji 的一串
  **搜索关键词**，不是名字（🍓 → 「水果」「浆果」「草莓」）。早期会话一次性灌入，**源脚本已不在仓库**。
  **当前没有任何脚本会重灌它们**（只有 `build_equiv.py` / `build_emoji_zh.py` / `datatool.py`
  写这个文件，前两者都不碰 `default`；`build_zwj.py` 读 `default[0]` 但只用于序列名）。
  所以**手动删这类别名是安全的**。
  ⚠️ 判断一条别名是不是这个来历，**看 `git log -S '关键词'`，别只看 HEAD**——HEAD 只是最近一次
  提交，不代表是人写的。
- 历史：`ename` 曾挂在每个组上，删组会连英文名一起丢，v1.26.0 起废弃；
  兜底组键 `编辑` 曾用于"无标签字符"，v1.28.0 起废弃（改用条目级字段）。**别再造 `编辑` 键**。
- 文件格式：第一行 `const ENRICHED_SYMBOLS = [`，每条**一行** `\t{...},`，最后一行 `];`（**末条不带逗号**）。
  字段顺序：`char, name, alias, groups, intro, mode`。手工追加条目时不要漏逗号。

## 三、组键（groups 的键）——最容易踩的地方

**是什么**：组键是这组名字的「容器名 + 外连 id」，指明**这组名字属于哪个标签**。

**谁在用它**（渲染不读键，但下面三处读）：
1. **语境名渲染**：取名用 `符号.js` 的 `ctxGroupKey(cp)`——按当前选中标签的**子树**找最深的**已命名**组（父节点浏览时取子节点的组名），兜底再按标签名精确命中。取别名另外用 `ctxAliasKey(cp)`——只按标签名**精确**匹配，且**不要求该组有 `name`**（1500+ 个组只挂别名不设组名，用 `ctxGroupKey` 永远圈不到它们）。
2. **序列联动**：改一个肤色/旗帜序列的名字或别名时，兄弟条目按「当前组键」写入同一容器。
3. **工具脚本**：`dedupe_symbols.py` 等按**组名**取数/合并。

**硬约束**：
- **组键必须是现存标签名**。键指向的标签若不含该符号（或标签已被改名/删除），该语境名**永远显示不出来**，且**静默回退**到兜底链（条目级 `name` → 直译兜底），不报错。
- 机械轴（`文字系统` / `官方分类` / `区块` / `emoji（绘文字）`）**不作组键**。
  ⚠️ **判一个组键属不属于机械轴，必须用节点路径，不能用节点名。** 区块轴里有一个节点就叫「**箭头**」，与语义根「箭头」同名——用名字判重会把 15 个箭头条目的组并成一条。
- **没有可用标签名的字符，根本不用 `groups`** —— 名字/别名/简介写条目级字段（第二节）。
- **标签改名会自动同步组键**（`dev_server.py` 的 `tag_meta()` → `sync_symbol_group_keys()`，含撞键合并）。但**手工直接编辑数据文件时，程序不会兜**。

**体检**：改完数据跑一次
```bash
python 符号/check_group_keys.py     # 列出"不可达组键"
```
输出为空即健康。单码位查 `ranges`，序列查 `seqs`，口径与页面一致。

## 四、名字的权威层次与显示规则

**名字只有两层**（"这个字符叫什么"）；往下再没有第三层，只剩一个"它没有名字"的标记。

| 场景 | ① 人工层 | ② 直译名 | ③ 无名字时的标记 |
|---|---|---|---|
| **搜索 / 无标签浏览** | **拼接名**（`joinedName`） | 直译名 | 「未分配码点 / 私用区码点 / 控制字符」 |
| **标签视图**（选中某标签） | **语境名** = 该标签**子树里最深的已命名组**的 `name`；该标签下没有组则 → 条目级 `name` → **直译兜底** | 同上 | 同上 |

- **③ 不是第三层名字，是"没有名字"的占位提示** —— 它只在①②都没有时出现，本身不给名字。
  ⚠️ 它靠**码位区段**判断（`unnamedKind`），不查 Unicode 到底分配没分配。
- **语境名** = 组键对应那组里 `name` 字段的值 = 该字符在**那个标签语境**下的名字。
  （⚠️ 别叫"组名"——那会让人以为指组键。）
- **拼接名**（`joinedName`，`joinGroupNames` 算出，**不落盘**）= 去重拼接下面这些，以「、」相连：
  1. **条目级 `name`**；没有就取**直译兜底名**（单码位查 `官方名直译名.js`、序列查 `SEQ_INDEX`）
  2. **各组的语境名**，按组键插入顺序
  - 语义是「**这个字符在各标签下分别叫什么**」的并集。它**只在搜索 / 无标签浏览时**是权威名；标签网格一律用语境名。
  - ⚠️ **有条目级 `name` 时直译兜底不参与**——没配主名的标签下显示的本来就是条目级名，它已经"代表"了那些标签（否则 `☝` 会拼成「空心向上食指、空心竖食指」这种双名）。
  - ⚠️ **没有条目级 `name` 时直译兜底参与**——因为没配主名的标签下显示的**本来就是那个直译名**，拼接用它是**一致**的，不是新增噪音。代价是机械直译会出现在搜索结果里；解法是**去加条目级名 / 去标签里加主名**，不是把它藏起来。
  - **占位名不参与拼接**（未分配码点 / 私用区码点 / 控制字符不是名字）。
- **有组 = 有语境名**（硬规则，v1.40.0 收口）。建一个组**必须**给它 `name`——组存在的唯一理由就是"这个字符在这个标签下叫另一个名字"。
  - 历史包袱已清：过去有 1255 个组**只有别名没有组名**（那是早期把"全局"当成一个组来用的残留），v1.40.0 把它们挂着的 3804 条别名／3 条简介全部提回条目级，组键删除。**组数 3533 → 2278，无名组归零**。
  - ⚠️ **别名和简介是全局的**：别名是搜索键，而搜索本来就全局（`meta.aliases` 聚合所有来源，不按当前标签过滤）。挂进某个组不会真的把它限制在那个标签里，只会在别的标签下**看不见**它。所以别名/简介一律写条目级。
  - **唯一一条曾经算得上"语境别名"的是 `⌘` 的「景点符号」**（⌘ 本义是地图/路标上的名胜古迹标记），
    但它最后不是靠别名解决的：⌘ 已补挂 **`社会生活/旅游、旅行`**，而 **U+2318 的直译兜底名本来就是「景点符号」**
    ——所以那里显示它**靠的是名字、不是别名**，`景点符号` 也不必当全局别名。
    **于是全库组内别名归零，"有组 = 有语境名"零例外。**
- **语境名之间不要互相嵌套**（如 `厕所` 与 `厕所/洗手间`）—— 拼接名会拼出两个近乎重复的名字；发现就统一成一个。
  ⚠️ **判据是「意思」不是「字」**（2026-09-15 用户裁定）。同一个词的两种**语序**只要指的不是一回事，就**不算重复、该两条都留**：
  `男人划船`（水上运动里这件事）与 `划船男人`（运动的人里这个人）是正交的两条轴，拼接名拼成
  「男人划船、划船男人」是**期望行为**。别拿字面相似去砍。单码位 `🚣` 早就是这个形态（「划船、划船的人」）。
- **双轴命名**：一条序列可以同时挂主题轴（`体育、运动/<项>`）和角色轴（`人/人物角色/运动的人`），
  两边各给一个语境名（见第六节 `build_zwj.py` 第 3 条）。**组键的插入顺序决定拼接名的拼接顺序**，
  主题轴的名该排在角色轴前面。
- **编辑弹窗按组分块**（2026-09-15 改造；2026-09-20 最上面加了一块「直译名」）。表单是
  **直译名**块（独立落点，写 `官方名直译名.js`）+「**全局**」块 + 数据里**已有的每个组**各一块
  （当前标签若还没有组，末尾补一块空的供新建），每块各有「主名」与一个别名列表，末尾一个全局简介。
  五个落点：直译名 → `官方名直译名.js` 的 `names[键]`；全局主名 → 条目级 `name`；全局别名 → 条目级 `alias`；组块主名/别名 → `groups[组键].name` / `.alias`。
  - **直译名块的初值取原始值**（`rawZhNameOf`，只查 `names[键]`），**不走 `lookupZhName`**——后者未命中时会扫 `patterns` 返回一个**前缀**，拿它当初值一保存就把前缀固化成了真条目。清空 = **删键**回落（不是写空名）；序列只读（序列键归 `build_zwj.py` 独占）。
  - **全局主名与直译名各管各的**（2026-09-20 拆开，见 任务/·017）：全局主名一律走富化层——字符没有条目就**新建一条最小条目**，不再像从前那样「没有条目时退而写进直译名」。那条旧路会让弹窗里两个框指向同一处存储（一个空一个有值、清空还走不通），现在只留给外部脚本。
  - **拼接名不进输入框**：全局块的初值恒为条目级 `name`（可能为空），拼接名只出现在 placeholder（「留空则用各标签名的拼接（当前：…）」）。早年那套「拼接名就把名字框禁用」（`metaEditorNameLocked`）已被这个设计取代——初值里根本没有拼接串，写回风险从根上消失，锁反而会挡住设全局主名。
  - 清空一个组的主名和别名后，该组键会被删掉，不留 `"标签名":{}`。
- **别名**：语境下 = 本组 `alias`（用 `ctxAliasKey` 圈定）∪ **条目级 `alias`** ∪ **其他组的组名**，并**一律排除"当前正在显示的那个名"**。**虚拟合并，不写回文件**；无标签语境下 = 各组合并的 `aliases` ∪ 条目级 `alias`。
  ⚠️ 早先有一条兜底「条目里没有任何组带 name → 回退聚合别名」，它会把**某个标签的别名泄到所有标签下**（实测 1992 条受影响）。已删除——`ctxAliasKey` 不要求组有 `name`，那些"只挂别名不设组名"的组因此能圈住自己的别名。
  数据侧要求：`alias` 不得与本组名或其他别名重复（大小写不敏感）。

#### 别名存废：字面包含（2026-09-19 用户裁定，·016）

一条别名只要**被同条目的别的可搜文本整段包含**，它就是零贡献的，删。
基准四条，缺一不可：① 条目级 `name`　② 各组语境名　③ **直译名**　④ **同条目的其他别名**。

⚠️ **判据的字面包含是「大小写敏感 + 繁简敏感」的，不是「折叠后搜得到」。** 两者差 16 倍：
按搜索的折叠口径（小写 + 全角半角 + 简繁）扫出 625 条，按字面只有 36 条，多出的 589 条是假的。

```
e带锐音符  不 ⊂ 拉丁小写字母E带锐音符   （E≠e，是另一种说法）      → 留
男厕       ⊂   男厕所、男厕           （原样一段，同一说法的长短式）→ 删
```

⚠️ 判据问的是「**这串字有没有被另一条*说法*整段包含**」。`datatool.py` ④d 用的就是这个口径，
它的 `in` **是大小写敏感的、这是对的**——别当成"忘了折叠"去"修"它。

**拆顿号**：`"男厕所、男厕"` 这类一条串塞两个说法的，**先拆成两条再跑上面的判据**，
拆完跟已有独立别名撞上的那一份就是删的对象。
⚠️ `︑ ﹑ ､` 三条的别名**就是顿号字本身**，拆了会变空串，要挡掉。

**含义不同的不算重复**：`散步 ⊂ 散步的人`、`玩球 ⊂ 玩球的人`、`祈祷 ⊂ 祈祷处`
——短式指行为/事物、长式指人/场所，**两条都留**。判据是意思不是字。

⚠️ **机器分不出「同一个说法」和「字形长得像」**（2026-09-21 用户裁定）：判过「含义不同」的，
在 `datatool.py` 的 `ALIAS_KEEP` 里**登记豁免**——目前 1 条：`☰` 的别名 `三`
（三爻卦像汉字「三」，与口诀 `乾三连`、直译名 `三爻·天堂` 都不是同一个说法）。
**它是登记表不是逃生舱**：被包含**且**确实是同一说法长短式的（`男厕 ⊂ 男厕所、男厕`）照删。
⚠️ 别改成「单字别名一律不查」——`①` 的别名 `1` 也是单字，那条是**真冗余**（同一个说法），
`datatool` 里有一行注释专门挡着这个退法。

**被官方英文名覆盖的也删**：官方英文名本身就是搜索通道（`符号.js:1497` 的 `nameOf()`，
查询侧折小写），所以 `Mahjong Tile Plum` 这类英文别名零贡献。
⚠️ 麻将八张花牌那 8 条还**指向了别的牌**（🀢 梅 挂着 `Mahjong Tile Spring`，那是 🀦 春 的官方名），
搜 Spring 会同时冒出梅和春 → **删，不是归位**。

⚠️ **删别名会级联**：删空后条目只剩 `char`，成了 ④ 报的**空壳条目**，
要用 `drop_symbols` 整条移除（·016 实测删空 15 个）。

- **旧粗名不留别名**：`a变音` 这类宽泛名一个名字盖着五个码位，留成别名只会变成搜谁都出一堆的废词，直接换掉不留。
- **编辑规则**：在某标签下改名/改别名，**只写该标签对应的组**；其他组不动。

### 命名风格（人工起名时遵守）

- **主名要「一眼看懂」，宁通俗勿精确。** 能意译就译意思（`YEAR` → 年份），别为精确或「权威音译」牺牲易懂。
  样板：`Metretes` → 「古希腊容积单位·大罐」——原文词进别名，数值与考证进简介。
  **被否的两版**：① 自造凑音汉字「墨特雷特」；② 主名留原文「希腊 Metretes」。
- **量纲后要带「单位」字眼**，币/衡双维度要写全（`Litra` 币衡两用 → 「古希腊货币重量单位·磅」）。
- **文明/时代词要明确**：现代希腊 ≠ 古希腊；爱琴文明不写地名式的「爱琴」，写「**古爱琴文明**」。
- **别名前缀要与主名的文明词一致**；术语变体放别名（干量↔干货容积、重量↔衡）。
- **别把已在官方英文名里的外文词再当别名**——既是外文，又不增懂。
- **字母/变体名写本源字形，不写拉丁译词**：小写希腊用 `π` 不是 `PI`，数字用 `0-9`，`∂ / ∇ / ς / ı / ȷ` 用符号本身。
- **符号在前加顿号引中文义**（`π` → 「π、圆周率」），或「中文词+字母」不加空格。**不用「圆周率 π」这种带空格的拼法。**
- **反白 / NEGATIVE 字形**：主名「实心X」，别名「阴文X」/「反白X」；正体（空心）不加前缀。
- **主名要自然口语**：👨‍⚕️ = 「男医生」（不是 CLDR 的「男医务工作者」）；👳‍♂️ = 「戴头巾的男人」（性别后置）。
- **别名必须保留性别信息**：男款别名写「男医师 / 男航天员」，不能丢「男」；中性款（🧑）才用无性别通用词。肤色款主名带前缀「浅肤色男医生」。

**同款序列联动**：同款 = 去肤色基础相同**且肤色配置全同色**（双人异色组合是两个独立符号，不并入）。
别名/简介在整组共享；**名字只在兄弟「当前名 == 改名前的名」时才联动**——名字各肤色款允许不同。

## 五、编辑保存链路（页面 → 文件）

页面把改动 POST 到 `/symbol-api/save`，由 `dev_server.py` 落盘（`action` 见其文件头注释）：

- `add` / `move` / `remove` → `标签.js`（成员增/移/取消打标）。**序列只写码位，不写名字**。
- `tag`（改名/别名/简介） → `标签.js`；**改名时另同步 `符号富化数据.js` 同名组键**
- `tag-new` / `tag-del` / `tag-sort` / `tag-reparent` → `标签.js`
- `sym`（符号名/别名/简介） → 字符已在 `ENRICHED_SYMBOLS` → 写 `符号富化数据.js`（`entry`，没有条目就**新建一条最小条目**）；否则写 `官方名直译名.js`（`name`，**旧路，编辑弹窗已不再走**，只留给外部脚本）
- `sym` 的 `zh` 字段 → 独立写 `官方名直译名.js` 的 `names[键]`（编辑弹窗的「直译名」框）。与 `entry` **正交**、可同一次提交；空串 = **删键**回落（不写空名）；序列拒收（序列键归 `build_zwj.py` 独占）
- `sym` 收到只剩 `char` 的 `entry` → **删行**（那是 `check_all` ④ 报的「空壳条目」，把主名/别名/各组/简介全清空就会走到这里）
- 三大机械轴（`文字系统`/`官方分类`/`区块`）**禁止修改**

## 六、生成脚本（三个，各管一段）

| 脚本 | 产出 | 语义 |
|---|---|---|
| `build_unicode_names.py` | `unicode官方名.js` 的**单码位键**（源 `UnicodeData.txt`） | 可重跑：重算单码位，**保留**序列键 |
| `build_zh_translation.py` | `官方名直译名.js` 的**单码位键**（源 unicode官方名.js + 词表 + CLDR） | **merge：只补没有的键，已有的不动**。⚠️ 别当成全量生成器 |
| `build_zwj.py` | 直译名的**序列键** + `标签.js` 的**序列归属** + `符号富化数据.js` 的**序列语境名/别名**（源 `emoji-test.txt` + `emoji词表.py`） | 本脚本**独占序列键**，直接覆盖（页面改序列名走符号条目，从不写直译名）。名字一律取**机械直译**，**不取 CLDR** |
| `build_equiv.py` | `符号富化数据.js` 的**等价形式 alias**（源 `UnicodeData.txt` 分解字段 + `confusables.txt`） | 可重跑、幂等：给字符补「另一种写法」当搜索键。有了它，搜 `xii` 出 `Ⅻ`、`m2` 出 `㎡`、`μ` 出 `µ` |
| `build_emoji_zh.py` | `官方名直译名.js` 的**直译** + `符号富化数据.js` 的**俗名 alias**（源 `emoji词表.py`） | 可重跑、幂等：把 CLDR 俗名从直译名搬回人工层，直译名补机械直译 |

`build_emoji_zh.py` 认范围（`find_scope`）看的是**直译名当前值**：要么还是 CLDR 兜底值、要么已是本脚本产出的直译。后者是为了**可重跑**——光认「值 == CLDR 俗名」的话，搬完一次脚本就再也认不出这些码位，重跑等于失效。人工改过的名字（两个都不是）一律不动。

它还会**删掉与新显示名同字的既有别名**：直译名的值一从俗名换成直译，显示名就跟着换；若这个新显示名正好等于本条既有的某条别名，详情区别名行会把主名再念一遍（实测 8 例）。别名本是搜索同义词，成了主名后走直译名通道照样搜得到，留着纯冗余。删空的组把那个字符串提为组语境名，不留空组。

⚠️ `build_equiv.py` 会让**新建条目**的字符改名落盘从 `官方名直译名.js` 改到 `符号富化数据.js`（`sym` 路由看的是「在不在 ENRICHED_SYMBOLS 里」）。`build_emoji_zh.py` 同理。这是期望行为 —— 页面上改名本来就该落到符号数据。

⚠️ 两个 build_* 脚本都**只增不改**：`update_symbols` 碰到已有条目的 `alias` 是**追加**，不动其他字段；`--dry-run` 可先看统计与抽样。

三条容易踩的：

- **`--dry-run` 与落盘必须共用同一个「算计划」函数。** 曾经 dry-run 拿 `len(equiv) − 已有条数` 硬减当「需新建」，不计重复过滤，**虚报 170 条**。
- **类别判据用项目自带的 `参考资料/UnicodeData.txt`（17.0.0）**，别用 Python 的 `unicodedata`（本机是 UCD 14）——Unicode 15+ 新增的组合符会被漏判成「可用」。
- **直译落空时要保留原值。** `EMOJI_WORD` 里 `'THE': ''`、`'A': ''` 是去冠词用的。直译名写空名是**静默的数据损坏**——`datatool.check_all` 只校验键合法，不校验值非空。

### `build_zwj.py` 的三条硬规矩（v1.38.0）

1. **序列名不取 CLDR。** CLDR 短名是俗名、**不含人称**（`man/woman rowing boat` 和 `rowboat`
   都叫「划船」），男/女/中性三条序列会撞成同一个名字，网格卡片上根本分不出是谁。
   序列名一律走 `emoji词表.py` 的**机械直译**；漏一个实词整条名会掉回英文原文
   （`direct_zh` 返回空串并记进 `MISSING_WORDS`，故意让它显式爆在 `missing_zh` 里）。
2. **CLDR 只进别名。** 主名与某个 CLDR 值恰好同字，那是**巧合**，不是「采用 CLDR」的依据。
   CLDR 的 `default` 是联想词大杂烩（`🚣` 那条混着 `河`/`湖`/`钓鱼`/`船`），`tts` 质量高一档。
   **整批灌进去别名行就成垃圾场** —— 所以只用一张**人工逐条筛过**的表 `CLDR_PICKED_ALIAS`
   （按官方英文名做键，目前 30 条）。另外 CLDR 还有同名天体污染：`🧚‍♂️` 的 default 里混进了
   `天卫十五`/`天卫四`（天王星卫星 Puck / Oberon）。
3. **体育类序列双挂标签。** 「体育、运动/<项>」是**主题轴**，「人/人物角色/运动的人」是**角色轴**，
   两条轴正交、不是二选一（`SPORTY` 常量）。同一条序列在两条轴下**叫不同的名字**：
   主题轴「男人划船」（这件事）、角色轴「划船男人」（这个人）。语境名写进 `符号富化数据.js`
   的 `groups`，由 `符号.js` 的语境名机制按当前选中标签取。
4. **别替英文原文的别扭磨平。** 「男小仙子」读着怪，但怪的是源语那套政治正确（还有 `pregnant man` 呢）——**如实译**，别自作主张改成顺口的。
   词形分派：**职业类走「男X」**（男厨师、男医生），**动作类走「男人X」**（男人划船）。`man fairy` → 男人小仙子、`man elf` → 男人精灵。

序列别名 = **人称同义词（男人/男子/男生）× (动作词 + 动作同义词)**，见 `PERSON_SYN` / `ACTION_SYN`。
`ACTION_SYN` **只收真有第二种通行说法的**，没有就留空、别为凑数编。别名一律落**条目级**
（v1.40.0 起；过去挂"语境组各一份"，那会让它在别的标签下看不见），
且**只给无肤色、不朝右的基础序列** —— 肤色变体是同一张折叠卡的下挂项，挂上去会把搜索引偏。

⚠️ **改 `emoji词表.py` 后要跑一次「搁浅检测」**：`find_scope` 的第二条判据拿的是**当前引擎输出**，
一改词表，旧引擎产出的名字就既不等于新输出、也不是 CLDR 值，会被当成「人工改过的名字」**永久冻结**。
判定：把新加的键从词表摘掉、用旧表重译，若「旧译 == 现值 ≠ 新译」就是被本次改动搁浅的
（人工改过的名字，旧译也不等于现值）。**修法**：`set_zh` 写回新值——写完 `cur == translate(en)`
重新成立，该条回到范围内、将来仍可重跑维护（不是单向冻结）。实测 2026-09-14 搁浅 6 条。

⚠️ `build_zh_translation.py` 历史上是全量生成器，跑一次会抹掉后来所有人工改动（实测差过 8963 条），
v1.28.0 起改成 merge。**真要全量重算，得先把现有文件挪走。**
`upgrade_ucd.py` 只调 `build_unicode_names.py`，不连带其它。
以上脚本（含只读的 `build_noto_cmap.py` / `check_group_keys.py` / `待译清单.py`）读写一律走 datatool 的读写层，不再各自 `json.load`/`json.dump`。
⚠️ `build_zwj.py` 原先写 `标签.js` 时裸 `json.dump(indent=2)`、**绕过 `dump_tags`** —— 重跑会把 `ranges`/`seqs` 打回 expand 形态。已收口到 `dump_tags`。

## 七、译名工作流（把直译名里的英文译干净）

工具两个，都靠 `__file__` 定位，**任意目录可跑**：

```bash
python 符号/待译清单.py          # 产出/刷新 符号/待译清单.json，并打印两节词频榜
```

产物分**两节**，分别对应两类问题：

| 节 | 含义 | 怎么办 |
|---|---|---|
| **a 节** | 词表 `WORD`/`PHRASE` 里**有**译法，却原样留在中文名里 | 译法现成，**应用**即可 |
| **b 节** | 那个词词表里**没有** | 先**定译法**（并考虑并进 `WORD`），再应用 |
| `keep_suspect` | `KEEP` 里**像英文常用词**的（`HE`/`TO`/`NO`…既是虚词又是字母名） | **只列出不动**，留作人工复查线索 |

`译名词表.py` 的四个结构：

- `WORD`：英文词 → 中文译法
- `PHRASE`：短语（比 `WORD` 优先，按最长匹配）
- `KEEP`：**保留原样**的词 —— 字母名 / 音节音值 / 转写名 / 编号 / 语言专名
- `ENGLISH`：英文实词黑名单。最终 `KEEP = union(_KEEP_*) − ENGLISH`

**⚠️ 往 `KEEP` 加词是整个流程最容易出错的地方**（踩过两次）：`KEEP` 一旦误收真英文词，那些词所在的条目就**永久漏报**，而且清单会"看起来变干净了"。
**判据只能是「这个词在名字里的实际用法」**，不能靠拼写结构猜（`MAN`/`EWE`/`PHASE` 就是因为"看起来像记音"被误收的）。

**已验证的当前状态（2026-09）**：a 节 0 / b 节 0，`KEEP` 4669 / `WORD` 180，连跑两次输出一致（幂等）。

### 按文字系统域批量译名（这套打法可复用）

**分域看官方英文名前缀**（`CUNEIFORM` / `SIGNWRITING` / `CANADIAN SYLLABICS` / `LATIN` + `GREEK`…），**别靠中文名猜**——别的文字系统里也有 `MU` / `PI` / `NU` 这种音值，跟希腊字母无关。

子代理产出「码点 → 新中文名」的**成品映射**（写到临时文件，**不直接改权威数据**），主代理验货后再统一落盘。
**验货必查四项**：范围重叠（多域并行时）、键是否存在、改后残留英文、撞名。
域内**先读已译好的条目摸既有惯例再动手**，别自创。

⚠️ 子代理会错——手语域把 `INDEX` 译成「索引」，实际是**食指**（`MIDDLE`=中指、`RING`=无名指、`LITTLE`=小指）。
主代理也会怀疑错——`TWO` 看着像数字二，看邻居 `TWII` / `TWOO` / `TWA` 才知是音节音值。**两边都要核。**

### 中文名层的四层生成（要补译法时改哪一层）

`官方名直译名.js` 的内容由四层拼出来，优先级从高到低：

1. **词表** `zh-*.json` ×9（7093 条，子代理翻译产物）
2. **字母类规则**（`build_zh_translation.py` 内嵌：174 个文字系统的 `SCRIPT_ZH` + 结构词 + 修饰前缀，如 `CYRILLIC SMALL LETTER A → 西里尔小写字母 A`）
3. **CLDR emoji**（`参考资料/annotations-zh.json`，1753 条，**只补空缺、不覆盖**）
4. **算法范围 patterns**（汉字 11 万+ / 谚文音节 / 古埃及象形 / 西夏 / 契丹 / 兼容表意，不带编号）

改某个字的名字前先判断它落在哪层：**词表层**改 `zh-*.json` 重跑；**字母规则层**规则内嵌在脚本里——⚠️ `SCRIPT_ZH` 用的是**名字实际形态**（空格大写 `OLD ITALIC`），不是脚本名下划线 `Old_Italic`；**算法层**是按区段批量生成的，个别例外要去人工层改。

### 为什么另有一张 `emoji词表.py`

**同一串字母在两张表里归属不同，合表会互相污染**：

| 词 | `译名词表.py` 里 | `emoji词表.py` 里 |
|---|---|---|
| `CAT` | 加拿大原住民音节的**记音**（在 `_KEEP_SYLLABLE` 里，与 `CAAI CAP CAU` 同行） | 🐱 的「猫」 |
| `MAN` | 卢恩等文字系统的**字母本名**（在 `_KEEP_LETTER` 里） | 👨 的「男人」 |
| `PIN` `BAG` `CAR` `COW` `HAT` `BOX` `EAR` `BAR` `TWO` … | 同理，各有记音/专名用法 | emoji 名里的实词义 |

`译名词表.py` 服务的是**全量的直译名**（上下文无关），`emoji词表.py` 服务的是 **emoji 名这一份独立语料**。同名不同义由**调用方**决定用哪张（`build_emoji_zh.py` 只查 `emoji词表`，再兜 `译名词表.WORD`，**绝不兜 KEEP**）。别为了「省一张表」把它们合起来。

⚠️ **`EMOJI_WORD` 分好几段写，同一个键写两次时 `dict.update()` 让后者静默赢。**
实测踩过：`PALM` 在「手」段是「手掌」、在「植物」段被写成「棕榈」，于是 `🤦 FACE PALM` 译成「脸棕榈」、`🫳 PALM DOWN HAND` 译成「棕榈下手」；`FLAT` 同理（「平底」被「降号」盖掉）。
**改完词表必须扫一遍重键。** 一词多义的靠 `EMOJI_PHRASE` 定死（`PALM TREE` / `FACE PALM` / `FLAT SHOE`）。

### 封闭集合：整条官方名进短语表（2026-09-19）

有些族的官方名**逐词引擎做不到**。做法是：把**整条官方名**加进 `EMOJI_PHRASE` 定死，
再把直译名写成**引擎输出**——这样 `translate(官方名) == 直译名`，重跑可复现，
不会被 `find_scope` 当人工值冻住。

| 族 | 官方名模式 | 直译名 | 为什么逐词做不到 |
|---|---|---|---|
| 中国象棋 14 | `XIANGQI RED/BLACK <棋子>` | `象棋红帅 … 象棋黑卒` | 同一个词按红黑方要译成不同的字（GENERAL 红方「帅」黑方「将」，仕/士、相/象、兵/卒 同理） |
| 麻将 44 | `MAHJONG TILE <牌>` | `麻将牌东风` / `麻将牌绿龙` / `麻将小丑牌` | `X OF 花色` 被 OF 分支倒装；梅兰竹菊春夏秋冬不在词表；`WHITE` 是排版术语「空心」 |

- ⚠️ **麻将只加 3 条短语就够 27 张**：`'OF CHARACTERS': '万'`、`'OF BAMBOOS': '条'`、
  `'OF CIRCLES': '筒'`（短语按最长匹配切，正好落在那三个位置上），不必为每张牌写一条。
- ⚠️ **`JOKER` 在麻将里是「小丑」不是「王牌」**——`王牌` 在中文里是 ace/trump。
  麻将这条走 `'MAHJONG TILE JOKER': '麻将小丑牌'` 单条定死，别动共用的 `JOKER` 词条（🃏 在用）。
- ⚠️ **加前缀会把下游别名一次带成冗余**：直译名 `红方帅` → `象棋红帅` 后，
  别名 `红帅` 就落进它里面了，14 条被 ④d 揪出。**这类改动跑完必过 `datatool.py`。**
- ⚠️ **富化主名盖住直译名**：麻将 44 张在富化层都有主名（东风/发财/白板…），
  卡片上照旧显示富化主名，**改直译名只影响搜索通道**——不是没生效。

### 圈字族的三个形状

`b345353`（2026-09-18「带圈/方框族收尾」）定的主口径，2026-09-19 补了三条：

| 层 | 形状 |
|---|---|
| **直译名** | `圆圈内“X”` —— **不带「字」** |
| **别名** | `带圈“X”字` |

- **谚文按官方名的词分开译**（`HANGUL` 和 `KOREAN CHARACTER` 是两个词，别揉成一条规则）：
  - `CIRCLED HANGUL <字母名>` → `圆圈内谚文“가”`
  - `CIRCLED KOREAN CHARACTER <罗马字>` → `圆圈内朝鲜语“참고”`，富化主名 `谚文词“참고”`
  - ⚠️ **`KOREAN` 别译「韩」** —— 谚文朝鲜韩国都在用；中文学界对这个语言的通称是「朝鲜语」。
  - ⚠️ **`CHARACTER` 别译「字符」** —— 这里指具体的一个字。但这两条用户裁定**不加「字」后缀**。
- **合成形别写成分解形**：`㉮` 圈里是**一个音节** `가`，不是 `ㄱ`+`ᅡ`。
  取真值要过 `unicodedata.decomposition`，并剥掉 `<circle>` 这类兼容标签。
- **CLDR 的 `tts` 值不能直接当直译名**：`㊗` 的直译名曾是 `圆圈内“日文的“祝贺”按钮”`
  —— 那是 CLDR 的 `tts` 字段整条灌进来的，还带嵌套引号。官方名是 `CIRCLED IDEOGRAPH CONGRATULATION`，
  该走 `圆圈内“祝”`（**圈里那个字**，跟 ㊖ `圆圈内“財”`、㊑ `圆圈内“株”` 同一惯例）。


## 八、改数据怎么写脚本

**不要各自手写 JSON 解析和写回。** 用 `符号/datatool.py`，坑都封在里面了：

```python
import sys; sys.path.insert(0, r'd:\工具兽\静态页面工具\符号')
from datatool import *

n = update_symbols(lambda o: ...)   # 改 符号富化数据.js：只重写被改的行，其余字节不动
append_symbols([{...}])             # 在 '];' 前追加
set_zh(0x262D, '镰刀锤子')           # 改 官方名直译名.js（names 是 {键:名} 映射）
save_tags(load_tags())              # 写 标签.js —— **只能走 dump_tags（+ wrap）**，否则格式被打回原形
check_all()                         # 一次跑完所有不变量，返回 (ok, 问题列表)
```

`check_all()` 覆盖：`node --check` / 逐条解析 / **char 是不是字符串**（防 `},,` 造成稀疏空槽，
那种语法合法但数组里是 `undefined`、页面整挂）/ **空壳条目** / char 重复 / 组名空串与顿号异常 /
名字层两个文件可解析且键合法 / 组键可达性。

命令行直接跑：`python 符号/datatool.py`（通过退出码 0/1）。

### 通用读写层（`window.XXX_DATA = {...};` 那四个文件）

路径常量：`datatool.TAGS` / `.UNICODE_NAMES` / `.ZH` / `.NOTO`。

```python
read_data(path, var)      # -> dict；内部 unwrap + json.loads
dump_data(d, var, indent=2)   # dict -> 完整文件文本（含 `window.VAR = …;` 包装，交给 write_text 落盘）
write_text(path, text, newline=None, trailing=None)   # 落盘
wrap(var, body) / unwrap(text, var)   # JSON body 文本 ↔ `window.VAR = <body>;`（wrap 不带末尾换行）
```

- **换行风格与末尾换行由 `write_text` 自动探测并保持，不要在脚本里硬编码。**
  旧实现 `_write()` 把 `newline='\n'` 写死，会把 CRLF 文件**悄悄转成 LF**；`write_text` 改成探测后保持（`detect_newline` / `detect_trailing`）。
  同理，`dev_server.py` 自己维护的那套 `_JSON_NL` 换行记忆机制已删除。
- 现状：四个文件**都是 LF**；末尾换行不统一（`标签.js` 有，`unicode官方名.js` / `官方名直译名.js` / `noto-cmap.js` 无）。`noto-cmap.js` 原是 CRLF，本次统一成 LF（git 里存的 blob 本来就是 LF，磁盘与仓库早就不一致）。
- 手写文件时别漏包装：写成裸 JSON 会让页面 `<script src>` 一加载就 `SyntaxError`。

### `dump_tags`（`标签.js` 的专属写法）

`dump_tags` 是 `标签.js` 的唯一写法**（写盘 = `write_text(TAGS, wrap('TAGS_DATA', dump_tags(d)))`，即 `save_tags`）**：
`ranges`/`seqs` 一行一条，其余 indent=2。`indent=2` 会把 `[128104, 8205, 9877]` 拆成 6 行 —— 十万行里八成是数字行和括号行。
两个直译层文件则用 `dump_data(d, 'UNICODE_NAMES_DATA')` / `dump_data(d, 'ZH_TRANSLATION_DATA')`（`save_zh` 已固定 indent=2）。
`dev_server.py` 也已改成 import 它。

## 九、常见坑

1. **改标签名不同步组键** → 组键变成"历史快照"，语境名失效（页面改走服务端已兜；手工改文件不兜）。
2. **给无标签字符造 `groups`** → 会造出不可达组键。它们该用条目级 `name`/`alias`/`intro`。
3. **把语境名当拼接名**：符号条目（人工层）是最高权威，直译名只是第二层；拼接名不过是「各处名字的并集」，**只在搜索 / 无标签浏览时**当权威名，别拿它去当某个标签下的显示名。
4. **`符号富化数据.js` 每行一条、末条不带逗号** —— 用 `update_symbols`/`append_symbols` 就不用操心。
5. **写回时选错写法**：`标签.js` 必须走 `dump_tags` + `wrap`；两份数据走 `dump_data`（`save_zh` 已固定 indent=2）。
   换行风格与末尾换行**交给 `write_text` 自动探测**，别硬编码 —— 硬写 `newline='\n'` 会把 CRLF 文件悄悄转成 LF。
6. **改名前两层都要扫**：符号数据（组里的 `name`、条目级 `name`）和直译名都存名字，只扫一层必漏。
7. **遍历直译名的 `names` 时别假设键是数字** —— 里面混着序列键（含 `-`）。`+k` 会得到 `NaN`，
   `String.fromCodePoint(NaN)` 直接抛 `RangeError`（踩过）。
8. **别留空组**：`{"标签名": {}}` 或 `{"标签名": {"alias": []}}`。组壳（既无 `name` 也无 `alias`）
   会让 `ctxGroupKey` 返回一个**没有名字的键**，该标签下名字取到 `undefined`、**回落到英文名**，
   而组名被当成别名吐出来（曾遗留 734 个，踩过）。`check_all()` 会查。
   组对象一旦被清空就该把整个键删掉。
9. **「显示英文名 + 中文名跑到别名行」的穷举排查**（好用，可复用）：在页面里拿 `__vue_app__._instance.proxy`，
   遍历「所有条目 × 它们的每个组键」，逐一切换 `selectedTag` 取 `ctxZhName`——一次列出全部取不到名字的组合。
   默认选中标签是「人」，所以这类 bug 一打开页面就中招。
