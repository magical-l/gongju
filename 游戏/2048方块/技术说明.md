# 2048 方块 — 实现技术说明

本文档描述与《玩法.txt》规则对应的**实现约定**，供开发与对照测试使用；规则本身以《玩法》为准。

## 1. 棋盘存储与屏幕方向

- 二维数组 `board[r][c]`：`r = 0` 为**屏幕最上一行**，`r` 增大方向为**向下**。
- 《玩法》中的数学坐标为 **`y = 0` 在底部、`y` 增大向上**；与 `r` **相反**。讨论「靠上/靠下」时请标明用的是哪一种。

## 2. 消行 7.1 收尾：`packAfterClearedEmptyRows`

一轮 `doClearAndGravityOnly` 内，对本轮标记为**满行**并已做除法、剩格 1×1 下落的行，记集合 `clearedSet`。

收尾时**不再**使用「把所有非空行压缩到场地最底」的算法。

当前实现：

1. 自上而下扫描每一行 `r`。
2. 若 **`r` 在 `clearedSet` 中**且该行**全为 0**，则**丢弃该行**（相当于消行里被抽掉的空行）。
3. 其余行按原顺序依次保留（含：非本轮满行、本轮满行但仍有剩格/未全空的行、以及原本就全空的全空行——**建造空隙所在的全空行会保留**）。
4. 设丢弃了 `k` 行，则在结果棋盘**顶部**补 `k` 行全 0，使总行数仍为 `rows`。

效果：与经典消行一致——消掉的行消失，上方整体下移；**不会**把悬空块与下方消行区之间的全空行「吃掉」，行内建造空隙（如 `[2,2,0,0]`）随整行平移。

## 3. 剩格 1×1 下落（顺序与临时占位）

- 满行除法后，每个非零剩格单独按与 `tick` 一致的下落/合并/锁定处理。
- 实现上需避免同一轮多粒仍占原格导致路径错误：在按顺序模拟每一粒之前，会先把**本轮已收集到的剩格原位置**置 0，再依次跑每一粒（详见 `runSequentialClearRemainderDrops`）。这是**实现手段**，不是玩法术语。

## 4. 测试场景 ⑤ / ⑥

- **⑤**：`advancePostLockLineClearNoSpawnWithStats` 统计下，区内竖合、cascade、剩格下落合并**均为 0** 的终盘。
- **⑥**：含上述任一类合并的终盘，以及脚本中**固定写入 ⑥**的用例（如「被消行上方仍有非满行」一组），与 stats 是否为 0 无关。

**期望棋盘 `expected` 的来源**：运行 `test/gen-scenario-05.js` 时，对每条用例的 `before` 调用 **`logic.js` 里的** `advancePostLockLineClearNoSpawnWithStats`（⑤/⑥ 分流）或 `advancePostLockLineClearNoSpawn`（⑥ 固定例），把返回的 `board` 写入场景文件。**不在场景数据里手填终盘**。浏览器 / Node 跑场景时再次调用同一套 `advancePostLockLineClearNoSpawn`（见 `test/runner.js`、`test/run-all-scenarios.js`），与文件中的 `expected` 比对。

⑤ 内标签含「**悬空**」的用例在生成时排在**无悬空用例之后**（仍无合并）。

⑥ 内：合并顺序为 **固定小盘 → 底双行枚举去重 →「被消行上方 / 上方非满行」等复杂固定例**；再按标签二次排序，使含「**悬空**」「**被消行上方**」或「**上方非满行**」的用例一律在**其余用例之后**（与 ⑤ 同一套直觉：简单在前、复杂在后）。

## 5. 消行「下方」与 7.2 多轮合并的语义（设计讨论）

**问题**：被消行带**下方**的固定块堆，在消行之后是否也应当做「重力式」的合并？上方失去支撑而下落，叙事上很顺；**下方**的块并没有因为消行而「失去支撑」，为什么还会跟着合并？

**说明**：

1. **消行 7.1**里「整行抽掉」只改变**上方**相对位置（+ 剩格 1×1 下落），**不是**用「下方块被往上吸」来叙事。
2. **7.2 多轮合并**（含 cascade）在规则上是对**当前整盘固定块**做「竖向相邻同数可合并」的**全局整理**，**不是**单独对「消行下方」或「失去支撑」的块做重力合并。消行结束后若某列里出现新的竖向相邻同数（例如上方整块下移、或区内竖合之后），就会进入合并/级联——这是 **2048 式**的「有相邻就合并」规则，与「这一格是不是在消行带下面」无直接因果。
3. 若场地下方是**场地边界**（最底几行消行），则**不存在**「消行下方还有块」；若消行在中间带、**下方**仍有块，**它们本身不会**因为「消行」而像上方那样**整行塌落**，但若盘面变化后**与**邻格形成同数竖合，**仍会**按 7.2 合并——这是**规则驱动的合并**，不是「下方块也受重力下落」的同一套叙事。

玩法与实现若希望**严格禁止**「消行带下方」在未发生任何位移/下落时触发合并，需要单独改规则（当前实现未做这种区分）。
