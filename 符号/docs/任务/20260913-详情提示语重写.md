# 符号页：详情提示行移位与提示语重写（v1.34.1）

日期：2026-09-13
状态：已实施

## 背景

两条来源：

- **todo 第 24 条**：右侧字符详情栏里"此字符需 Noto Sans Symbols 2 字体，装它才能在别处显示"这一行，放到字符名**之上**。
- **随之而来的文案返工**：那句话的口气像是"必须要这个字体"，要说清三件事——你的系统显示不了、本页靠什么显示、复制到别处怎么办。

## 一、先纠正一个事实前提

用户最初提的三点里，第 3 点是「**别人如果装有 a 字体则也可以显示**」。这条**是反的**：

`Noto Sans Symbols 2` **不是用户机器上装的字体，是本页自带的 webfont**——`符号.css` 顶部有 `@font-face`：

```css
@font-face {
	font-family: 'Noto Sans Symbols 2';
	src: url('../lib/fonts/NotoSansSymbols2-Regular.ttf') format('truetype');
}
```

它同时是渲染栈的**倒数第二位**（栈的来历见 `20260912-字体栈回退修复.md`）：

```
"Arial", "Segoe UI Emoji", "Segoe UI Symbol", "Consolas", "Lucida Sans Unicode", "Noto Sans Symbols 2", sans-serif
```

因为是自带 webfont，**别人打开本页自动就有，根本不用装**。真正成立的说法是：**你把这个字符复制到本页之外，才需要自己装一个能显示它的字体。**

另外两条成立，且可以互相印证：

- 「你的系统字体显示不了」——`_localCan(cp)` 用空栈 `'72px "__nonexistent__", serif'` 渲染后与 PUA 豆腐块模板逐像素比对，测的就是**系统默认字体链**。
- 「当前是用 Noto 显示的」——`_localCan` 为假 ⇒ 渲染栈里排在 Noto 前面的那几个系统字体（Arial / Segoe UI Emoji / Segoe UI Symbol / Consolas / Lucida Sans Unicode）也渲染不出 ⇒ 实际落到的就是自带的 Noto。**这个推论不是猜测**。

## 二、文案的迭代过程

用户对文案提了两轮要求，中间的关键判据值得记下来。

### 第一轮：不要让人"必须"装字体

原案 `此字符需 Noto Sans Symbols 2 字体，装它才能在别处显示`，"需…才能"读起来像硬性依赖。改成三段式，每行一条完整信息。

### 第二轮：把"知识的诅咒"清干净

用户逐词否掉了初稿：

| 毛病 | 改法 |
|---|---|
| "系统默认字体"——什么系统？ | → **你的**系统字体 |
| "这里用自带的"——这里是哪？ | → **本页** |
| "Noto Sans Symbols 2"——这是什么？ | 补类别 → ……**字体** |
| "想在别处也看到"——谁想？别处是哪？ | → **你**把它复制到**本页之外** |
| "（如其他网页、文档、聊天软件）" | 字太多，砍掉；"其他地方"本身已够具体 |

用户给的方法：**先罗里吧嗦把所有信息写全，再逐词问"删了它，读者会不会少知道一件事"**。不影响信息量的词（"是……的"的"是"、"现在"、"正常"）删掉。

后又删掉第 3 行的主语"你"——原话「"你"并不是关键信息，换谁都一样」。**主语能省是因为它对结果无影响，不是因为句子短。**

### 定稿

```html
<div v-if="selectedChar && detailAdviceNeeded" class="tofu-tip above-name">
	<p>你的系统字体不能显示这个字符</p>
	<p>本页用自带的 Noto Sans Symbols 2 字体显示</p>
	<p>在其他地方若想显示，也需安装和使用可显示的字体</p>
</div>
```

## 三、实现：从"字符串 + \n"改成"布尔 + 标签"

中途版本是把三行塞进一个字符串、靠 `\n` 分隔、再上 `white-space: pre-line` 换行。用户否掉了：「没必要用什么 `\n` 换行，就不能弄 3 个 `<span>`、`<p>` 标签之类吗？」

于是向同区块的 `detailTofu` 看齐——**它本来就是"布尔状态 + 模板里写死文案"**：

| 状态 | 类型 | 条件 | 渲染 | 位置 |
|---|---|---|---|---|
| `detailTofu` | 布尔 | Noto 也没有 | 模板写死「当前字体不支持」 | 名字**下**方 |
| `detailAdviceNeeded` | 布尔 | Noto 有、系统渲染不出 | 模板写死三句 | 名字**上**方 |

### 改动（3 文件）

| 文件 | 改动 |
|---|---|
| `符号/符号.js` | `detailAdvice`（字符串）整体改名 `detailAdviceNeeded`（布尔）：`data()` 初始化 `false`；`selectChar` / `selectFlag` / `refreshDetailAdvice` 里 3 处 `= ''` 的置空改 `= false`；赋值那句 `localOk ? '' : '…'` 改为 `!localOk`。函数名 `refreshDetailAdvice` 保留 |
| `符号/符号.html` | 第 245 行 `<div v-if="…detailAdvice" class="tofu-tip above-name">{{ detailAdvice }}</div>` → 三个 `<p>`；`.name` 与提示行的先后顺序对调（提示移到名字**上方**）。第 20 / 437 行 `?v=` 换成 `260913` 破缓存 |
| `符号/符号.css` | `.details` 嵌套块内新增 `& .tofu-tip.above-name { margin-top: 0; margin-bottom: 6px; & p { margin: 0; } }` —— 上边距归零是因为 `.char-preview` 已有 `margin-bottom: 12px`；`& p { margin: 0 }` 是清 `<p>` 的默认外边距，**不清会把块撑开，是这类改动最容易漏的点** |

### 布尔方向核对（等价性）

改前 `localOk` 真 → 空串（falsy → 不渲染）、假 → 文案（truthy → 渲染）；改后 `= !localOk` → 真 → `false` 不渲染、假 → `true` 渲染。**方向一致。**

### 为什么不并成数组

三句话是常量，只有"显不显示"在变。状态 = 布尔，文本 = 呈现，两者分开；数组会把常量文本又塞回 data。

## 五、教训

1. **"需…才能"这种句式会把"本页已有的能力"说成"外部依赖"。** 判断文案是否失真，先问：这个字体现在**当前页面**是已经好了还是没好？好了就不该用"需"。
2. **同类组件已经有写法时，跟它对齐，别另起一套。** `detailTofu` 早就是"布尔 + 模板文案"，`detailAdvice` 却存字符串，同屏两个兄弟用两种模式——这是本次返工的直接原因。
3. **`white-space: pre-line` 是"字符串里塞结构"的补丁信号。** 见到它，或者见到 `'第一行\n第二行'` 拼 UI 文案，就该拆标签。
4. **`<p>` 有默认外边距，拆标签后必须 `& p { margin: 0 }`。** 静态检查抓不到，只能靠浏览器读 computed style。
5. **面向用户的文案，"读者不看代码也能懂"是硬标准。** 逐词自检：这个名词自足吗？代词指代的对象在本段出现过吗？举例括注是不是可砍的肥肉？
