# 符号页：别名与简介收敛到条目级、组只放语境名（v1.40.0）

日期：2026-09-15
版本：**v1.40.0**
状态：已实施并验证（全区数据迁移 + 独立功能测试通过）

---

## 0. 一句话

把「别名」「简介」从各个组里全部提回**条目级**——它们本来就不该按标签分组；**组只放语境名**，
「**有组 = 有语境名**」成为硬规则。组数 **3533 → 2278**，无 `name` 的组 **1255 → 0**。

---

## 1. 起因：⌘ 的「景点符号」

上一轮（v1.39.0）做完名字分层后，余下一个尾巴：`⌘` 的「景点符号」是**唯一一条真·语境别名**，
留在 `计算机键盘符号` 组里。用户指出两点：

> ⌘ 也没放在类似于旅游之类的标签下啊？还要加上简介说明为什么是景点符号。

查下去牵出更大的问题：**组内别名/简介这个"按标签分组"的设计，在数据上基本是失效的。**

---

## 2. 判断：组内别名绝大多数只是机械挂上去的

**（1）位置不是语义决定。** v1.37.0 的 CLDR 俗名搬家（`build_emoji_zh.py`）和更早那批关键词灌入，
规则都是「挂到该字符所属**最深非机械标签**下」——机械判据，不是"这个别名只在这个标签下成立"。

**（2）组内别名在搜索上本来就是全局的。** 搜索走 `meta.aliases`（`符号.js:1498/1522`），
那是**所有组的别名 + 条目级别名聚合后**的列表，**完全不按当前标签过滤**。
所以「标签别名」这个身份只影响两件事：详情面板的别名行、编辑框里的归属——
**它并没有真的把别名关在那个标签里**。反过来说：提全局之后搜索行为一点不变，风险极低。

**（3）样本里语境专义极少。** 抽了 20 个高频标签各 4 条，外加象棋/围棋/易经/逻辑这些强领域标签，
全是同一符号的**另一种叫法**（🍀「四叶草」、📉「趋势向下的图表」、こ「Hiragana Ko」、👩‍🌾「女人农民」）。
连 `中国象棋` 的「红帅」、`逻辑` 的「存在量词」也**就是那个字符的本义**，不是领域专义。

用户的判断一语中的：

> 就是说有的符号的数据里，有的组是无名的？那应该就是以前的"全局"，所以提取是对的。

**无名的组 = 早期把"全局"当成一个组来用的残留。** 提取（提回条目级）就是把概念还原。

---

## 3. 迁移（原计划两步，判断完并成一步）

原计划先搬「既无 `name` 也无 `intro`」的纯别名容器、再人工筛「有语境名」的那批。
判断下来没有语境专义，于是**一次搬完**：

- 所有组内别名 → 条目级 `alias`（去重，保序）
- 所有组内简介 → 条目级 `intro`
- 变空的组键删除
- **例外保留**：`⌘` 的「景点符号」留在组里（当时还不知道该换标签，见 §5）

**逐字符比对验证**（对 git 基线，别名 = 各层来源的并集）：**只少了 `⚤` 的「双性恋」**，
0 丢失、0 凭空多出；组键只少了该删的，**0 个命名组被误删**。

---

## 4. ⚤ 的修正（查证后才动）

`⚤` U+26A4 的别名里有「双性恋」和「异性恋」两条。查证：

- U+26A4 **INTERLOCKED FEMALE AND MALE SIGN** 的标准含义是**异性恋**
  （[Wikipedia LGBT symbols](https://web.archive.org/web/20230331054817/https://en.wikipedia.org/wiki/LGBT_symbols) 明确列为 Heterosexuality）。
- 「双性恋」是**同一个码位的「变体字形」含义**——Unicode 图表注明「两个圆圈在同一条线上 = bisexuality」，
  那是另一个字形，不是这个。

留着会把搜「双性恋」的人引到 ⚤ 而不是该去的 ⚥（U+26A5）。**删除。**

---

## 5. ⌘：它挂错了标签，而且兜底名本来就是「景点符号」

查证发现：**U+2318 的官方名就是 `PLACE OF INTEREST SIGN`，直译兜底名正是「景点符号」**。

于是这条"语境别名"是个巧合——它和兜底名**同字**。真正的错位在于**标签**：

| | 改前 | 改后 |
|---|---|---|
| 所属标签 | 只有 `技术符号/计算机键盘符号` | 加上 **`社会生活/旅游、旅行`** |
| 旅游、旅行下 | （不显示） | **景点符号**（兜底名自动生效，不需要组、不需要别名）|
| 计算机键盘符号下 | 命令键（且别名里有「景点符号」）| **命令键**（组名保留，别名撤掉）|
| 简介 | 无 | 「地图与路标上的名胜古迹标记（源自北欧，瑞典、芬兰等国的地图用它标景点），后也被 Mac 键盘借作 Command 键。」|

**关键**：挂进旅游标签后，`景点符号` 从"别名"升级成了"**名字**"——比原来干净，
且它仍然**不是全局别名**（在别的标签下不出现）。用户最初说「⌘留」的意图由此更好地满足了。

**于是全库组内别名归零**（3806 → 0），「有组 = 有语境名」是**零例外**的硬规则——
先前打算保留的"唯一一条语境别名"其实不需要存在，因为那个意思由**名字**承担了。

---

## 6. 简介：一个从来没显示过的字段

组内 `intro` 是**死数据**——`符号.js` 全文件**零处读取 `groups[k].intro`**，
`SYMBOL_MAP` 只收条目级 `s.intro`。全库只有 3 条（`⛑` 和 `🃪`/`🃫` 的塔罗牌简介），
**从来没在页面上出现过**。用户问「我怎么没看见」——因为这个字段压根没接到渲染上。

提回条目级后走的是详情区本来就有的简介渲染，三条全部生效：

- `⛑` → 救援/安全用途的白十字头盔
- `🃪` / `🃫` → 塔罗牌王牌10/11：四元素（土风水火）中的土与风 / 水与火

## 7. 生成脚本对齐（防回潮）

两个生成脚本原本都往**组键**里挂别名，不与数据现状对齐就会在重跑时把组内别名建回来：

| 脚本 | 改法 |
|---|---|
| `build_zwj.py` | 序列别名落**条目级**（plan 的组键传 `None`）。别退回 `seq_tag()`——那会建出无名组 |
| `build_emoji_zh.py` | 「补别名」落条目级（不再补到"第一个有名组"）；新建条目直接写条目级别名；「删撞名别名」同时查条目级与组内 |

顺带删掉两处死代码：`deepest_semantic_tag`（唯一调用点已移除）与 `build_emoji_zh` 里那句没用的
`tags = load_tags()`。`build_zwj.seq_tag()` 保留但标注了「当前无调用方，别拿它去建组键」。

## 8. 踩过的坑

1. **过滤写反，把要保留的值删了。** 第一版迁移我写的是「把不在 KEEP/DROP 里的别名搬走」，但落进了
   `if al != old:` 分支——于是只调整了 KEEP/DROP 两条，其余别名原地不动，**还把 `⌘` 的「景点符号」
   从组里移除且没搬到条目级 = 直接删了**。靠 `git checkout` 回退重做。
   **教训：数据迁移脚本先回退再重跑，别在坏状态上叠补丁。**
2. **删组时连组名一起删。** 修 `⌘` 时我 `pop('计算机键盘符号')` 整个组，把组名「命令键」也丢了——
   那会让 ⌘ 在键盘标签下显示成兜底的「景点符号」。改成只 `pop('alias')`、保留 `name`。
   **教训：组是"名字的容器"，清别名前先确认组名还在不在。**
3. **两次"碰巧幂等"**：`build_zwj.py` 重跑输出 `0/0`，看着像没回潮，其实是别名已存在于条目级、
   脚本「只增不改」跳过了。**从干净状态跑仍然会建出组内别名**——不能拿"重跑没变化"当对齐的证明。
4. **`符号富化数据.js` 是裸 `<script src>`，没有 `?v=`**（只有 `符号.js`/`符号.css` 带）。
   验证数据改动时不能靠 URL 判断，要页内 `fetch(..., {cache:'no-store'})` 比对 sha256。
