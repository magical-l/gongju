## 设计决策

### 检测方案：豆腐块模板比对（多轮实测迭代）

浏览器有隐式系统字体回退——渲染栈字体都不含某字符时，仍会用系统里能支持的字体（如 Segoe UI Historic 渲染楔形文字）。检测"最终渲染是否豆腐块"经历三轮实测迭代：

1. **宽度法**（canvas measureText 精确比较）：对汉字/☺ 等"全宽 em 字符"，任意字体宽度都 72px，无法区分"栈内字体有字形"与"fallback" → **弃**
2. **FontFace API**（`document.fonts.load/check`）：实测 Chrome 只做字族匹配，**不做字形检查**（Noto 不含的 ☺/楔形文字 check 全 true）→ **弃**
3. **豆腐块模板比对**（采用）：空栈（`"__nonexistent__", serif`）渲染私有区 U+E000 生成"当前环境 .notdef 豆腐块"像素模板；字符用同一空栈渲染，与模板**逐像素比对**——相同=系统默认画豆腐块=不支持，不同=真实字形（楔形由 Historic 渲染）=能渲染

实测正确性：楔形/萧伯纳/汉字/emoji/扩展B 判能渲染（系统字体覆盖）；私有区/西夏文判豆腐块（系统无字体）；多私有区 .notdef 统一（系统 last-resort 一致）。

### 双向白名单（跳过 canvas，零检测成本）

- **正向**（判能渲染）：Noto 覆盖（noto-cmap.json，栈尾兜底字体，离线精确）+ 系统必含老区块（基础拉丁/符号/几何/箭头/基本 CJK/谚文/emoji/全角等）
- **反向**（判不支持）：私有区（E000-F8FF、F0000-FFFFD、100000-10FFFD）+ Unicode 未分配码位——任何系统字体都不含，必然豆腐块
- 西夏文等"大概率没有"的**不进反向白名单**：走模板比对，由系统实测判定（本机装了西夏字体的用户会正确判能渲染）

### 渲染栈：系统默认优先 + Noto 兜底

- **不手动排列系统内置字体**（Segoe UI Symbol/Emoji/Historic 等）——它们已在系统回退链中且顺序正确（emoji 彩色、汉字、符号、历史文字）。显式排序会打乱：实测 `Segoe UI Symbol` 排在 `Segoe UI Emoji` 前 → emoji 变黑白
- 渲染栈 = `sans-serif`（置首触发系统回退链）+ 用户字体（queryLocalFonts 授权后，居中）+ `"Noto Sans Symbols 2"`（栈尾兜底，补系统+用户都没有的符号）
- 实测：emoji 彩色、符号/汉字/楔形正常、系统缺而 Noto 有的 U+10140/U+FFF9 由 Noto 兜底显示

### 替代显示语义

- 网格卡片：判定不支持的字符字形区显示「当前字体不支持」（灰字换行）
- 详情大预览 / 效果预览：显示真实渲染（豆腐块），体现"出现在文本中的样子"；详情区保留「当前字体不支持」提示条 + Unicode 码点行

### 目的2 四象限（详情区）

Noto 含 + 本机不含 → 「此字符需 Noto Sans Symbols 2 字体，装它才能在别处显示」。`本机含` = checkLocalRenderable（模板比对，空栈不含 Noto），与目的1 复用同一检测函数。

## 踩坑记录

- **宽度法全宽字符不可判定**：汉字/☺ 在任意字体都全宽 em，宽度法无法区分"栈内字体有字形"与"fallback"——信息不可判定，非实现问题
- **FontFace API 不做字形检查**：Chrome `fonts.load/check` 只做字族匹配，对不包含该字形的 face 也返回——实测全 true
- **Segoe UI Symbol 排在 Emoji 前 → emoji 黑白**：渲染栈手动排列打乱系统回退链；修复为系统默认优先 + Noto 兜底
- **queryLocalFonts 挂在 window 而非 navigator**（Chrome 151 实测）：`navigator.queryLocalFonts` 为 undefined，需 `window.queryLocalFonts || navigator.queryLocalFonts` 双兼容
- **豆腐块模板候选**：F8FF 在 macOS 映射 Apple logo（渲染真实字形）→ 一致性校验失败会禁用检测；改用相邻中性 PUA E000/E001/E002
- **检测与显示栈解耦**：检测用空栈，与 CSS 变量栈无关——setFontStacks 不应清检测缓存（清缓存会使已判豆腐块字符丢标记）

## 已知项

- 反向白名单只放"肯定豆腐块"（私有区/未分配码位）；西夏文等"大概率没有"的走模板比对——本机装了字体会正确判能渲染
- 正向白名单 `[0x1F000, 0x1FAFF]` 覆盖麻将/多米诺/扑克/炼金术符号等，会压制"Noto 含+本机不含"的四象限建议（spec 声明的保守假设）
- FALLBACK_SYMBOL_FONTS 首项含 Noto → 渲染栈中 Noto 出现两次（中段+栈尾），浏览器忽略重复族名，无害；可后续把 Noto 从 FALLBACK 移除，栈尾统一兜底
- 豆腐块模板比对逐像素相等判豆腐块："真实字形恰好等于 .notdef"几乎不可能；漏判（不同缺字形字符 .notdef 不同）实测低（系统 last-resort 统一）
