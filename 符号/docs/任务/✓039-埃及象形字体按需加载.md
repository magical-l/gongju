## 0. 一句话

给 `✓038` 起的 941 个埃及象形补上字体（此前只有 Windows 靠系统自带的 `Segoe UI Historic` 看得见），
并让这份字体**只在该看的时候才下载**。

## 1. 起因

`✓038` 落盘后核出：埃及象形基本区 U+13000–1342F 的 1072 个码位，
**只有 `seguihis.ttf`（Segoe UI Historic，Windows 自带）覆盖**（实测 1071/1072）；
macOS / Linux 都不带它，页面自带的 `NotoSansSymbols2` 也不覆盖（0/1072）。
——等于那 941 个名字对应的字形，只有 Windows 用户看得见。

## 2. 内置

- `lib/fonts/NotoSansEgyptianHieroglyphs-Regular.ttf`（OFL 1.1，572KB）
  + 单独的 `lib/fonts/OFL-NotoSansEgyptianHieroglyphs.txt`
- 实测覆盖：基本区 **1072/1072**；**扩展区 0/3995**（连它也没有——正好印证 `✓038` 记的"扩展区没有字体支持"）
- ⚠️ 它也吃掉了 Windows 上原来走 `Segoe UI Historic` 的渲染——**这是有意的**：让全平台用同一份字形

## 3. 按需加载（这轮的主要工作）

`符号.js`：

- `EGYPT_FONT` 常量 + `EGYPT_CP_RANGES` / `isEgyptCp(cp)`
- `buildFontStack(families, withEgypt)` / `setFontStacks(families, withEgypt)`：埃及族**只在 `withEgypt` 时**追加到 `sans-serif` **之后**
- computed `viewHasEgypt`：判据 = **当前实际会渲染的成员**里有没有 `U+13000-1342F`
  （搜索看 `searchSections`、概览看各段 `preview`、否则 `gridItems`；另纳入详情 `selectedChar` 与操作记录面板——那两处也用同一个栈）
- watcher `viewHasEgypt`（`immediate`）驱动；原初始化那处 `setFontStacks(...)` 删掉，交给 watcher，避免调两次

`符号.css`：

- 两份 `@font-face` 都加 `unicode-range`
  （`Noto Sans Symbols 2` 的按它 ttf 的实际 cmap 生成 204 段；埃及的 `U+13000-1342F,U+13441-U+13446`）
- **静态 `--sym-font-stack` 里去掉埃及族**——见下

**实测结果（只读静态服务 + Playwright，两个方向都验）**：

| 场景 | 埃及字体请求 |
|---|---|
| 默认加载（页面上 0 个埃及字符） | **不请求** ✓ |
| 搜「水波」→ 屏上 7 个埃及字符 | **请求** ✓ |

## 4. `unicode-range` 挡不住下载（重要教训）

我原以为给 `@font-face` 加 `unicode-range` 就能"只在用到时才下"。**实测不成立**：
只要字体族出现在栈里，**页面一加载就把它取下来**——该页一个埃及字符都没有，
逐字符查过也没有任何栈内字体盖不住的字符（0 个）。

更早我还犯过一次同类错误：把字体排在 `sans-serif` **之前**，然后用"注入到独立 div"的小实验
得出"排到 `sans-serif` 之后就不下"的结论，**直接当成了真实页面的结论**——真页面上不成立。
**小实验不等于真实页面结论**（这已经是这几轮第五次栽在同一类事上）。

真正生效的是**条件加栈**：栈里没有它，就无从触发。

⚠️ 因此 CSS 静态那份 `--sym-font-stack` **只留 JS 按需追加**——「两处必须同步」（`✓017`）这条
在**这一个族上是有意破例**的，别顺手同步回去。
