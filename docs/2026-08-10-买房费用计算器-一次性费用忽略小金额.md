# 买房费用计算器：一次性费用 <100元 忽略并灰显

## 动机

一次性费用表里登记费（80元）等小额费用数额微小，却与几万、几十万的税费同列，干扰对「现金支出合计」的直观判断。用户要求：金额 <100元 的费用项忽略（不计入合计），该行文字灰显提示。

## 变更（`买房/买房费用.html`）

| 项 | 说明 |
|----|------|
| 阈值常量 | 新增 `FEE_IGNORE_WAN = 0.01`（100元 = 0.01万元，全表金额单位万元） |
| 判定方法 | 新增 `feeIgnored(wan)`：`wan < FEE_IGNORE_WAN` |
| totalCash | 7 项一次性费用逐个用 `count(wan)` 包装，忽略项按 0 计；首付、feeItems 不受影响 |
| 行灰显 | 7 个费用行（增值税/个税/契税/中介费/维修基金/印花税/登记费）加 `:class="{ mute: ... || feeIgnored(x) }"`，复用已有 `.mute`（#c0c4cc） |
| 占比列 | 被忽略行显示「—」，正常行显示「x%」 |

## 设计决策

- **「忽略」= 不计入现金支出合计**（用户确认）。语义：灰显即表示"没算进去"。
- 阈值 100元：登记费默认 80元 恰在其下，印花税免付为 0 也落入——都是用户感知上的"零头"费用。
- 首付行不适用（非费用项，且恒大于阈值）。
- 判定统一用 computed 值（vat/pit/deedTax/agencyFee/maintenanceFund/stampDuty/registrationFee），与 totalCash 求和口径一致；登记费占比列原用 `regFeeAmount`，本次统一为 `registrationFee`（fixed 模式下二者相等）。

## 踩坑记录

1. **占比列「—%」残留百分号**：模板写成 `{{ cond ? (x/totalCash*100).toFixed(n) : '—' }}%`，`%` 在三元表达式外，被忽略行渲染成「—%」。修复：`%` 移进真分支（`toFixed(n) + '%'`），假分支纯「—」。此写法是页面既有模式，本次让该坑首次可见。
2. **Edit 工具 em-dash 匹配失败**：html-editor 用 Edit 对含「—」（U+2014）的 7 行全部报"未匹配"（Grep 显示内容精确存在），降级用 Node 字符串替换完成（替换前校验模式计数==1）。根因未定位，疑与文件编码/BOM 相关。
