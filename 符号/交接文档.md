# 符号标签系统 · 交接文档

> 交接时间：2026-08-17。给新会话的上下文快照，避免重新摸清架构。

## 一、任务本质

**给所有 Unicode 字符打标签**，核心数据结构是"**标签 → 码点范围**"映射。最终要做一个能浏览全部字符的符号工具：选标签出字符、点字符出标签，双向。

## 二、架构：四个轴（全部在 标签.json 里）

| 轴 | 标签数 | 覆盖 | 说明 |
|---|---|---|---|
| 文字系统 | 175 | 全部 1,114,112 | 即 Unicode script，**不叫"脚本"**，永远叫"文字系统" |
| 官方分类 | 30 | 全部 1,114,112 | Unicode general category |
| 区块 | 347 | 全部（含"无区块"兜底）| Unicode block；脚本同名区块不重复暴露 |
| 语义 | ~90 有成员 | 精选 + emoji | 标签.txt 树 + emoji 映射 + 旧数据草稿 |

每个真实字符至少有 **文字系统 + 官方分类** 两个标签；非脚本区块字符再拿一个区块标签；emoji 和精选字符再加语义标签。

## 三、数据规则（关键约定）

- **标签 = 树节点**，结构 `{ code?, ranges, intro?, src, children? }`（ranges = `[[起,止],...]` 十进制、含两端）。
- **同名同内容 = 同一标签**（共享节点，可出现在多个分支，如"制表符"同时挂 区块 和 装饰、花纹）。
- **同名不同内容 = 不同标签**，靠路径区分（如 文字系统/西里尔字母 vs 区块/西里尔字母（区块），区块侧加了"（区块）"后缀）。
- **src 来源标记**：`draft`（旧数据迁移）、`emoji`（emoji 映射）、`full`（机械轴并集/共享），可为数组。
- 升级 Unicode 时**只更新带 `code` 的节点**（UCD 轴），语义节点保留。
