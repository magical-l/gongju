**语义树设计哲学**（用户定的，勿违背）：
- **标签=关键词/一个侧面，不是分类、不是完整描述**。一个字符挂多个标签合法（+→=加标签，不是移走）。例：😀 同时挂"情绪表达"+"脸"；🧝 挂"人物角色"+"怪力乱神"。
- **子标签必须是父标签的子集概念**（属种关系）。因此 emoji 根无子标签（"emoji"不可分）——只有 `emoji-text双模`（有 text/emoji 双模式字符，是 emoji 的真子集）。
- **`别名` 不纯是别名**：还收纳"太小/琐碎/边界模糊"的子级概念（如 娱乐场地和表演 别名含 马戏团、杂耍）。
- **人物角色**（v1.9.0 重新定义）= **人在特定角色的行为或装扮中**，判断标准=「能否给这个人一个可称呼的身份」（职业=身份、运动员=身份、新娘=身份；下跪者/站立者/桑拿者=无身份）。**通用人** = 无属性中性人（站/跪等中性姿态归 人根本级）；未成年/老人 = 人生阶段；性别/年龄 正交分开。
- 机械轴（文字系统/官方分类/区块）是外部客观数据，语义讨论/编辑不涉及。

**v1.16.0（2026-08-28，ZWJ 标签补齐 + 序列别名/搜索 + 组成显示）**：
- **ZWJ 标签补齐**：1614 个 ZWJ 序列中 89%（1442 个）只有 1 个真实语义分类——build_zwj.py 英文名关键词只打主分类，没享受单码位精修多标签。本轮按"标签=关键词"哲学补交叉标签 1080 条（跨 28 个节点：职业→行业域、医生→健康、kiss/相爱→家庭、牵手→手/手势/爱、骑车/跑步→运动的人等）。
- **用户裁定**（数据决策）：白杖/轮椅保持"人"不挂器具；**走路不挂田径**——用户明确"走路不是竞走，连单码位 🚶 都不该在田径里"，故单码位 🚶 已从 田径/运动的人 清理并入"人"根（与站立/下跪一致）。厨师补"饮食"，超英补"神话"。
- **对齐单码位修正**：kiss/相爱补"人/家庭"（非性别、婚姻，对齐 💑💏 单码位）；牵手补"手、手臂"（对齐 🤝）；骑车对齐 🚴 的"运动的人+交通、出行"。
- **序列别名机制**：新文件 `序列别名.json`（键=去肤色基础键 variantGroupKey → string[]），mounted 异步加载到 SEQ_ALIASES。决策：独立文件而非改 seqs 条目格式——seqs 是 `[cps...,zh,en]` 刚性格式，加别名位会破坏 seqCps/seqMeta/变体折叠。搜索 seqs 循环 + selectFlag 别名展示都走它。数据目前 8 职业（医务→医生/医师/医护人员、教师→老师、警察→民警、厨师→大厨、消防员→消防队员、宇航员→航天员、科学家→科研人员、白领→上班族）。
- **序列本身可搜 + FE0F/FE0E 容忍**：`matchCharsForToken` 加"token 本身是已收录序列"直接命中（中心栏不再"（0）"）。`resolveSeq(cps)` 容忍 VS16(FE0F)/VS15(FE0E)/无 VS 三种形式——用户复制 ZWJ 序列时变体选择符常被剥离或用错，精确键匹配会失败。
- **组成显示**：右侧详情"组成"行（zwjComponents computed）列出 ZWJ 拆分组件（排除 200D/FE0F），可点击选中组件。详情区布局：别名→复制字符→简介→组成→Unicode→HTML转义。
- **缓存坑**（重要教训）：dev_server NO_CACHE_FILES 原本不含 符号.html——浏览器缓存旧 HTML（带旧 ?v= 链接）导致改 JS 后用户反复加载旧代码，F5 都不行。已把 符号.html + 序列别名.json 加进 no-cache。**改 符号.js 后必须 bump ?v=，否则浏览器用旧 JS**（26084x 递增）。缓存 js=260847。

**v1.15.0（2026-08-28，右侧「所属标签」按左树顺序）**：
- **需求**：右侧栏「所属标签」chips 顺序要与左侧标签树显示序一致。此前 chips 走 FLAT 构建序=标签.json 键序（文字系统/官方分类/区块在最前），而左树 treeRoots 显示序=语义根在前、机械轴固定末尾——根层恰好相反。
- **根因修法**：新增模块级 `rootEntries()`（语义根在前 + AXIS_ORDER 末尾），`treeRoots` computed、mounted 初始 FLAT、`rebuildFlat` 三处统一改走它。子树遍历本就 `Object.entries(node.children)` 与左树一致，未动。FLAT 其他消费方（搜索标签导航列表）随之按树显示序，副作用是更一致。
- **决策**：改 FLAT 构建顺序而非 tagsOf 内排序——在 tagsOf 内排序只修 chips 一处，搜索标签列表仍与树序不符；根因在 FLAT 与显示序不一致。缓存 js=260844。

**折叠卡整组编辑（2026-08-28，v1.14.0）**：
- **需求**：折叠卡（有肤色变体）的 ✎ 打标/拖拽移动/取消打标时，主符号+所有肤色变体**整组一体**操作（用户裁定；否则目标标签只进主符号、变体留在原标签）。
- **协议**：opAdd/opMove/opRemove 的 payload.cps 在整组时传**对象数组成员列表** `[{cps,zh,en},...]`（每成员带名字，防刷新后旗名丢）；单成员仍传单 cps。服务器 `is_member_list` 判 `cps[0] is dict`，`_add_member` 逐成员解包。op 记录 1 条（cps=成员列表），`opChar`/`cpsHex` 取第一个（主符号）显示。
- **前端**：`onDragStart` 折叠卡记 `dragChar={group:[main,...dots]}`；`onTreeDrop`/`openTagEditor` 识别 group 构造 `tagEditorChar.members`；`opAdd/Move/Remove` 遍历 members 发服务器+applyOp；`applyOp` isGroup 判定（`op.cps[0] is Array`）逐成员应用。
- **坑（都踩过）**：①**成员列表元素必须是对象（带 zh/en），不能是数组的数组**——否则服务器 `_add_member` else 分支把整个列表当单成员 `norm_cps` → `seqs_add` 把 dict/嵌套列表整体存成坏数据，后续 `seqs_add` 排序 `tuple(s[:2])` 遇 dict 比较崩溃（报 `'<' not supported between instances of 'dict'`）。修复：`_add_member` 识别数组的数组逐个递归 + `seqs_add` 防御性排序（key 只取首元素 int 的条目，坏数据用 (0,0) 兜底）。②**浏览器缓存旧 JS**：改了 符号.js 必须 bump `?v=`（曾因 260840 没 bump，整组移动时 payload 无 zh/en → 服务器存空名 + 可能写坏数据）。③**cellText 对嵌套数组崩**（`String.fromCodePoint(...item)` 展开 NaN）——`cellText`/`variantGroupKey`/`groupSeqsByBase` 加防御跳过非数字条目。④**测试后 git checkout 标签.json 会清掉用户打标**——测试污染需精确清理，不能整文件回退。
- **旧服务残留**：重启 dev_server 换端口后，浏览器若连旧端口（旧代码）仍会复现旧 bug（如 18765 旧实例写坏数据 → 第二次打标 500）。排查用户报错先确认连的服务端口是新的。

**ZWJ 序列支持（2026-08-27，v1.12.0 完成）**：
- **seqs 泛化**：seqs 条目格式统一 `[cp1,...,cpN,zh,en]`（N≥2，码位+中英文名），旗帜（双码位）与 ZWJ（任意长度）同构。前端 helper：`seqCps(s)`（剥离尾部字符串→纯码位）、`seqMeta(s)`（取{zh,en}）；序列键= `cps.join('-')`（如 `1F9D1-200D-1F9B0`）。**所有"取前两个码位"假设须整串化**（memberKey/SEQ_INDEX/tagsOf/nodeHasMember/seqsAdd/Remove/gridItems/previewItems/selectFlag/搜索/编辑/opChar/watch）。
- **服务器**：`seqs_contains`/`seqs_remove` 按 `seq_cps(s)==cps` 精确比较（前缀比较会让 ZWJ [a,b,c] 被双码位 [a,b] 误匹配）。`seqs_add` 存 `list(cps)+[zh,en]`（协议：前端 opAdd/opMove payload 带 zh/en，否则刷新后名字丢——旗帜既有问题一并修）。
- **build_zwj.py**（可重跑）：从 `参考资料/emoji-test.txt` 注入全部含 U+200D 的 fully-qualified 序列 1614 个。**emoji-test 注释格式是 `emoji E版本 英文名`，须 en_clean 剥前缀**；CLDR zh 注解 key 剥 VS16 匹配。归属=按英文名规则映射现有标签（肤色变体与基础同节点）。
- **中文名坑**：CLDR 第一个注解常是泛词（'🧑🍳'→'做饭'、'woman standing'→'女'、'🧔♀'→'女人'、'🏳️🌈'→'双性'）——fallback（发型/家庭/爱情/握手/职业/动作词）+ EXTRA_ZH 显式覆盖优先于 CLDR。肤色变体名 = 肤色词+基础名（浅肤色红发男人）；肤色词简化（浅/中浅/中/中深/深）。**SKIN_EN.sub 剥肤色后要 rstrip(': ')**（'cook: light skin tone'→'cook: ' 否则职业 fallback 不匹配）。
- **肤色维度**：`人/肤色/{浅肤色,中浅肤色,中肤色,中深肤色,深肤色}`（用户裁定加，插在 性别、婚姻 后）。含肤色序列按**出现的肤色多挂**（双肤色握手/kiss/牵手/兔耳舞/摔跤挂 2 个）；修饰符单码位 🏻🏼🏽🏾🏿 也挂对应节点 ranges + 官方名直译名.js 显式条目。

- **双肤色命名**：交互动作（牵手/握手/接吻）→ `x肤色人牵手y肤色人`；共同动作（戴兔耳/摔跤）→ `x肤色人与y肤色人戴兔耳`（用户纠正：动作在末尾避免"A 戴 B"歧义）。
