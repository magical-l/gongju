# 符号页：数据文件 json → js（v1.34.0）

日期：2026-09-12
状态：已实施

## 背景

页面用 `fetch` 读 4 个数据 json，`file://` 下被 **CORS** 拦 —— **双击 `符号.html` 打不开**（必须起服务器）。

`docs/2026-09-06-符号页-数学符号整理与备用字形节点.md` 第 595 行早就提过这个方案：

> 页面仍走 `fetch` 读 4 个 json（`标签/名字/中文名/noto-cmap`），所以**双击 `符号.html` 打不开**（file:// 下被 CORS 拦）。……**下一步可把所有数据文件统一成 `.js`**（包一层 `window.X = {...}`），改完"看不用服务器，改还要"。

一直没做。本次落地。

## 目标

**双击 HTML 即可浏览**，但编辑功能仍走 `dev_server.py` —— 即「**看不用服务器，改还要**」。

## 一、做法：逐字节包装，不重新序列化

4 个文件重命名为 `.js`，外面包 `window.VAR = ` 前缀与 `;` 结尾，**里面的 JSON body 一个字节都不动**。

**全局变量带 `_DATA` 后缀**：`TAGS_DATA` / `NAMES_DATA` / `ZH_NAMES_DATA` / `NOTO_CMAP_DATA`。

为什么不能直接叫 `TAGS`：`符号.js` 顶层已有 `let TAGS / NAMES / ZH_NAMES`，而 classic script 的顶层 `let` 是**全局词法绑定**（存在 global lexical environment 里），与新脚本的 `let`/`var`/全局属性同名会 **SyntaxError**（`let` 与已声明的全局词法绑定重名直接报错）。加后缀彻底绕开，语义也清楚（"这是数据文件里的"）。

运行时读取（`符号.js` `mounted()`，第 2573-2579 行）：

```js
TAGS = window.TAGS_DATA;
NAMES = window.NAMES_DATA;
ZH_NAMES = window.ZH_NAMES_DATA;
TOFU_NOTO = window.NOTO_CMAP_DATA || null;   // 缺失则容错留 null
if (!TAGS) throw new Error('缺少数据文件 标签.js（window.TAGS_DATA 未定义）');
if (!NAMES) throw new Error('缺少数据文件 名字.js（window.NAMES_DATA 未定义）');
if (!ZH_NAMES) throw new Error('缺少数据文件 中文名.js（window.ZH_NAMES_DATA 未定义）');
```

**缺失时抛点明文件名的 Error** —— 而不是等某处 `undefined.xxx` 崩在半路（见第六节"新失败模式"）。

## 二、换行风格实测（没照抄记忆）

**转换前用字节统计量了一遍**，没信记忆：

| 文件 | 换行 | 末尾换行 |
|---|---|---|
| `标签.json` | LF | 有 |
| `名字.json` | LF | 无 |
| `中文名.json` | LF | 无 |
| `noto-cmap.json` | **CRLF** | 无 |

- **记忆里写「标签.json 是 CRLF」是错的**（实际 LF）—— 幸好转换前用字节量过。
- `noto-cmap` 顺手**统一成 LF**：因为 **git 里存的 blob 本来就是 LF**，磁盘和仓库早就不一致；统一后 body 与 blob **逐字节相同**（diff 干净）。
- **工具坑**：`wc -l` 和 `grep -c` 都不可靠（前者数 `\n`，后者按行匹配，CRLF/LF 混在一起会给误导值），**要直接数 `\r` / `\n` 字节**。

## 三、`datatool.py` 新增统一读写层

原来**没有唯一入口** —— 各处脚本自己 `open()` + `json.dump()`，换行风格各写各的。

新增函数：

| 函数 | 职责 |
|---|---|
| `detect_newline(path)` | 探测换行风格（数 `\r`/`\n` 字节） |
| `detect_trailing(path)` | 探测末尾是否有换行 |
| `wrap(var, body)` | 加 `window.VAR = ` / `;` 包壳 |
| `unwrap(text, var)` | 剥壳，还原 JSON body |
| `read_data(path, var)` | 读 `.js`（自动剥壳）或 `.json` |
| `dump_data(data, var, indent=2)` | 序列化 + 包壳 |
| `write_text(path, text, newline=None, trailing=None)` | 写文本，**换行/末尾自动探测并保持** |

关键修复：旧 `_write()` **硬编码 `newline='\n'`**，会把 CRLF 文件**悄悄转成 LF**。`write_text` 改成自动探测并保持 —— 否则每次落盘都会制造一次全文件 diff。

`dev_server.py` 原来自己维护一套 `_JSON_NL` 换行记忆，**已删**（同一件事两个真源，迟早打架）。

## 五、顺手修掉的隐患

`build_zwj.py` 原来写 `标签` 时**裸 `json.dump(indent=2)`、绕过 `dump_tags`**。重跑会把 `ranges` / `seqs` 的紧凑写法打回 expand 形态（行数暴增）。

改成走 `dump_tags` —— 这**不是可选项**：不走它根本写不出 `.js` 形式（包壳逻辑在 `dump_tags` 那一层）。

## 六、验证（真实数据，非模拟）

**1. 字节幂等**

`python 符号/datatool.py --selftest` —— 4 个文件全部「**语义等价 OK + 字节还原 OK**」（`selftest` 写的是临时副本，真文件一个字节不动）。

真实走 HTTP 写入后再比：POST `{action:'tag', path:'emoji（绘文字）', aliases:<原值>}` → `标签.js` **md5 不变**。

**2. `file://` 双击**

4 个全局就位、Vue mount、默认标签「人」、**899 树节点 / 254 卡片**；饮食 / emoji / 区块 / 语言、文字 四类标签抽查、详情、搜索（中文名 / `U+26BD` / 多标签分词）**全通**。

**3. 新引入的失败模式专测**（新增同步 script 带来的，必须专门测）

| 场景 | 结果 |
|---|---|
| 删掉某个数据文件 | 红色 toast **报出缺哪个文件**，**页面不白屏**（header/footer/左树仍在） |
| 4 个脚本各延迟 3 秒 | 并行取、`loading` **不卡死** |

**4. 编辑链路**

`editEnabled:true`、POST 保存 `{"ok":true}`、旧 `.json` 全部 **404**、新 4 个 `.js` **200 + `no-cache`**。

## 七、代价与风险（如实写）

1. **4 个数据文件从并行 `fetch`（非阻塞）变成同步 `<script>`**，合计 **4.4MB**。
   实测 `first-paint 120ms / DOMContentLoaded 944ms / load 2376ms` —— **可接受但真实**（首屏被数据体积拖住的风险是实打实的）。
2. **4 个新 `.js` 必须进仓库 / 上 CDN**，否则线上缺文件。好消息是失败是**显式**的（页面报明确的错），不再是静默空白。这条对 `gongju.document.cool` 的部署流程有直接影响（线上需与本地同步 `push`）。

## 八、教训

1. **大规模数据文件换格式，逐字节包装 > 重新序列化**。后者必然产生**全文件 diff** 和**格式漂移**（缩进、换行、键序、末尾换行任一处不同就是满屏 diff），review 时等于什么都没说。
2. **换行风格 / 末尾换行必须实测**，不能信记忆 —— 记忆里的 `标签.json 是 CRLF` 就是错的。并且别用 `wc -l` / `grep -c` 判断，**数字节**。
3. **同一件事只能有一个真源**。`dev_server.py` 自己记 `_JSON_NL`、`datatool.py` 又硬编码 `newline='\n'`，就是两个真源 —— 迟早把文件写坏或写脏。
4. **新增的同步 script 是新的失败模式**，要专门测「缺文件」「慢加载」两件事，不能只测 happy path。
5. **历史文档里写下的"下一步"是有价值的待办** —— 本次落地的方案与 9-06 文档第 595 行完全一致，连"看不用服务器，改还要"这句目标口径都没变。
