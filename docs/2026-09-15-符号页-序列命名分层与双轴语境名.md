# 符号页：ZWJ 序列命名分层、双轴语境名与拼接名锁定（v1.38.0）

日期：2026-09-15
版本：**v1.38.0**
状态：已实施并验证（三轮功能测试，最后一轮全部通过）

---

## 0. 一句话

ZWJ 序列的中文名从「取 CLDR 短名」改成「官方英文名的**机械直译**」，消除男/女/中性三条序列撞名；
补上「**人称同义词 × 动作同义词**」的搜索别名；体育类序列在**主题轴**和**角色轴**下各叫各名
（水上运动→`男人划船` / 运动的人→`划船男人`）；顺带把「拼接名」的编辑入口锁掉。

涉及 **10 个文件**：数据 4（`标签.js` / `官方名直译名.js` / `符号富化数据.js` / `符号.css`）、
脚本 3（`build_zwj.py` / `emoji词表.py` / 页面脚本）、页面 3（`符号.js` / `符号.html` / 上列的 css）。

---

## 1. 起因：todo「数据清理」那一条

> 🚣‍♂️ 官方名是 `man rowing boat`，但汉语主名却是「划船」，丢失了「man」这个信息。
> 应该在「水上运动」里叫「男人划船」，别名是（男人、男子、男生）×（划船、划艇），
> 在「运动的人」里叫「划船男人」，别名同理。类似的符号很多。

查根因发现两件事：

1. **`build_zwj.py` 的 `zh_of()` 末尾是「CLDR 短名优先」**。CLDR 短名是给人快速读的**俗名**，
   不含人称——`man rowing boat` / `woman rowing boat` / `rowboat` 三条序列因此拿到同一个「划船」，
   网格卡片上分不出男女。而且序列版本从来没做过 v1.37.0 对单码位做过的那套「CLDR 俗名分层搬移」。
2. **脚本本来就有对付这类的机制**（`ACTION_ZH` / `OCCUPATIONS` / `EXTRA_ZH`），只是没覆盖到
   `surfing` / `rowing boat` / `lifting weights` 等十来个动作词。

**用户裁定**（本次三条定调的话）：

- 「来源 CLDR 的名字严格只能进别名，恰好跟主名相同那是**恰好**，而不是「用 CLDR」」
- 「直译里当然只能放直译的！这个直译你自己就可以做，**不要依赖 CLDR**」
- 「CLDR 感觉就是一堆半吊子翻译的……**译得好的就用，译不好的直接扔**」
- 「怪就正说明他们怪」——别替英文原文的别扭磨平

---

## 2. ① 命名层：序列改机械直译

`build_zwj.py` 的 `zh_of()` 末尾换成 `direct_zh(en)`，**CLDR 彻底退出名字层**。

- 直译引擎 `translate` / `segment` / `token_of` 从 `build_emoji_zh.py` **搬进 `emoji词表.py`**，
  单码位与序列**共用一份词表和同一个引擎**（引擎放任一脚本里都会让另一份漂移）。
- `emoji词表.py` 新增「ZWJ 序列专用」词块：22 个动作/状态词 + 13 个职业/身份词 + 神话生物等，
  外加 36 条短语（`LIFTING WEIGHTS`→举重、`IN LOTUS POSITION`→莲花坐、`WITH BUNNY EARS`→戴兔耳…）。
  短语是必要的：逐词拼会串味（`LIFTING WEIGHTS` 逐词是「举重物」，运动名该是「举重」）。
- `direct_zh` 查不到词时**返回空串并记进 `MISSING_WORDS`**，故意让它显式爆在 `missing_zh` 里，
  不静默产出「男人 SURFING」这种半英半中的名字。

**结果**：1614 条序列全量有中文名，零 missing。

## 3. ② 别名层：人称同义词 × 动作同义词

`seq_aliases()`：`PERSON_SYN`（男人/男子/男生、女人/女子/女生）× (动作词 + `ACTION_SYN`)。

- `ACTION_SYN` **只收真有第二种通行说法的**（`rowing boat` → 划艇、泛舟），没有就留空——
  不为凑数编一个（「游泳」就没有同义词）。
- **只给无肤色、不朝右的基础序列**：肤色变体是同一张折叠卡的下挂项，给它挂「男生划船」
  只会把搜索引到浅肤色那条上（v1.37.0 修过同类坑）。
- **别名每个语境组各挂一份**：详情面板的语境别名 = 本组 alias ∪ **其他组的组名**
  （`符号.js` 的 `ctxAliases`），只挂一个组的话，在另一个标签下点开就看不到这 8 条同义词。

### CLDR 俗名只做人工挑选

新增 `CLDR_PICKED_ALIAS`（`build_zwj.py`，按**官方英文名**做键，30 条，用户逐条筛过）。
**不整批灌**：CLDR `default` 是联想词大杂烩，`🚣` 那条混着 `河`/`湖`/`钓鱼`/`船`，
整批进来别名行就成垃圾场了。另外 CLDR 还有同名天体污染——`🧚‍♂️` 的 default 里混进了
`天卫十五` / `天卫四`（天王星的卫星 Puck 和 Oberon）。

同时给所有别名加了统一闸门：**不得与当前显示名同字**（数据说明 §四），之前只有人称同义词那条路径过滤了。

---

## 4. ③ 打标层：体育类双挂

新增 `SPORTY = '人/人物角色/运动的人'` 常量。**两条轴正交，不是二选一**：

- **主题轴** `体育、运动/<项>` —— 这是一件什么事
- **角色轴** `人/人物角色/运动的人` —— 这是什么人

五个体育规则（田径/舞蹈/水上/球类/其他）各加了第二个路径。改前「运动的人」里只有跑和骑
两条是早年手工加的，其余全漏着（`🚣‍♂️` 只在「水上运动」里、不在「运动的人」里）。

## 5. ④ 语境名：序列终于接通（页面侧，最难的一段）

数据写好了，**页面上完全不生效**。两轮测试都失败，才挖到真正的原因。

### 症结一：语境名机制只对单码位接线

`符号.js` 里序列的渲染一律短路走全局名：

| 位置 | 改前 |
|---|---|
| `seqSymbolMeta()` | `zhName: rich.globalName` —— 直接用拼接名 |
| `gridItemName()` / `itemTitle()` | 遇到数组**短路返回**，不走语境 |
| `ctxGroupKey()` | `if (!tag \|\| Array.isArray(cp)) return ''` —— 数组直接返回空 |
| `ctxZhName()` | 数组分支提前 return |
| `ctxAliases()` | 数组分支提前 return |
| `zhNameIn(cp, tagName)` | **定义了但全文件零调用**（死代码） |

改法：`ctxGroupKey` 放开数组（按整串 char 取元数据）、`ctxZhName` 先试语境键再回退 `seqSymbolMeta`、
`ctxAliases` 去掉数组短路（并把 `shown` 的兜底从 `zhNameOf(cp)` 换成 `this.ctxZhName(cp)`——
`zhNameOf` 内部 `String.fromCodePoint(数组)` 会抛 `RangeError`，原来正是靠数组提前返回避开的）。

### 症结二：`isFlag` 把**所有**序列都当旗

修完上面仍不生效。真凶是：

```js
isFlag(item) { return Array.isArray(item); }   // 注释写着「双码位数组」
```

名字叫「旗」，**实际语义是「是序列（多码位数组）」**，全文件 15 处调用都按这个语义用。
于是 `gridItemName` / `itemTitle` / `selectItem`→`selectFlag` 三个入口在 `isFlag` 分支里
**短路掉了刚修好的语境函数**。

改法：三个调用点改走 `ctxZhName` / `ctxAliases`（`ctxZhName` 已内含「语境名 → `seqSymbolMeta` 全局名」
的完整回退，所以无标签时行为不退化）。

**用户随后裁定把这名字本身改对**：`isFlag` → **`isSeq`**（19 处：方法定义 + 15 个调用点 +
3 个局部变量），并修正 17 处把数组一律称作「旗」的注释；**保留** 3 处确实在讲旗帜的
（`renderState` 的「非 ZWJ 序列（旗帜等）恒可渲染」等）。

### 症结三：改了 `selectFlag` 的别名语义，破坏了编辑回写

`selectFlag` 的 `aliases` 从聚合别名改成 `ctxAliases`（语境下是**虚拟合并**列表）后，
编辑弹窗的初值取到的就是虚拟列表，用户一保存会把「其他组的组名」当真别名写回。
`符号.js:2272` 的注释白纸黑字写着「虚拟合并的其他组名不回填、不写回；**序列沿用聚合别名**」——
单码位靠 `editAliasesOf` 挡住了，序列没有。改法：`editAliasesOf` 支持数组，两处统一。

## 6. ⑤ 拼接名禁止编辑

无标签语境时显示的是各组名的拼接串（`男人划船、划船男人`）。在编辑弹窗里改它会把整串写回顶层 `name`。

新增 `metaEditorNameLocked`：**≥2 个命名组 且 当前无标签语境** → 名字框 `disabled` + 一行提示
「此符号在多个标签下各有一个名字，这里无法修改；请进入对应标签改名。」，别名/简介照常可改；
`saveSymbolMeta` 另加兜底（锁定时 `nameChanged` 恒 false）。

判据用「命名组数 ≥2」而不是「串里有『、』」：**ambiguity 的来源是组数不是分隔符**，
两个组恰好同名（`🚹` 男士洗手间 ×2，拼接后被 `Set` 去重、串里没有『、』）同样不知道该写回哪个组。
实测 291 条富化条目命中这个判据。

⚠️ 顺带发现（**非本次引入**）：UI 改名往返**不能**让数据文件字节复原——保存会把组名写进
`符号富化数据.js` 的 `groups`，改回去会残留一个 `name` 键（语义等价但多一个键）。

## 7. 踩过的坑（都可复现，值钱的在这）

### 7.1 多人组合命名：人称不在句首，搬不得

双肤色 + 双人的序列（戴兔耳、摔跤）名字形如 `浅肤色男人与中浅肤色男人戴兔耳`——**两个**人称。
按「句首人称搬到句尾」的规则生成角色轴名，得到的是
**`浅肤色与中浅肤色男人戴兔耳男人`**（只搬走了第一个「男人」）。80 条。
判据加「`rest` 里还有人称词或含『与』就不拆」，只留主题名。

### 7.2 `find_scope` 的第二条判据会被词表改动打断

`build_emoji_zh.find_scope` 放行两类值：「== CLDR 俗名」或「== **本脚本产出的直译**」。
第二条拿的是**当前引擎的输出**——所以**一改 `emoji词表.py`，旧引擎产出的名字就变成孤儿**：
既不等于新输出、也不是 CLDR 值，于是和「人工改过的名字」长得一模一样，被永久冻结、重跑修不了。

**判定方法**（可复用）：把新加的键从词表里摘掉、用旧表重译一遍，若「**旧译 == 现值 ≠ 新译**」
就是被本次改动搁浅的；人工改过的名字，旧译也不等于现值。

**修法**：`set_zh` 写回新值——写完 `cur == translate(en)` 重新成立，该条回到范围内、
将来仍可重跑维护（**不是单向冻结**）。

实测搁浅 6 条：`👯 带兔耳耳朵的女人`、`👫👬👭 男人和女人持双手/二男人持双手/二女人持双手`、
`🧖 人在蒸汽房间`、`🧘 人在莲花姿势`。

### 7.3 组键顺序决定全局名顺序

全局名 = 各语境名**按组序**拼接（`joinGroupNames`）。别名先写入时组键是 `运动的人`，
主题轴后写入 → 拼成「划船男人、男人划船」（主名垫后）。
改法：计划里**语境名先写、别名后写**；且数据要用 `git checkout` 回退后**干净重生成**才生效
（`update_symbols` 是只增不改，已存在的条目不会被重排）。

### 7.4 `getLineEndings`：本次顺手检查

`符号.html` 全 CRLF、`符号.js`/`符号.css` 全 LF，各自统一、无混合，未踩 `windows-crlf-js-corruption` 那个坑。

## 8. 被否决 / 被修正的方案

| 方案 | 否决理由 |
|---|---|
| **序列全量改直译**（1873 条） | 直译引擎吃的是单码位那份语料，没有国家名表、不认 `xxx: a, b` 复合命名。实测 `Chad`→`CHAD`、`Austria`→`AUSTRIA`、`kiss: person, person`→`KISS:PERSON,人`。**只有人称打头的 ~173 条**该走直译。 |
| **整批灌 CLDR 俗名当别名** | `default` 是联想词大杂烩（`河`/`湖`/`钓鱼`/`船` 之于「划船」、`冲刺`/`训练` 之于「跑步」）；还有 `天卫十五`/`天卫四` 这类天体污染。改成人工筛的 30 条。 |
| **动作类统一成人称前置** | 用户裁定「职业类走 `男X`（男厨师、男医生），动作类走 `男人X`（男人划船）」——职业的「男」是限定语、动作的不是。 |
| **回退双名，只留别名** | 拟议理由是「数据说明 §四说近乎重复的语境名要统一成一个」。**用户否决**：「这俩都留着就好了啊！所谓『近乎重复』应该按**意思**判断，不是按**字**判断」。已据此修订 `数据说明.md` §四。 |
| **全局名只取第一个语境名** | 会让现有的**真·多名**条目也被砍（`♂` 的「男性、雄性、火星」、`⛺` 的「帐篷、露营、户外」）。 |
| **`蒸桑拿` / `莲花坐` 砍掉人称当名字** | 用户修正：「`人在桑拿房`/`莲花坐的人` 是完整直译（一个说状态、一个说人），`蒸桑拿`/`莲花坐` 是活动侧写」。两条都留，各归各轴（见 §9）。 |

## 9. 两条「活动 / 角色」双读的落地

用户指出 `PERSON IN STEAMY ROOM` / `PERSON IN LOTUS POSITION` 两种读法都要保留，
于是 🧘 做成和 🚣 **完全同构**：

| | 主题轴（活动） | 角色轴（人） | 无语境（搜索） |
|---|---|---|---|
| 🚣 / 🚣‍♂️ | 水上运动 → `划船` / `男人划船` | 运动的人 → `划船的人` / `划船男人` | `划船、划船的人` / `男人划船、划船男人` |
| 🧘 | 其他运动 → `莲花坐` | 运动的人 → `莲花坐的人` | `莲花坐、莲花坐的人` |
| 🧖 | （无运动轴） | — | `人在桑拿房`；别名 `蒸桑拿` + `蒸房里的人` |

- 🧘 **单码位补挂了「运动的人」**：查证时发现 🧘‍♂️/🧘‍♀️ 本来就在里面，只有单码位漏了，属既有不一致。
- 🧖 **没给组名**：它唯一的语义标签是「物品、用具/生活用品、生产用品」，不是运动轴；
  硬设组名会把全局名顶成「蒸桑拿」，反而丢掉「人在桑拿房」。所以走别名。
- 两条单码位都在 `find_scope` 范围内，**可重跑**（走的是短语表，不是硬改名）。
- ZWJ 保留人称：`男人蒸桑拿` / `女人莲花坐`（那个「男人/女人」要留）。
