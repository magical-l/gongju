# 符号页：搜索视图双模渲染

## 动机

接手符号页标签系统交接后，处理交接文档遗留项第一条：搜索视图的匹配字符网格仍是单字符渲染，而标签网格已支持双模字符（文本/表情双变体）。为保持两处网格行为一致，将搜索网格对齐标签网格。

## 变更

| 文件 | 变更 |
|------|------|
| `符号/符号.html` | 搜索网格对齐标签网格：双模字符渲染 text/emoji 两个 `.variant` span（点击各复制对应风格）；加 `sel`/`has-variants` 类获得选中高亮与变体样式；title 改用 `searchTitle`；单模字符/旗序列行为不变 |
| `符号/符号.js` | 新增 `searchTitle(mc)` 方法（`titleOf` 之后）：中文名 + 官方名，无官方名回退 U+ 码点 |

## 设计决策

### 搜索网格复用标签网格渲染模式
- 双模字符渲染完全依赖 `.char-grid/.char/.variant/.has-variants` 类，CSS 已在 `符号.css` 定义好（后代选择器），搜索网格复用类名即自动获得样式，无需新增 CSS。
- 模板内 item 一律用 `mc.cp`（数字=单码位 / 数组=旗序列），与标签网格的 item 形态一致，下游 `cellKey/isSelected/itemDual/cellText/selectItem/copyGridVariant` 全部直接复用，不新增重复逻辑。
- 搜索网格比标签网格多持有 `zhName`，故 title 单独走 `searchTitle(mc)`（吃整个 mc 对象），而非标签网格的 `itemTitle(item)`——保留中文名展示优势。

### 旗序列 title 修复
- 原搜索网格内联 title 表达式对旗序列数组调用 `mc.cp.toString(16)`，数组 `toString()` 后对字符串再 `toString(16)` 返回原样，显示成 "U+1,2"。`searchTitle` 用 `Array.isArray` 分支，双码位按 `U+CP1 CP2` 格式空格连接。
