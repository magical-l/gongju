# 符号页：多标签交集简介误中 —— ☊☋ 非 emoji 混入（v1.12.1）

日期：2026-08-27
状态：已实施

## 背景

todo bug 1：搜「月亮 emoji」，多标签交集里出现 ☊（U+260A 升交点）、☋（U+260B 降交点）等，但它们并非 emoji。

## 根因

多标签搜索 v1.9 重构后，`matchTagsForToken` 用 name/path/**intro**/alias 子串匹配命中标签，`memberSetOfTags` 把命中标签的**全部成员递归物化**进 token 结果。搜 "emoji" 时：

- `官方分类/其他符号`（intro「…emoji、几何形状、箭头…」，7468 成员）
- `文字系统/通用`（intro「…符号、emoji 等」，9123 成员）

两个大桶标签仅因 intro 里**提了一句** "emoji" 就被命中，整桶成员并入 "emoji" 结果。☊☋ 属于这两个桶，于是通过「月亮 ∩ emoji」交集混了进来。

**回归来源**：先例 e11c9d9 已定下「简介命中仅在标签匹配呈现，不枚举进字符结果」（修的是搜"云"拉进傣那字母），但多标签搜索重构（v1.9）把 intro 又带回 `matchTagsForToken`，并通过新增的 `memberSetOfTags` 枚举进字符结果，违反先例。

## 方案权衡

| | A：算法修复（本次采用） | B：数据修复（清简介例举词） |
|---|---|---|
| 做法 | 成员物化只用强匹配（name/path/alias），intro 命中仅留"标签匹配"导航列表 | 从 `其他符号`、`通用` 等大桶简介里删掉例举词 |
| 稳健性 | **免疫于任何简介措辞** | 打地鼠：简介例举词不止 emoji（数字/标点/箭头/棋类…），未来任何简介含关键词即复现 |
| 副作用 | 简介保留信息量（展示用，todo 2）；纯靠简介提词才匹配的标签不再自动灌字符进网格 | 简介是展示文本，删例举后浏览信息变少 |

**结论：A**。与先例 e11c9d9 原则一致，根因在算法层，简介数据保持原样。

## 落地

- **符号.js**：
  - 新增 `matchTagsStrong(token)`：仅 name/path/alias 子串匹配（无 intro），上限 100。
  - `computeTokenResult` 的 memberSet 改用 `matchTagsStrong` 物化；`matchTagsForToken` 保留含 intro，供"标签匹配"导航列表。
- **todo.txt**：bug 1 打勾。

## 验证

浏览器实跑（localhost:52330）：

| 搜索 | 结果 |
|---|---|
| 月亮 emoji | 交集 9 个纯月亮 emoji，☊☋ 消失；月亮节仍含 ☊☋（确为月亮相关） |
| emoji | 3005（emoji 根精确值；此前被污染到 16591） |
| 月亮 / 太阳 / 动物 / 云 | 均正常，云无傣那字母泄漏（e11c9d9 场景未回归） |
| 标签匹配列表 | emoji 仍列 6 个标签（含 intro 命中的 4 个，可点击导航） |

控制台无新增 JS 错误（仅既有广告 403 / favicon 404）。

## 踩坑记录

- **同名 bug 的先例没被重构守住**：e11c9d9 在旧 `matchedChars` 里删了 intro 枚举，但 v1.9 多标签搜索把 intro 匹配挪进 `matchTagsForToken`（服务导航列表），又新加了 `memberSetOfTags` 做成员物化——导航和物化两条用途耦合在一个函数里，物化侧把 intro 命中也带进来了。教训：一个函数同时服务"导航列表"和"成员物化"两个用途时，用途不同就要拆开，别让描述性匹配（intro）混进成员物化。
