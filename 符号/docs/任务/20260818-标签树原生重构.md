## 设计决策

- **TagTreeNode 递归组件（render + h）**：有子节点 → `details.tnode > summary.trow > [span.tname, span.tcount]` + 递归子组件；无子节点（叶子）→ 普通 `div.trow.trow-leaf`（非展开容器，无 marker）。`details.open` 由组件 data.open 驱动 + `@toggle` 同步（折叠状态不被 Vue 重置）
- **选中高亮**：`selectedPath` prop 从根穿透所有深度，`.trow.selected` 按 `path === selectedPath` 精确匹配
- **默认展开**：语义轴根 `:default-open="!isFormalAxis(name)"` 展开一层，机械轴折叠（与旧 `expanded` 行为一致）
- **原生三角（用户指定）**：不用自定义 `::before`，直接依赖浏览器 disclosure marker。要点：summary 保持默认 `list-item`（**flex 会抑制原生 marker**），内部不用 flex 容器，名字+数量顺排
- **聚合计数**：每节点 `count = rangeCount(collectNodeMembers(node).ranges) + seqs.length`，与 `selectedCount` 同函数一致
- **简介迁移**：树节点不显示简介；中部 `gridhead` 下 `.grid-intro` 显示 `selectedTag.node.intro`（558/659 节点带 intro）

## 踩坑记录

- **flex 抑制原生 marker**：`.trow { display: flex }` 时 Chrome 中 details summary 的 disclosure marker 不渲染（marker 空间 0）。曾用 `summary::before` 自定义 ▸/▾ 补救，用户要求直接用原生三角 → 改为 summary 保持 list-item + 内部不用 flex，名字数量顺排
- **叶子节点不宜用 details**：无子节点的 details 仍显示空三角（点了展开空白），叶子渲染为 `div.trow-leaf`
- **叶子缩进**：CSS 只对嵌套 details 加 `margin-left: 10px`，叶子 div 需额外 `.tag.tree details.tnode > .trow-leaf { margin-left: 10px }` 保持同级缩进
- **替代方案验证过**：初版用 cheerio 全文档重排导致格式回退（doctype 合并等），已还原改用逐行精确替换
