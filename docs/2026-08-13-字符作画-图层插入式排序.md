# 字符作画页：图层拖拽排序改插入式（bug3）

## 动机

todo bug3「图层调整现在是交换式的，应该是插入式的」。旧实现 drop 时把拖拽元素与目标元素的 zIndex 两两互换，中间图层不动——用户把 A 拖到 D 上，A 和 D 直接对调，视觉上 A 瞬间跳层，不符合"把一个图层插到某位置"的预期。

## 变更

| 文件 | 变更 |
|------|------|
| `字符作画/字符作画.js` | `refreshLayers` 的 drop handler（约 380-405 行）从交换式改为插入式：按 drop 在目标 cell 的上/下半判断插到目标上/下方 → 收集 `#sceneCanvas .scene-item` 按 zIndex 降序 → 取出拖拽元素 → 定向插入 → 重分配连续 zIndex（顶层最大） |

## 实现说明

```js
const rect = cell.getBoundingClientRect();
const insertBefore = e.clientY < rect.top + rect.height / 2;
const order = [...document.querySelectorAll('#sceneCanvas .scene-item')]
    .sort((a, b) => (parseInt(b.style.zIndex) || 0) - (parseInt(a.style.zIndex) || 0));
const fromIdx = order.indexOf(layerDragEl);
order.splice(fromIdx, 1);
let toIdx = order.indexOf(el);
if (!insertBefore) toIdx += 1;
order.splice(toIdx, 0, layerDragEl);
order.forEach((item, i) => {
    const z = order.length - 1 - i;
    item.style.zIndex = z;
    item.setAttribute('data-zindex', z);
});
```

关键约定（验证过兼容）：

- **zIndex 方向**：zIndex 越大越靠上，`refreshLayers` 渲染按降序（rail 顶部=最上层）。重分配 `z = order.length-1-i` 让首位（顶层）拿最大值，方向一致。
- **undo/redo**：快照存 `el.style.zIndex`、恢复用 `parseInt` 写回，与重分配后的连续值兼容；`data-zindex` 全项目**仅写入、无读取**（仅两处 setAttribute，无属性选择器引用），同步写入保持一致性。
- **nextZIndex**：单调递增计数器（起点 300，从不重置），重分配只产生 0..N-1 恒低于计数器，新元素始终拿 300+ → 永远在最上，无碰撞。

## 踩坑记录

1. **drop 的矩形取值对象错误**——初版用 `el.getBoundingClientRect()`（画布元素）做上/下半判断，但 drop 事件挂在图层轨道 `cell` 上、`e.clientY` 是鼠标在 cell 上的坐标。结果插入方向不随鼠标在 cell 内的位置变化，由画布元素与轨道行的相对 Y 决定。verify 层抓出，改为 `cell.getBoundingClientRect()`。教训：**事件处理函数里取几何信息，一定要用事件真正挂载的元素**。
2. **fromIdx/toIdx 的 -1 早退**——`indexOf` 找不到（理论上不该发生）时在写 DOM 前提前 return，避免污染。splice 末位插入不越界（`toIdx` 最多为 `length-1`，`+1` 后等于 length 是合法 splice 位置）。
