# 符号页：全量汉化（中文名层）

## 动机

2026-08-18 用户反馈符号页很多字符没有汉语名字、看不懂（不只符号，谚文/假名/西里尔字母等文字类也不认识）。决定给全部 Unicode 字符配中文名。已确认：全量汉化（含文字类），来源 CLDR + 翻译 + 规则 + 算法混合。

## 设计决策

### 分层覆盖（优先级从高到低）
1. **词表**（zh-*.json 子代理翻译）— 符号/标点/数字/组合 7093 条
2. **字母类规则** — 174 文字系统英文名结构翻译，如 `CYRILLIC SMALL LETTER A`→西里尔小写字母 A
3. **CLDR emoji** — 1753 条官方中文名，只补空缺不覆盖已有
4. **算法范围**（patterns）— 汉字 11 万+/谚文音节/古埃及象形/西夏文/契丹/兼容表意，编号对用户无意义故不带编号

### 字母类规则（build_zhnames.py）
- **SCRIPT_ZH 用名字实际形态**：脚本名下划线（Old_Italic）→ 名字空格大写（OLD ITALIC），letter_zh 贪心多词匹配（优先长形态如 OLD ITALIC 而非 OLD）
- **别名表**：名字形态与脚本名不一致（EGYPTIAN HIEROGLYPH / CANADIAN SYLLABICS / HENTAIGANA 等）
- **结构词映射**：CAPITAL→大写、SMALL→小写、LETTER→字母、CHOSEONG→初声 等；假名省略冗余的"字母"
- **修饰前缀**：MATHEMATICAL 系列（粗体/斜体/无衬线/哥特/手写/空心）、FULLWIDTH/HALFWIDTH、LINEAR B 等
- **边界**：无 script 且无修饰前缀时返回 None（避免把英文名原样当中文名，交给词表）

### 搜索接入
- matchedChars 在 SYMBOL_MAP 匹配后新增中文名.json 包含匹配（遍历 3.5 万条 names，`zh.includes(q)`），与人工名/英文名/旗序列共享去重、200 条上限
- 实测单次计算 10-35ms，连续输入无卡顿

## 踩坑记录

- **SCRIPT_ZH 下划线 bug**：key 用脚本名（OLD_ITALIC）匹配不到英文名（OLD ITALIC 空格大写），导致古意大利/古匈牙利等一批文字没匹配——改用空格形态 + 多词贪心
- **letter_zh 无 script 误伤**：无 script 词时把整个英文名原样返回（🔥→FIRE），把 CLDR 全挤掉——限定仅在命中 script/修饰前缀时返回
- **词表 cp 解析**：子代理输出 `0x` 十六进制字符串，`int('0x0300')` 报错——按 0x 前缀用 `int(cp, 16)`
- **CLDR 变体选择符**：key 含 FE0F（©️），去变体后存基础码位

## 已知项

- 词表 7093 条为子代理翻译，可能有少量错译/不理想——改 zh-*.json 重跑 build_zhnames.py 即可修正
- 中文名.json 2184 KB，与名字.json 同构同量级；紧凑格式判定不值得做（gzip 后差距 <5%）
- Unicode 升级：新字符无中文名时，等官方数据发布后走 upgrade_ucd.py 重算，再人工/子代理补词表
- 交接文档（标签系统）中"搜索视图单字符渲染"、"名字紧凑格式"两条已知项已分别解决/判定不做
