## 0. 判断（用户问「是否应该窄化为「天气」」）

**该窄化，但改名是最后一步，不是第一步。**

判据是一条硬伤：**「自然现象」这四个字在替兄弟命名**。
`自然` 下的 `水`、`火、烟`、`雷电`、`风、气` —— **它们本身就是自然现象**，是这个节点的**兄弟**。
这节点从来没拥有过"自然现象"这个范畴，只是名字上占了它。

补两条：`天气` 是高频词（过规则 1 绰绰有余），节点已有别名 `气候`；
而「自然现象」作搜索入口太泛，读起来像「其他」。

## 4. 语境名：在 `天气` 下按气象状态命名（用户定的模式）

用户先给出模式 —— **在 `天气` 语境下，名字要表达气象状态**（`☀`/`🌞` → 晴朗、`🌙` → 夜间晴朗），
照此给 `天气` 下的成员加 `groups: {"天气": {"name": …}}`。

**判据（本条是纲）：官方名里有什么成分，天气名里就该有什么。** 有太阳就带"晴"，有雨就带"雨"，
纯云无日就是"阴"。**多给了和少给了都是错。**

### 4.1 我在这上面错了两次，方向相反

| 错法 | 例子 | 病灶 |
|---|---|---|
| **多给**（第一次） | `🌨` CLOUD WITH **SNOW** → 我写"阵雪"；`🌩` CLOUD WITH **LIGHTNING** → 我写"雷阵雨"；`💨` **DASH SYMBOL** → 我写"阵风"；`☂` **UMBRELLA** → 我写"有雨" | 加了官方名没有的意思（"阵"是间歇性、`🌩`没有雨、`💨`压根不是风） |
| **少给**（第二次纠正时矫枉过正） | `🌤` WHITE SUN WITH SMALL CLOUD → 我从"晴间多云"砍成"多云" | 砍掉了官方名里**有的**"太阳" |

用户两次都当场指出来了（"这些都是怎么'阵'的？"／"你刚才不就是叫它'晴间多云'吗"）。

### 4.2 最终（2026-09-24，含用户的多次手调）

```
☀晴朗  ☁阴  ☇闪电  ☈雷暴  ☔雨  ⚡闪电  ⛅晴间多云  ⛆雨  ⛈雷雨  ❄雪
🌈雨过天晴  🌊风浪  🌙夜间晴朗  🌞晴朗  🌤晴间多云  🌥多云  🌦太阳雨
🌧雨  🌨雪  🌩打雷  🌪龙卷风  🌫雾  🌬风
```

云的四种按中文天气预报的四档：**晴 / 晴间多云 / 多云 / 阴**
（`⛅`=晴间多云、`🌤`=晴间多云、`🌥`=多云、`☁`=阴）。

### 4.3 撤掉天气名的（画的是器物/符号，不是天气现象）

`☂`伞 `🌂`合上的伞（**用户已把它们摘出 `天气`**）、`☃`雪人 `⛄`雪人无雪 `⛇`实心雪人、
`💨`破折号符号、`🌫`雾（=直译，白设）、`🌀`旋风（别名本就是
`晕/飓风/龙卷风/台风`，不缺搜索面）。

用户另摘除了 `🌑`新月（只有"夜"没有气象含义，"夜"是**时间**概念，活儿在 `时间、日期、历法/夜晚`；
对比 `🌙` 弯月能当"晴夜"图标是因为**月牙看得见 = 天上没云**）与 `⛱`地面雨伞（更像度假/海滩）。

### 4.4 关于 `晴偶有云`

它是 **CLDR 官方中文注解**（`参考资料/annotations-zh.json`：`🌤` 的 CLDR 中文名里含"晴偶有云"），
由 `build_emoji_zh.py` 第 3 步搬进 `符号富化数据.js` 当 `alias` —— **CLDR 用词偏港台**，
与大陆气象标准用语（晴间多云）对不上。用户已把 `🌤`等条目的 CLDR 别名清掉。

⚠️ 全库可能还有一批 CLDR 港台用词别名，**值得单独立任务扫一遍**，不在本任务范围。
