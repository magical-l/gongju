## 0. 一句话

把「符号叫什么」这件事彻底分层：**{全局, 本标签} × {主名, 别名}** 四格，编辑弹窗按组分块一次看全；
取名回退链明确为「本标签组名 → 条目级名 → 直译兜底」，**拼接不再越界**；术语「全局名」纠正为**拼接名**。

涉 5 个文件：`符号.js` / `符号.html` / `符号.css`（编辑弹窗与取名逻辑）、`emoji词表.py`（一条短语）、
`符号富化数据.js`（✌ 一条）、`dev_server.py`（两行）。

## 1. 起于一个别名：✌ 的「胜利手势」蹲在别名槽

用户问「有些符号的别名在右侧栏能看见，点开修改界面却看不见？比如 ✌ 的『胜利手势』」。

查下去发现三层全对不上：

| 层 | 值 |
|---|---|
| Unicode 英文名 | `VICTORY HAND` |
| 名字表（直译层） | **胜利手** ← 逐词拼 `VICTORY`+`HAND` 的产物，中文里没这词 |
| 符号数据 | `{"groups":{"手、手臂、手指头":{"alias":["胜利手势"]}}}` ← **一个正经主名被塞进了别名槽** |
| 条目级 alias（全局别名） | 无 —— **「剪刀手」全库不存在** |

**「看不见」的直接原因**是两个函数用了两套「语境」判据：

- `ctxGroupKey()` 要求组**必须有 `name`** 才算语境组 —— `✌` 的组只有别名没有组名，于是它在**任何**标签下语境组键都是空；
- `ctxAliases()` 因此走到兜底「没有任何组带 name → 回退聚合别名」，到处都显示「胜利手势」；
- `editAliasesOf()` **根本不看 `ctxGroupKey`**，只看「当前标签名是不是本条的组键」：不是 → 返回空。

两条路在「条目没有命名组」时分岔。**全库 1243 条**是「只有无名组 + 别名」的形态，在非其组键的标签下编辑框必空。

**修法与后续**：这一条最终催生了整轮改造（见下）。同一轮里还顺手修了 `✌` 本身：

- `emoji词表.py` 加短语 **`VICTORY HAND → 胜利手势`**（走短语表而非硬改名，所以 `cur == translate(en)` 仍成立、**可重跑**）；
- **`🖖 REVERSED VICTORY HAND` 因此解冻** —— 它早被人手工改成「反向胜利手势」，但引擎给的是「反向胜利手」，
  两边对不上 → 被 `find_scope` 判成「人工改名」冻在范围外。补了短语后自动回范围。

## 2. 模型定案（用户裁定）

> 别名也应该是「在这个标签里的别名」，或者「全局别名」。

于是「名字/别名」都是 **{全局, 本标签} × {主名, 别名}** 四格。数据侧**本来就支持**，只是 UI 混成一坨：

| | 数量 | 就是 |
|---|---|---|
| 组里 `alias` | 2210 条 | **标签别名** |
| 条目级 `alias` | 5162 条 | **全局别名** |
| 只有组内 alias（无条目级别名） | 1992 条 | 曾被聚合兜底泄到所有标签 |

## 3. 编辑弹窗：从「四字段」到「按组分块」

**第一版**（按用户最初的描述）做成「全局」+「本标签」两块 × 主名/别名。

**用户当场改设计**：

> 主名、别名那里就按组分好：x组：主名：[输入框]，别名：[别名1][别名2][输入框]这样不就行了

因为有「本标签」就意味着**要看别的标签得先切过去**。最终形态：

```
全局                          ← 条目级 name / alias，恒定第一块
  主名 [____]  别名 [xxx][+]
手、手臂、手指头                ← 数据里已有的每个组，标题就是组键
  主名 [____]  别名 [xxx][+]
手势、姿势                     ← 当前标签若还没有组，末尾补一块空的供新建
  主名 [____]  别名 [____][+]
简介 [textarea]               ← 全局
```

- 列出规则：全局块 + `Object.keys(entry.groups)` 原顺序 + **仅当当前标签还没有组时**末尾补空块（无语境不补）。
- **拼接名绝不进输入框**：全局块初值恒为条目级 `name`（可能为空），拼接名只出现在 placeholder（「留空则用各标签名的拼接（当前：…）」）。
- 由此**删掉了 `metaEditorNameLocked`**（v1.38.0 加的「拼接名禁用名字框」）：新设计里初值根本不含拼接串，写回风险从根上消失，那个锁反而会挡住用户设全局主名。
- 清空某组的主名与别名后删掉组键，不留 `"标签名":{}`。
- 附带修：`useNameRoute` 原先不检查 `introChanged`，同时改名 + 改简介时**简介会被静默丢弃**。

## 4. 术语：全局名 → 拼接名

用户指出：

> 你叫「全局名」不太好。是指「搜索时在结果列表里叫什么」的这个靠拼接拼出来的名字吧？

对。它**只出现在搜索结果与无标签浏览**里（标签网格一律用语境名），「全局」这名字替拼接打了掩护。
代码 `globalName` → **`joinedName`**，「全局名」→**「拼接名」**，全库零残留。

## 5. 取名回退链：拼接不该越界

用户报的第二个 bug：

> 我把 ✊ 在「手势、姿势」里设置主名为「举起拳头」，但来到「手、手臂、手指头」标签里，它显示的主名也变成了「举起拳头」，
> 这里不是应该落在默认的直译「举起的拳头」上吗？

`手、手臂、手指头` 与 `手势、姿势` 是**平级**标签。`ctxGroupKey` 取不到键是对的，问题在**回退那一步**：
`ctxZhName` 无键时走 `zhNameOf` → 用 `joinedName`（各标签名的拼接）→ 别的标签的组名越界顶掉了兜底直译。

**改成**：

```
本标签组名（ctxGroupKey 命中）
  → 条目级 name
  → 直译兜底（单码位查 官方名直译名.js；序列查 SEQ_INDEX）
  → 未分配/私用区/控制字符 占位
```

**跳过拼接**。语义上：拼接是**全局视图**用来并排展示「这个字符在不同标签下各叫什么」的，
放到某个具体标签下就必然越界。无语境时保持原样。

顺带删掉死代码 `zhNameIn(cp, tagName)`（全文件零调用，语义与新链重复）。

**实测（全量扫描，8452 条 × 8 千+ 标签路径 = 757 万组合）**：
- 旧值含**越界拼接名**的组合 **253,017 → 0**
- 取值变化的组合 1,539,063（全是"非其组所属标签下，由别标签组名改回兜底直译"这一类）
- 新值为空 0 条

## 6. 拼接名也纳入兜底名

用户的推理：

> 单个组名，意味着「在这个标签下叫 a 这个名字」和「在其他标签下叫另一个名字 b」，那么就该拼这个 a 和 b 呀。
> b 可能是来自于条目级，可能来自于直译兜底。

我先照字面量了一遍，得到 **7035 / 8452 条**全局名会变，且很难看（😃「张嘴笑脸」→「带张开嘴的微笑脸、张嘴笑脸」），
据此建议退回。**用户纠正了判据**：

> 如果有条目级名，那么没有特别配置主名的标签下，显示的就是条目级名字，它们「贡献」的就是条目级名字，
> 兜底直译显然不会再参与了啊。
> 而如果没有条目级名字，在未配置主名的标签里，符号显示的本来就是那个怪怪的「直译兜底名」，
> 那么拼接时用它，也不显得特别怪了。这种情况应该是去加条目级名字，或者到标签里加主名。

我量的时候用的正是 `条目级 name or 直译` —— 所以那 7035 条本来就是「**没有条目级名**」的那批，
它们在未配置的标签里显示的**就是那个直译名**，拼接用它是**一致**、不是新增噪音。

**定案**：

```
拼接名 = 去重拼接([ 条目级 name → 否则 直译兜底,  ...各组语境名 ])
```

- **有条目级 `name` 时兜底不参与**（它已"代表"了那些没配主名的标签）
- **没有条目级 `name` 时兜底参与**（一致性）
- 占位名（未分配/私用区/控制字符）**不参与**

**实测**：✊ = `举起的拳头、举起拳头`；🚣‍♂️ = `男人划船、划船男人`（兜底与组名重复，去重后不变）；✌ = `胜利手势`；
有条目级名的 `☝` = `空心竖食指`（直译名「空心向上食指」**没被拼进来**——这是判别性用例）。
**1552 条的显示名真的变了**，其余 6487 条（无组名）显示零变化。

代价明确：机械直译会出现在搜索结果里。**解法是去加条目级名 / 去标签里加主名，不是把它藏起来。**

## 7. 踩过的坑

1. **`isFlag(item) { return Array.isArray(item); }`** —— 名字叫「旗」，实际语义是「是序列」。
   15 处调用全按这个语义用，于是 `gridItemName` / `itemTitle` / `selectItem` 三个入口在 `isFlag` 分支里
   **短路掉了刚修好的语境函数**，导致序列语境名两轮都不生效。改名为 `isSeq`（19 处）。
   **教训：误导性的函数名会让后续改动落在错误的调用点上，而且症状看起来像是"改动没生效"。**
2. **`zhNameOf(数组)` 会抛 `RangeError`** —— 内部 `String.fromCodePoint(cp)` 收到数组转成 `NaN`。
   `ctxAliases` 原来正是靠「数组提前返回」绕开它的；一旦去掉短路就必须同时换掉 `shown` 的兜底。
3. **`ctxGroupKey` 要求组有 `name`，会让"只挂别名的组"永远圈不到自己** —— 1500+ 个组是这个形态。
   取别名必须另用 `ctxAliasKey`（精确匹配标签名，**不要求有 name**）。
4. **`sed` 全局改名会误伤** —— `s/seq_alias/seq_meta/g` 把 `seq_aliases` 改成了 `seq_metaes`，脚本运行时才炸。
5. **边遍历边删字典** —— `for k, gg in g.items(): g.pop(k)` 抛 `RuntimeError: dictionary changed size`。先取键快照。
6. **UI 改名往返不能让数据文件字节复原** —— 保存会把组名写进 `符号富化数据.js` 的 `groups`，改回去会残留一个 `name` 键。
   （测试代理每次都用 md5 逐字节还原并复核。）
7. **`?v=YYMMDD` 一天里改两次就断不掉缓存** —— 本地会一直吃旧代码、误判成「改了没生效」。
   已把 `符号.js` / `符号.css` 加进 `dev_server.py` 的 `NO_CACHE_FILES`（**需重启 dev server 生效**；生产部署仍走 `?v=` bump）。

## 8. 被否决 / 被修正的方案

| 方案 | 否决理由 |
|---|---|
| **全局名只取第一个语境名** | 会让现有的**真·多名**条目也被砍（`♂` 的「男性、雄性、火星」、`⛺` 的「帐篷、露营、户外」）。 |
| **详情向编辑看齐（别名严格按标签，去掉聚合兜底）** 与 **编辑向详情看齐（到处可编辑）** 二选一 | 两条都只是打补丁。用户直接给出了模型（标签别名 / 全局别名）与按组分块的界面，问题从模型上消失。 |
| **把昵称「胜利手势」直接写进名字表** | 那是硬改名，会冻死这条（`cur != translate(en)` 就不再可重跑）。正解是补 `VICTORY HAND` 短语。 |
| **砍掉人称只留「蒸桑拿」「莲花坐」** | 用户修正：完整直译（`人在桑拿房` / `莲花坐的人`）与活动侧写（`蒸桑拿` / `莲花坐`）**两种读法都要**，各归各轴。 |
| **拼接名不含兜底名**（我基于 7035 条劣化样本的建议） | 判据错了：那批本来就是「没有条目级名」的，未配置标签下显示的**就是**那个直译名。用户指出正解是去补名，不是把兜底藏起来。 |

## 9. 一处行为变化（判定为修正）

**肤色兄弟扩散的「全局块」分支不再联动肤色兄弟。** 全库只有 `👨‍🎨` / `👩‍🎨` 两个家族会触发：

- 改前：👨‍🎨 与 👨🏻‍🎨… 的拼接名都是 `男画家`（相等）→ 改全局名会把这 5 个兄弟一起改掉
- 改后：👨‍🎨 = `男艺术家、男画家`，兄弟 = `浅肤色男艺术家、男画家`（不等）→ 不联动

`syncSeqSiblings` 的注释本来就写着「本身名字不同（如带肤色前缀）不动」——**旧行为违反了它**。
组名那条路径不受影响（兄弟的同名组照常联动）。
