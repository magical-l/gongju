## 1. 筛选：通用字段只能粗筛

第一遍只按通用类别（`Po/Pd/Ps/Pe/Pi/Pf/Pc/So/Sm/Sk/Sc/Zs`）筛，捞出 **2000 多个**。
一看内容——**手语图示 545、汉字部首 330、盲文点阵 256、带圈假名 135、希腊声乐记谱 68**。
它们的 GC 确实是 `So/Sk/Sm`（Unicode 就这么分类的），但**内容根本不是装饰**。

**加一层官方名关键词**（含 `MARK`/`PUNCTUATION`/`DANDA`/`SECTION`/`SEPARATOR`/`ORNAMENT`，
排掉 `HAND-`/`RADICAL`/`BRAILLE`/`CIRCLED`/`NOTATION` 等）→ **365 个**，
再排掉乐谱与已否决项 → **248 个候选**，分布在 **62 个文字系统**。

## 3. 三个教训

### ① 预览页的字体栈必须跟实际环境一致

判读页为了显示南亚文字用了 `Nirmala UI` 等专门字体，而**符号页用的是**
`Arial → Segoe UI Emoji → Noto Sans Symbols 2 → Segoe UI Symbol`。两者显示能力不同：
**用户在判读页看到方框的字符，在符号页其实能正常显示**（`11B00` `11B01` 就是这样被误删的）。

**要判"能不能显示"，就得在实际那个环境里渲染。**

**连带**：豆腐块该在**建的时候就自动检测剔除**——渲染成位图、跟空白/空栈位图比对即可，
不该等用户发现。（这轮补做了检测：490 个里符号页字体栈下 **0 个豆腐块**。）

### ② 拿数据字段当结论，又犯一次

`A8FA` 的 GC 写着 `Po`，我据此说"它不是组合符"；**用户 F12 实测它叠在一起、不占宽度**——
它是**天城文脱字符**，官方名就写着。**看名字就明白的事，我去查了字段。**

### ③ 判形状看"单字符"，不看"重复排"

「重复排」是**给人看**的好办法（单个竖线看不出价值，排一排就是竖条纹），
但它**只适合判"好不好看"，不适合判"是什么形状"**——
我一度想用"重复起来围不围出格子"判网格纹，而**任何交叉重复起来都会形成格子**，判据作废。
正解是**单字符内部**有没有网眼。

## 4. 自动化到什么程度

| 能做 | 不能做 |
|---|---|
| **豆腐块检测**（渲染成位图比对） ✓ | **形状判读**——"主体是什么形状"要眼睛 |
| **孔洞数**（网格纹的初筛，`🙨` 9 个孔 vs `✕` 0 个孔） | 孔洞数只说明"有镂空"，不说明"排成格子"（`🉠` 福字 5 个孔、`⚜` 3 个孔，都不是网格） |
| **按官方名关键词归类**（`HEXAGON` / `DIAMOND` 一眼可判） | 关键词两头都会错，得配人工复核 |
