# 字符作画页：画布设置对话框重构（优化5）

## 动机

todo 优化5「画布设置」共 6 点用户反馈，外加两轮设计纠正：

1. 内边距太大
2. 直接在对话框做预览，就可以取消预览窗了
3. 渐变方向下拉里混着"天空草地(145deg)"这种配色命名的选项，与预设按钮重复
4. 渐变色起止颜色控件是两个细长条，跟"→"分成 3 行
5. "天空草地""浅灰""日落"等预设按钮用途不明
6. 宽高输入框各占一行且位置靠后，应一行、作第一组

设计纠正（用户反馈后重做）：① 对话框不该用 JS 动态生成，应直接写 HTML 静态 `<dialog>`；② 背景预览应放 `.body` 背景而非 dialog 背景；③ 后代元素不应为可读性打白底补丁。

## 变更

| 文件 | 变更 |
|------|------|
| `字符作画/字符作画.html` | 新增静态 `<dialog id="canvasSettingsDialog">`（尺寸、背景类型、纯色/渐变控件、方向下拉、颜色行、预设背景色区、取消/应用） |
| `字符作画/字符作画.js` | `showCanvasSettings` 从 `createElement + innerHTML` 重写为操作静态 dialog；新增 `canvasSettingsEls`/`parseGradient`/`toHexColor`/`updateCanvasSettingsMode`/`updateCanvasSettingsDialogBg`；`initCanvasSettingsDialog` 一次性绑定事件；删除 `#gradientPreview` 预览条与 `updatePreview` |
| `字符作画/字符作画.css` | dialog padding `40px 50px` → `24px 28px`；`input[type=color]` 紧凑尺寸 44×32；`.size-row`/`.group-title`/`hr.divider`/`.dialog-actions`/`.solid-row` 新增；`.gradient-preview` 删除；颜色行 `nowrap` |

### 功能增强：纯色背景

背景原只支持 linear-gradient（裸 CSS 字符串）。本次新增「纯色 | 渐变」类型切换（btn-group 连体分段），纯色只显示单个颜色控件。存储零改动——`style.background` 仍是字符串，snapshot/undo/导出/autosave 不受影响。

### 背景预览方案

- 预览直接做在对话框 `.body` 背景上（`#canvasSettingsBody`），JS 实时更新 `linear-gradient(...)` 或纯色
- 控件（input/select/button）保留 `--bg-muted`/白底保证可操作，文字不加任何背景
- 用户自选深色背景时文字可能偏淡——实时预览就在眼前，用户能自行判断，不做防御性补丁

## 踩坑记录

1. **对话框 JS 动态生成是坏味道**。原 `showCanvasSettings` 用 `createElement + innerHTML` 拼整个对话框，用户指出应直接写 HTML 静态 `<dialog>`，JS 只控制。静态化后结构一眼可见、事件一次性绑定，符合"往通用标签靠"方向。showHelp 仍为动态生成（未在本次范围）。
2. **背景预览放错位置，白做一遍**。第一版把渐变写到 `<dialog>` 元素背景，但 dialog 内部 `.body` 是白色浮层，盖住大部分 dialog，渐变只在 padding 边缘露出一点，等于看不出效果。用户纠正：预览应放 `.body` 背景，body 就是对话框主体，渐变大面积可见。
3. **后代元素白底补丁是过度防御**。为防深色背景文字不可读，给 h3/.group-title/label 加 `rgba(255,255,255,0.92)` 白底，在渐变上是一块块补丁很丑。用户指出后删除。默认浅色渐变下深色文字直接可读；深色背景是用户主动选择且实时可见。
4. **机械执行 vs 主动建议**。用户批评"你应该出个主意：背景也可以是纯色的，而不是只会机械地执行命令"。背景只支持渐变是明显局限，应在执行中主动识别并补上纯色。
5. **CSS-edit-safety 守卫**：含 `>` 的选择器 rename/remove 被拦截；`dialog > .body input { width:100% }` 对 color 控件不适用的修复，用更高特异性 `input[type=color]` 覆盖，与项目 `.size-row input` 覆盖模式一致。
