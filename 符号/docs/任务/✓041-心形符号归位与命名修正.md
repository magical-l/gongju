## 3. 命名（用户定的四条，写下来复用）

1. **直译名必须忠实官方名，不许丢成分**（尤指 `HEAVY`）。
2. **字形名里的 `BLACK` 是「实心」义**，不是黑颜色（同 `EMOJI_WORD['BLACK']`）。
   且**符号本身无色** —— `❤` 作为单色字符颜色随 CSS `color` 变，所以不叫「红心」。
3. **直译名撞名不要紧**；「心」标签下这批本质上就是一堆实心/空心心形，不必强行区分。
4. **避开中文里的歧义词**：`花心`（用情不专）→ `花饰`。

## 4. 语境名与直译名各管一段（本轮的两次返工都是这条）

- **语境名**（挂 `groups["心"].name`）：只管**标签视图**，是「这个字符在该标签下叫什么」，可省略噪音成分。
- **直译名**：管**所有其它视图**（搜索、无标签浏览、别的标签），必须忠实官方名。

第一轮我只补了语境名 → 用户问「这些字符在别处还是坏名怎么办」；
改直译名又会**全局生效**，所以必须按 §3 那四条规则定，不能按语境名顺手写。
⚠️ **用户说「起语境名」时不要顺手改直译名，反之亦然。**

## 5. 根因：`EMOJI_PHRASE` 短语会截胡更长的官方名

`'BLACK HEART': '黑心'`（给 🖤 那个**真黑颜色**的心用）会把 `HEAVY BLACK HEART` 里的
`BLACK HEART` 整段吃掉，剩 `HEAVY` 拼成「粗黑心」；`'HEART EXCLAMATION'` 同理留下落单的 `MARK`。
修法是**整名定死**：`HEAVY BLACK HEART` / `HEAVY HEART EXCLAMATION MARK ORNAMENT` / `LIGHT BLUE HEART`
三条短语进 `emoji词表.py`，直译名同步成引擎输出 —— `translate(官方名) == 直译名`，重跑可复现，不会被
`find_scope` 当人工值冻住。**规则已写进 `设计/数据说明.md` §七「封闭集合」一节。**

## 6. 留下没做的

1. **搜索视图的「拼接名」仍会带直译名**（例：搜 `❤` 得「粗实心心形、实心心形」）。
   那是 `joinGroupNames` 的**设计**——拼接名 = 各标签名的并集，不是没生效。
2. ❦❧☙ **不是 emoji**（不在 `emoji-test.txt`），直译名归 `build_zh_translation.py` 管；
   该脚本 merge-only，**不存在重跑覆盖的风险**，故没往 `译名词表.py` 补短语。
3. `粗心形感叹号装饰` 连读像「粗心」（careless），用户可选「粗体心形感叹号装饰」。
4. 全库同类的坏译名（`重`/`粗` 与词表不同步的**搁浅**、修饰词被吞）**未普查** —— 那是 `·015` 命名质量普查的范围。

## 7. 教训

1. **「名字含某字」这种字面判据在大库里必然噪声压倒信号**（802 → 79 → 43）。
   别自己挑一个读法就动手，**先把量级和样例摆给用户**。
2. **验证脚本查名字要拼十进制键**（`str(cp)`）。我拿 `'2763'` 当键查过一次，那是 `U+0ACB`
   （古吉拉特元音符号 O），差点当成写错。这条 `设计/数据说明.md` §一「键空间」早就写了，**照踩**。
3. **子代理报的「显示名」要回数据核对。** 第一轮 testing 把 ♥/♡ 的名字抄串了
   （报成 `空心红心花色`/`实心红桃花色`，与数据对调），第二轮回查才对上。
4. **该页搜索框对纯数字输入按十六进制优先解析**（`符号.js:297-310`，越界才回退十进制）。
   想按码点搜 `❣` 要输 `2763` 而不是 `10083` —— 我把它当十进制写进测试要求，害子代理多绕一圈。
