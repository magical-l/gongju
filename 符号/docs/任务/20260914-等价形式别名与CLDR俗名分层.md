## 1. 待办 27：等价形式别名

### 1.1 做法

`build_equiv.py` 从两个来源算「这个字符还能写成什么样」，写进 `符号富化数据.js` 的**条目级 `alias`**：

- **NFKC 展开式** —— `参考资料/UnicodeData.txt` 的 Decomposition_Mapping 字段，递归全分解后按规范重组。
- **同形字** —— `参考资料/confusables.txt`（UTS #39）。

搜索通道（`meta.aliases`）本来就认这个字段，**搜索代码零改动**。

### 1.2 铁律：NFKC 只碰数据，不碰用户输入

给字符发别名，**绝不把查询词 NFKC 化**。折查询词会让「打 `①` 直接跳到它」退化成「在三千多条里翻」，而那是本工具的核心交互。实测：51704 个单码位字符里 **4985 个（9.6%）** 会被 NFKC 改写成别的字符本身（`①→1`、`㎏→kg`、`㍿→株式会社`）。

### 1.3 数字与噪音

规模：**5313 字符 / 5674 条等价形式**；596 条老条目追加 alias、**4521 条新建条目**。

噪音实测（与设计文档的预测吻合）：

| 查询 | 现在 | 加表后 | 增量 |
|---|---|---|---|
| `xii` | 0 | 2 | +2 |
| `m2` | 6 | 11 | +5 |
| `kg` | 2 | 2 | +0 |
| `1` | 6920 | 6971 | **+51（0.74%）** |
| `a` / `ok` / `fi` / `in` | — | — | **+0** |

### 1.4 被排除的四类（都写了理由，别当成漏收）

1. **emoji 对应的「遗留计算符号」字形**。`confusables.txt` 把一批 emoji 跟 Unicode 16 的 Symbols for Legacy Computing 区配了对（🍓 对应 U+1CEBF「STRAWBERRY SYMBOL」）。那一整块是给复古电脑美术用的仿 emoji 图。收进来的后果是草莓的详情区别名行多一个「另一个草莓字形」。见 `DECORATIVE_BLOCKS`。
2. **跨文字系统的形近字**。源字符收窄到 拉丁/希腊/西里尔/通用，**目标**另加汉字白名单。挡掉 `ö→ة`（阿拉伯）、`▽→𐊼`（卡里亚）这种——形似，但中文用户既打不出也用不上。
3. **「等价写法就是它自己的名字」**。康熙部首 `⼀`(U+2F00) 的展开是 `一`，而它在直译名里的中文名**也是**「一」。挂上去的结果是详情区「名字：一，别名：一」。搜「一」本来就能从直译名通道命中它。**命中 170 条。**
4. **展开结果含组合符/空白的**。如 `¨` 展开成「空格＋组合分音符」，没法当搜索键，显示出来还是不可见字符。另：`U+2028` 这类行分隔符会**破坏 JS 源码行**，必须挡。

### 1.5 别名不得与显示名同字 —— 四处都要避让

`blocked()` 收集「这条条目里已经会当名字显示」的词：条目级 `name`、各组 `name`、各组已有 `alias`、**以及直译名兜底名**。漏掉第四处会多出 **170 条**重复（康熙部首那批，见上）。

### 1.6 副作用（已知并接受）

新建条目的字符，**改名落盘从 `官方名直译名.js` 改到 `符号富化数据.js`**（`dev_server.py` 的 `sym` 路由看的是「在不在 ENRICHED_SYMBOLS 里」）。用户明确表过态：在页面上给它们改名，本来就该落到符号数据。

## 2. 待办 29：CLDR 俗名的分层搬移

### 2.1 做法

`官方名直译名.js` 是直译名，只该装官方英文名的机械直译。但它混着一千多条 CLDR 俗名（`GRINNING FACE → 嘿嘿`）。做法：

1. **认范围**（`find_scope`）：`U+2600-27BF + U+1F000+` 里所有有 CLDR 俗名的单码位，且直译名当前值是「CLDR 兜底值」**或**「本脚本产出的直译」。人工改过的名字不动。
2. **补直译**：`emoji词表.py` 的词 + 结构规则（WITH/AND/OF/FOR/BEHIND 五个结构词 + 短语切分），写回直译名。
3. **搬俗名**：写进符号数据的 `alias`。

### 2.2 范围（1284 条，六类互斥）

| 类 | 条数 | 说明 |
|---|---|---|
| 直译 == 俗名 | 469 | 那个值既是俗名又是正确直译，直译名不用换 |
| 俗名已收录 | 111 | 条目里本来就有 |
| 俗名被主名包含 | 197 | 挂别名是冗余（见 2.4） |
| 补 alias | 150 | |
| 新建条目 | 357 | |
| 删撞名别名 | 8 | 见 2.5 |

直译名换直译 **813** 键。新建条目的 alias 挂该字符所属**最深非机械标签**下（机械轴 `文字系统`/`官方分类`/`区块`/`emoji（绘文字）` 不作组键）。

### 2.3 emoji 词表为什么必须独立成文件

`符号/emoji词表.py` 与 `符号/译名词表.py` **故意分开**。同一串字母两边归属不同：

| 词 | `译名词表.py` 里 | `emoji词表.py` 里 |
|---|---|---|
| `CAT` | 加拿大原住民音节的**记音**（在 `_KEEP_SYLLABLE`，与 `CAAI CAP CAU` 同行） | 🐱 的「猫」 |
| `MAN` | 卢恩等文字系统的**字母本名**（在 `_KEEP_LETTER`） | 👨 的「男人」 |
| `PIN` `BAG` `CAR` `COW` `HAT` `BOX` `EAR` `BAR` `TWO` … | 同理，各有记音/专名用法 | emoji 名里的实词义 |

编辑者用的判据是「这个词在名字里的实际用法」，而它服务的直译名是全局的、上下文无关的；emoji 名是**独立语料**。所以两边各自成表，同名不同义由**调用方**决定用哪张——`build_emoji_zh.py` 只查 `emoji词表`、再兜 `译名词表.WORD`，**绝不兜 KEEP**。

### 2.4 守卫一：俗名已被显示名包含就不挂别名

搜索是**子串匹配**，打「融化」本来就能命中主名「融化脸」。再挂一条同名别名，只是让详情区的别名行把主名念第二遍。**命中 197 条。**

（这条是用户手工删掉 🫠 的别名「融化」时给的理由，固化成规则。）

### 2.5 守卫二：直译名的值一换，就要查既有别名会不会撞上

显示名跟着直译名的值走。若新显示名**恰好等于该条既有的某条别名**，别名行就会重复主名。实测 8 例：🍊柑橘 🐢乌龟 ⛓锁链 🪯双刃剑 🩻X光 🏃跑者 💃舞者 🤱哺乳。

处理：删掉那条别名（它已成主名，直译名通道照样搜得到）。**删空的组把那个字符串提为组语境名**，不留空组（💃 就是这样：`{"通用":{"alias":["舞者"]}}` → `{"通用":{"name":"舞者"}}`）。

### 2.6 `find_scope` 的可重跑性（踩过的坑）

最初用「直译名的值 == CLDR 俗名」当探针 —— **搬完一次脚本就再也认不出这些码位**，重跑等于失效。改成双条件：值 == CLDR 兜底值 **或** 值 == 本脚本产出的直译。后者让脚本可重跑，且人工改过的名字（两个都不是）仍然不动。

## 3. 待办范围外、查证后确认是既有问题的两处显示 bug

两处都在 `符号/符号.js`，都**对 `git HEAD` 跑同一套复算得到相同结果**，即不是本轮引入。

### 3.1 `ctxAliases`：标签语境下别名行把主名重复一遍（74 个字符）

触发条件固定：条目的全局名是「几个语境名拼起来」的（⚔ 是「击剑、双剑」），而你选中**不包含这个字符**的标签（通用 / 其他符号 / 杂项符号 这类）。此时显示名取 `zhNameOf` = `globalName`（拼接串），紧接着的「其他组名当别名」循环又把这几个语境名逐个加了回去——**拼接后的串不等于任一段**，`seen.has(g.name)` 这个精确相等的去重闸拦不住。

修法：条件里加 `|| shown.includes(g.name)`。改的正是 `数据说明.md` 第四节早就写明的规则——「一律排除"当前正在显示的那个名"」。

验证：`通用` 标签下 9123 个码位做新旧逐码位比对，**73 个变化全部是「整条别名清空」**（无新增、无部分删除）；`功夫`/`军事、武器、战争`/`表情、表达` 三个标签整表哈希一致（零变化）。端到端 A/B 对照（用 `page.route` 替换成改前的 JS 跑同一套用例，两份产物只差那一行）结果一致。

### 3.2 `searchCardsFromKeys`：搜索时折叠卡选错了主变体

表情/人物类有「同款不同肤色、不同性别」的 ZWJ 序列，搜索时按肤色折叠成一张卡。挑主变体那段是 `members.find(命中preferKeys的)` —— **`find` 取列表里第一个命中项**，而 `members` 顺序来自各标签 seqs 的并集顺序。搜「划船」时 `浅肤色` 标签那两条排在 `水上运动` 之前，于是浅肤色那条先被选中；**可无肤色那条其实也命中了**（它的名字就是「划船」）。

修法：命中项先聚成数组，再从里面优先挑无肤色的；没有才退回命中数组第一个。原来那两级兜底（整体无命中 → 无肤色；再无 → 第一个）原样保留。

验证：搜 `划船` 由 🚣🏻‍♂️/🚣🏻‍♀️ 变成 **🚣‍♂️/🚣‍♀️**；搜 `浅肤色划船` 仍出浅肤色两条（命中优先没被废掉）；卡片的「肤色变体」下拉仍在。

### 3.3 同一个文件里还有两处**没动**的东西

- **序列名丢性别**：🚣‍♂️ 叫「划船」而不是 CLDR 短名「男生划船」。机制是 `build_zwj.py` 对没有程序化规则的序列取 **CLDR 关键词表的第 0 个词**（最宽泛的那个），而不是短名 `tts`。不是普遍现象（🏃‍♀️ 拿到的是「跑步女人」，走了程序化规则）。一刀切换 tts 会改 113 条且好坏参半（`❤️‍🔥` 现名「燃烧的心」更好），正确方向是给 `build_zwj.py` 补性别规则。**未修。** → **已于 v1.38.0 修**：序列名整体改走机械直译、CLDR 退出名字层，见 `20260915-序列命名分层与双轴语境名.md`。
- **全局名是「语境名拼接」**：⚔ 显示「击剑、双剑」、♂ 显示「男性、雄性、火星」，全库 87 个条目这样。要不要改是显示规则问题，**未定。** → **已于 v1.39.0 定案**：改名「拼接名」，并把直译兜底纳入拼接，见 `20260915-名字分层与编辑界面改造.md`。

## 4. 踩过的坑（按严重度）

1. **词表里同一个键写两次，后者静默覆盖前者。** `EMOJI_WORD` 的 `PALM` 在「手」段写 `手掌`、在「植物」段写 `棕榈`，`dict.update()` 让后者赢了 —— `🤦 FACE PALM` 译成「脸棕榈」、`🫳 PALM DOWN HAND` 译成「棕榈下手」。`FLAT` 同病（「平底」被「降号」盖掉，`🥿 FLAT SHOE` 成「降号鞋」）。**改词表后必须扫一遍重键。** 修法：易混词改用短语定死（`PALM TREE`/`FACE PALM`/`FLAT SHOE`）。
2. **`deepest_semantic_tag` 是死代码。** `walk()` 没把节点自己的名字传进递归，`best` 初值恒为 `(depth, None)` → `cand[1]` 永远 None → 子节点永远选不中，名字只能来自根那一层。实测 460 条新建条目里 **410 条拿不到标签**、50 条拿到的是根标签。修后 459 条拿到深层标签（最深第 4 层）。
3. **dry-run 报的数字是硬减出来的。** 拿 `len(equiv) − 已有条数` 当「需新建」，不计重复过滤，**虚报 170 条**。修法：落盘与 dry-run 拆成「算计划 / 按计划落盘」两个函数共用。
4. **`usable()` 用 Python 的 `unicodedata` 判类别会漏判。** 本机是 UCD 14，项目用的是 17.0.0，Unicode 15+ 新增的组合符会被当成「可用」（`ⷮ→U+1ADB` 是个组合符却漏了）。改成从项目自带的 `UnicodeData.txt` 读类别。
5. **confusables 只收窄源侧不够。** 目标是阿拉伯/卡里亚等文字系统的也要挡（`ö→ة`、`▽→𐊼`）。另外源侧收窄时 `Scripts.txt` 里的脚本名是 `Latin` 不是 `LATIN`，大小写不匹配会让收窄结果**静默变成 0 条**。
6. **「直译落空」会静默写空名。** `EMOJI_WORD` 里 `'THE': ''`、`'A': ''` 是去冠词用的；万一某个官方名整串只有冠词，直译就是空串，而 `datatool.check_all` 只校验直译名的**键**合法、不校验值非空。加了兜底：落空则保留原值并计数。

## 6. 顺带查清的两件旧事（**不是**本次引入）

用户看页面上几个别名觉得可疑，查下来都是早期会话灌的，且**当前仓库里没有任何脚本会重新灌它们**：

- **CLDR 关键词别名 1250 条**（如 🍓 的「浆果」）。`annotations-zh.json` 每个 emoji 有两个字段：`tts`（短名，待办 29 搬的就是它）和 `default`（关键词串：水果/浆果/草莓）。后者被当别名灌进来了 —— 其中 680 条就是该字符的 `tts`（本来就该收），另 **570 条是额外关键词**（好的是「哈哈」「大笑」，怪的是「浆果」「lolol」「超扯」）。CLDR 没给「同义词/联想词」的标记，没法自动切分。
- **Title Case 英文别名 516 条**（如 😅 的 `Grinning Face With Sweat`）。**不是 Unicode 官方名**（😅 官方名是 `SMILING FACE WITH OPEN MOUTH AND COLD SWEAT`），是 CLDR 英文短名转 Title Case。最早出现在提交 `34f7288`。

判别名出处的正确姿势是 `git log -S '<别名>'` —— 只看 `HEAD` 会误判（`HEAD` 只是最近一次提交，不代表是人写的）。
