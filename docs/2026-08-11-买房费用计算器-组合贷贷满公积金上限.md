# 买房费用计算器：组合贷默认贷满公积金上限 + 便捷按钮

## 动机

组合贷（公积金+商贷同时启用）下，用户通常希望公积金贷满政策上限（利率低），商贷补足余额。此前版本贷款总额变化时按当前公积金/商贷比例拆分（保持比例），不符合用户预期。需求经历三轮演进：

1. 最初实现「锁定公积金贷款上限 / 锁定比例」单选组 + 模式联动；
2. 用户反馈「锁定比例」无意义，要求大幅回退，直接默认贷满公积金上限即可，且不锁定公积金输入框（这只是个便捷操作）；
3. 补充规则：若用户手动改了「公积金贷款额度」的值，就保留该值。

## 变更（`买房/买房费用.html`）

| 项 | 说明 |
|----|------|
| 计算属性 | 新增 `isCombined()`（`useFund && useCommercial`）、`fundCap()`（首套240/二套160/三套0 政策上限） |
| 方法 | 新增 `fillFundAtCap()`：公积金贷满 `min(fundCap, loanPrincipal)`，商贷补足余额 |
| 数据 | 新增 `fundManual: false`：用户是否手动改过公积金额度 |
| UI | 贷款卡片底部新增「贷满公积金上限」按钮（仅组合贷 `v-if="isCombined"`）；公积金额度输入框加 `@change="fundManual = true"` |
| 联动 | `useFund`/`useCommercial` 形成组合贷时自动 `fillFundAtCap()`；`loanPrincipal` 变化时——未手动改 → 贷满上限；手动改过 → 保留公积金额度、商贷补足 |
| 帮助 | 弹窗新增「组合贷默认贷满公积金」说明 li |
| 缓存 | `STORAGE_KEY` 保持 `2026v4`：新增字段向后兼容，旧缓存可加载（`created()` 只复制已存在的 key，`fundManual` 默认 false），无需迁移 |

## 设计决策

- **区分"手动改过"用 `@change` 事件而非 watcher**：`el-input-number` 的 `@change` 只在用户操作时触发，程序化赋值（商贷联动调整公积金、`fillFundAtCap` 重置）不触发，避免误标记。若用 `fundAmount` watcher 标记，会连带把「用户改商贷 → 程序化调整公积金」也当成手动。
- **`fillFundAtCap()` 开头 `this.fundManual = false`**：一键贷满后回到"默认"状态；重开组合贷自动贷满同样复位。
- **只改商贷不改公积金 → 不误锁公积金**：商贷联动引起的公积金调整属于程序化，`@change` 不触发，`fundManual` 保持原值。
- **首套↔二套切换**：默认态公积金更新到新上限（240↔160）；手动态保留手动值（用户明确改过的数字优先）。
- **手动值恰好等于政策上限**时 `fundManual` 仍为 true，但与默认分支结果等价（值相同），行为无差异。

## 踩坑记录

1. **el-input-number aria-disabled 残留（`lib/` 修改，用户授权）**：Element Plus 2.10.7 的 `el-input-number` 只在 `onMounted` 里 `setAttribute("aria-disabled", ...)` 一次，`onUpdated` 钩子只同步 `aria-valuenow`、从不更新 `aria-disabled`，导致禁用状态切换（由禁用变启用）后 `aria-disabled` 属性残留旧值 `"true"`——屏幕阅读器会把已启用的输入框播报为禁用，Playwright `fill()` 也会拒绝操作。经用户确认走正道修复根因（即使改 lib/），在 `lib/element-plus/2.10.7/index.full.js` 的 `onUpdated` 补一行同步 `aria-disabled`（与 `aria-valuenow` 同理）。此 bug 影响全 app 所有 disabled 切换，属上游组件缺陷，本次一并根治。
2. **watcher 行为迭代**：回退单选组后，`loanPrincipal` watcher 保留了原比例拆分逻辑（`fund * val / total`），其行为恰等于用户否定的「锁定比例」——回退不彻底。后改为默认贷满，再补手动保留规则。教训：回退时要把原逻辑中与新需求冲突的部分一并审视，不能只删新增代码。
3. **`@change` 依赖 Element Plus 事件语义**：`@change` 在用户输入提交（blur/Enter）时触发；程序化 v-model 变更不触发。功能测试已覆盖「只改商贷不改公积金 → 改总价公积金回上限」，确认无误触发。

## 验证

- Playwright 功能测试 12 项断言全过：默认贷满/改总价保持上限/手动 100 改总价保留/按钮恢复/只改商贷不误锁/二套上限联动（默认160、手动保留）/重开组合贷回默认，无 console 错误。
- lib 修改后 aria 复测：切模式 `aria-disabled` 正确同步为 `"false"`（修复前残留 `"true"`）。

# 同日补充：三角联动身份系统（公积金+商贷+首付=总价）

## 动机

用户要求贷款模块三个值恒满足等式：**公积金 F + 商贷 C + 首付 D = 总价 P**，编辑任一值其余按优先级自动调整，原始输入值不再静默钳制。

## 最终设计

**核心不变量**：`F + C + D = P`（组合贷）/ `F + D = P`（纯公积）/ `C + D = P`（纯商业）。

**组合贷：公积金锚定，商贷↔首付互变**

| 编辑 | 保持 | 变化 |
|---|---|---|
| 公积金 F | F、D | `C = P−D−F` |
| **商贷 C** | C、F | **`D = P−C−F`（首付回写）** |
| 首付 D / 总价 P | F | `C = P−D−F` |
| 关闭某贷款 | 保留的贷款 | `D = P−保留贷款`（首付补缺口） |

- **设计漏洞修正**：最初"编辑商贷 → 公积金吸收"（`F = P−D−C`），但公积金默认已贷满上限，商贷增减会把公积金顶过上限或压低于贷满——首付永远动不了。改为**公积金锚定**（默认贷满上限；手动改过锚定手动值），商贷与首付成为仅剩的两个自由度互变。
- 纯公积/纯商业：改贷款 ↔ 首付互变。
- 免付模式：首付固定 0，商贷↔公积互变。
- 套数切换：非手动公积金更新到新上限（240↔160），手动保持（`fundManual` 仅此用途）。
- 软上限：公积金默认/「贷满」=政策上限，手动或单贷可填更高。

**首付回写**：首付由「比例/定额」算出，联动需要改首付金额时回写源头——比例模式回写 `downPaymentRate`（精度 0→2 位小数保证等式精确）、定额模式回写 `downPaymentAmount`。

**加载归一**：`syncLoanIdentity()` 在 `created()` 加载缓存后执行，把旧缓存/不一致值归一为等式。

## UI

- 「贷满」按钮从底部移到贷款表第一列「公积金」之后，改名「贷满」；状态色：贷满=绿（success）、超上限=红（danger）、未贷满=默认。
- 列宽再分配：额度/利率输入框 120→76px，释放宽度流向第 1/4/5/6 列（公积金/贷满、利息/本息/月供表头不再换行）。
- 数值列右对齐 + tabular-nums（统一 2 位小数→小数点对齐）；额度/利率列整体居中，使综合行数值与上方输入框对齐。

## 踩坑记录

1. **CSS 选择器误伤**：收窄公积金输入框写成 `.loan.card & tbody tr:first-child .el-input-number { width: 80px }`，匹配了该行额度+利率两个输入框，利率框被误收窄。修复：删除该规则（按钮移到第一列后额度列无需收窄）。
2. **`items-near-right` 依赖 `.flex`**：该工具类是 `.flex.items-near-right`（layout.css），贷款表 td 只有 `items-near-right` 没有 `flex`，不是 flex 容器，`justify-content` 不生效——数值左对齐的原因。右对齐改用 `text-align` 实现。
3. **watcher 循环收敛**：公积金/商贷/首付三者互写的 watcher 需逐条推演收敛——编辑 F→C 补足→C watcher 回写 D→回写后的 D 使 loanPrincipal=C+F→C 不再变，闭环 2 轮内收敛。

## 验证

Playwright 功能测试 22 项断言全过：默认 240/240/120、改商贷→首付变（公积金保持）、改公积金→商贷补足、贷满按钮三态颜色、手动公积金改总价保持、关/开贷款、纯公积/纯商业、免付、二套上限联动；多视口（1400→650）列宽布局无换行无溢出。无 console 错误。
