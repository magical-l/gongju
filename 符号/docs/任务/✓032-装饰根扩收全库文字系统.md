## 0. 起点：用户指出我的类比不成立

`✓031` 收尾时我拿「箭头」根（619 个）论证"装饰根收几百个很正常"。用户当场反驳：

> 我们还有好多好多个文字系统，所以你拿箭头说事不靠谱，最后"很多很多"有可能远超箭头。

**他是对的**：「箭头」是**有界**集合（判据是官方名里一个词，全 Unicode 就那么多），
「装饰、花纹」是**无界**的（判据是"外观像不像花纹"，而文字系统有一百多个）。

规模问题被摆上台面后，用户给出了**完整的分层路线**（见 §2）。

## 1. 三个把我绊倒的坑

### ① GC 区间标记：汉字九万多个被当成"未分配"

`UnicodeData.txt` 对 CJK 这类大区段**不逐行列出**，而用 `<CJK Ideograph, First>` /
`<..., Last>` 标记区间。我的读取只认逐行格式，**中间九万多个汉字全被当成"查不到 GC"**。

修好后 GC 表从 **40,575 → 299,382**，"未分配"从 119,303 **归零**。
（用户一眼看出不对："汉字的未分配怎么会有这么多？只有 1400 个汉字？？"）

### ② 豆腐块要跟实际环境一致，而且它不是空白

我先用自定义字体栈的 canvas 测"有没有墨迹"，结果西夏文、契丹小字**全测不出是豆腐块**。
改用符号页自己那套（`notoHas(cp) || _localCan(cp)`，含 noto-cmap 区间 + 空栈模板比对）才对。
**豆腐块是空心方框，有笔画**，"有没有墨迹"根本判不出来。

实测 **17,976 个豆腐块**，集中在西夏文+契丹小字 `U+17000–18CD5`、埃及象形 `U+13460–143FA`、
CJK 扩展 J `U+323B0–33479`。

### ③ 审阅状态没落盘 → 用户被重复问

用户标"删除"的意思是「**别再给我看这个**」，而我只当作"从装饰根移走"。
对**本来就不在根里**的字符，移走是**空操作**——下次筛又冒出来了。

修法：建 `符号/装饰根审阅记录.json`，记**否决码位** + **已审文字系统**，筛候选前先读它。

## 4. 两个可复用的机器判据

**对称性检测**（判"这字规不规整"）：
渲染 → **按包围盒居中** → 左右/上下/旋转翻转 → 算差像素占墨迹的比例。
⚠️ **必须先居中**——`fillText` 左对齐，不居中时连 `A` 都判成不对称。
⚠️ **对称 ≠ 能用**：汉字筛出 887 个对称字，用户一个都没要（笔锋）。

**Gardiner 分类**（具象图形不用逐个看）：
埃及象形的官方名是 `EGYPTIAN HIEROGLYPH D011`，**字母是埃及学标准的 Gardiner 分类**：
`A/B/C/D` 人、`E~L` 动物、`M` 植物、`N` 天地水、`O~Y` 器具建筑、`Z` 线条。
照它归形状，比逐个看图可靠得多。（`NL`/`NU` 是 N 组变体、`AA` 是 Aa 组、
`INSERT/BEGIN/END` 那 16 个是**格式控制符**，要否决。）

## 6. 留下的

- **其他文字系统的字母/音节还剩约 1.5 万个**没处理（拉丁 1353、彝文 1165、楔形文字 913、
  加拿大原住民 723、安纳托利亚象形 583…）。分两类：字母类可再用对称筛；
  **楔形文字、安纳托利亚象形、线形文字A/B 是画**，可以像埃及象形那样按官方名分类码归。
- **`BINDU`/`PADA`/`SURYA` 那批实词没译**（`译名词表.py` 的 `KEEP` 误收，见 `✓029` §3.4）。
- **「已审文字系统」清单里那 110 个，只审了符号部分**——字母部分（`Lo`）从没进过视野。
