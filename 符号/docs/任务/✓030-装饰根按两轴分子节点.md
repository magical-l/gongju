## 0. 起因：判据卡住了

`✓029` 把装饰根收到 263 个之后，用户发现**判据在中间地带失效**——
"很多符号很难说能做花纹，也很难说不能做，尤其是那些竖线形的字符"。

**根因是判据的形态**：「有人会拿它当装饰花纹用」要**想象使用场景**，而想象是可塑的
（"说不定有人用呢"），几乎什么都过关。**换个判据形态就解了**。

## 1. 判据的两次换形

### ① 「排成一排看」——判"好不好看"用，判"是什么形状"不行

用户提出：把字符排成一排，看会不会太密/冲突/不好看。
这确实管用（单个竖线 `།` 看不出价值，排一排就是竖条纹），
**但它只能回答"好不好看"，回答不了"算什么"**。

### ② 「主体是什么形状」——最终判据

用户给出**两个正交的轴**：

> 除了植物纹、动物纹、星形纹、文字纹之外，还可以有条形纹、阴影纹、绗缝纹、圆形纹、
> 方形纹、点状纹之类，**都是看主体形状**。各种文字系统里的字母或字就属于文字纹。
> **子标签也不是分类，不是说非要互斥的。**

**这一次判据变成了纯描述题**——不用想象任何场景，只描述它长什么样。

## 2. 两轴

| 轴 | 子节点 | 判据 |
|---|---|---|
| **身份轴** | `文字纹` | 来自具体文字系统，或字形本身就是「字」（福禄寿喜、ET连字、花体问叹号） |
| **形状轴** | 圆形纹 / 方形纹 / 三角纹 / 线形纹 / 波浪纹 / 云纹 / 点状纹 / 星形纹 / 植物纹 / 动物纹 / 人形纹 / 心形纹 / 交叉纹 / 网格纹 | 主体形状 |

**一个字符两个轴都挂**（`།` = 文字纹 + 线形纹），形状类之间也不互斥（`✢` = 星形纹 + 交叉纹）。
`动物纹` 和 `人形纹` 是用户点名的；`云纹` 是判到一半才想起加的传统纹样大类。

## 3. 三个判歪又改回来的地方

**① 「十字纹」→「交叉纹」**（用户改）。判据是**有没有尖角**：
星形纹是有尖角的放射（`★ ✱–✽ ❉`），交叉纹是等粗的直线相交（`✕ ✚ ✝ ✠`）。
两者**可以重叠**——`✢` 四水滴星号有尖（星形）也是四向交叉（交叉），两个都挂没错。

**② 「绗缝纹」→「网格纹」**（用户说看不懂 `QUILT` 这个词）。
它就是那 4 个字符（`🙨🙩🙪🙫`）：方块里布满交叉缝线，像棉被缝出的方格。

**③ 网格纹的判据，我错了两次**：
- 先写"交叉线围出格子"→ **用户当场指出**：`✕` 重复起来也围格子、`+` 两行也围格子，
  **任何交叉重复起来都会形成格子**，判据作废
- 而且我把页面上的说明**写反了**（说"前两个是网格候选"，可前两个里的 `᰾` 是叉）
- **正解**：**单字符内部**有没有网眼。`🙨` 自己带格子 → 网格纹；`✕` 自己没格子 → 交叉纹

**④ 云纹是补判的**：判第一轮时还没有这个选项，19 个当时只判了波浪纹的字符后来又补勾了 5 个。
**判据是卷不卷**：卷成回勾/螺旋头的进云纹，只上下起伏的进波浪纹。

## 4. 自动化的边界

- **网格纹可以量化**：把单字符渲染成位图，数**封闭孔洞数**——`🙨` 9 个、`᯼` 4 个、
  `✕ ᰾ 𑇍` 一律 0 个，切得很干净。
- **但孔洞数只回答"有没有镂空"，回答不了"镂空是不是排成格子"**：
  `🉠`（福字）5 个孔、`⚜`（百合花）3 个孔、`֍`（回旋纹）8 个孔——**都不是网格**。
  所以它只能做初筛（263 → 45 个候选），**定夺还得看**。
- **给用户判的页面**（visual companion）：每个字符**重复排 8 次** + 形状 checkbox + 删除标记，
  **勾选即自动上报**（不依赖点提交）。

## 5. 一个反复踩的坑：拿数据字段当结论

**用户 F12 实测：它叠在一起、不占宽度**。
