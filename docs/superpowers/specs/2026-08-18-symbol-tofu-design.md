# 符号页：豆腐块检测、替代显示与字体信息

- 日期：2026-08-18
- 状态：待用户审阅
- 范围：`符号/` 页面（符号.html / 符号.js / 符号.css）

## 背景与问题

1. **豆腐块（tofu）**：某些字符在用户设备的字体环境中没有字形，渲染为方块。用户希望"显示不了的字符不要显示为豆腐块"。
2. **todo bug1**：同一字符在中间网格显示方块/空白，右侧详情区却正常（如带柄向上箭头）。根因：**网格卡片字体栈太窄**——只有 `'Noto Sans Symbols 2', sans-serif`（[符号.css:274](符号/符号.css#L274)），而详情区用的是带系统符号字体的 `fontStyle(selectedPreviewFont)`。Noto 缺字形时，网格 fallback 到微软雅黑渲染成方块，详情区 fallback 到 Segoe UI Symbol 等系统字体则正常。

## 两个目的

**目的1 · 减少豆腐块**：把"内嵌 Noto + 用户本机字体"能显示的字符尽量显示出来；真显示不了的，替代显示而非豆腐块。

**目的2 · 字体信息**：让用户知道某字符靠什么字体显示，尤其是"网页内显示、离开网页就显示不了"时给出跨设备建议（装 Noto 字体）。

二者逻辑衔接：目的1 的"整条栈能否显示"检测结果 + 离线 JSON 查 Noto = 目的2 的四象限，不额外测量。

## 技术方案

### 1. 渲染字体栈（目的1 核心）

- **组成**：`sans-serif`（**系统默认优先**，置于栈首触发系统回退链）+ 用户本机字体（动态枚举，居中介入）+ 内嵌 Noto Sans Symbols 2（**栈尾兜底**，补系统+用户都没有的符号）。
- **关键（实测修正）**：**不手动排列系统内置字体**（Segoe UI Symbol/Emoji/Historic 等）——它们已在系统回退链中且顺序正确（emoji 彩色、汉字、符号、历史文字）。显式排序会打乱：实测 `Segoe UI Symbol` 排在 `Segoe UI Emoji` 前 → emoji 变黑白。系统默认优先由 `sans-serif` 置于栈首实现。
- 实测验证：`sans-serif, "Noto Sans Symbols 2"` 栈下，emoji 彩色（173 色相桶）、符号/汉字/楔形正常、**系统没有但 Noto 有的字符**（如 U+10140）由 Noto 兜底显示（非豆腐块）。
- **动态枚举**：queryLocalFonts 授权后，用户字体列表（去重、排序）插入 `sans-serif` 与 Noto 之间（排序后 Segoe UI Emoji 自然在 Symbol 前，重复列出无害）。
- **降级**：未授权时用 `FALLBACK_SYMBOL_FONTS` 静态列表置于中间。
- **授权时机**：字体选择器区域首次交互触发授权；成功后重建栈（检测用空栈与字体列表无关，无需重测）。
- **CSS/JS 一致性**：JS 维护字体栈字符串，通过 CSS 变量 `--sym-font-stack` 注入根元素；所有符号渲染位置用 `font-family: var(--sym-font-stack)`。

### 2. 检测方法（豆腐块模板比对 + 双向白名单）

实测淘汰的前代方法：宽度法（"栈内字体与 sans-serif 同宽"信息不可判定，汉字/☺ 误判）；FontFace API（`document.fonts.load/check` 在 Chrome **不做字形检查**，只做字族匹配）。

**原理**：浏览器有**隐式系统字体回退**——渲染栈字体都不含某字符时，仍会自动用系统里能支持的字体（如 Segoe UI Historic 渲染楔形文字）。最终渲染出"真实字形"还是".notdef 豆腐块"，取决于系统默认回退链是否有该字符。

**豆腐块模板比对**（一步检测最终渲染结果）：
- **生成模板**：用空栈（`"__nonexistent__", serif`）渲染私有区 U+E000，得到"当前环境的 .notdef 豆腐块"像素模板（任何系统字体都不含私有区字形，必画豆腐块）
- **判定**：字符用**同一空栈**渲染，与模板**逐像素比对**：
  - 相同 → 系统默认画的是豆腐块 → **当前字体不支持**
  - 不同 → 系统默认画的是真实字形（如楔形文字由 Historic 渲染）→ **能渲染**
- **模板一致性校验**：用多个私有区字符（U+E000/F8FF/10FFFD）渲染比对，若不一致（用户装了私有字体）→ 禁用豆腐块检测，保守全判能渲染

**三层判定**（白名单外才走 canvas，零检测成本兜底）：
1. **正向白名单**（肯定能渲染）：Noto 覆盖（noto-cmap.json）+ 系统必含老区块（ASCII/Latin/希腊/西里尔/符号/几何/箭头/基本 CJK/谚文/emoji/全角等）→ 直接判能渲染
2. **反向白名单**（肯定豆腐块）：私有区（E000-F8FF、F0000-FFFFD、100000-10FFFD）+ Unicode 未分配码位 → 直接判不支持（替代显示）
3. **模板比对**（其余）：空栈渲染 + 与豆腐块模板逐像素比对

**异步预计算**：选中标签/翻页后对当前可见字符批量发起检测，结果缓存 `Map<字符, bool>`；模板查缓存（同步），未完成前默认能渲染。

**与目的2 复用**：模板比对用空栈（不含 Noto）→ `checkRenderable` 判的即"**本机能否渲染**"，正是目的2 四象限的"本机含"。

### 3. 离线 noto-cmap.json（目的2 数据）

- **工具链**：新脚本 `符号/build_noto_cmap.py`，用 Python `fontTools` 读 `lib/fonts/NotoSansSymbols2-Regular.ttf` 的 cmap，生成 `符号/noto-cmap.json`（码位区间列表，几 KB）。
- **网页不依赖工具，只依赖 JSON**；字体文件升级时才重跑。
- 一次性 `pip install fonttools`，符合现有纯 Python 工具链惯例（8 个 build_*.py）。

### 4. 替代显示（判定"当前字体不支持"时）

| 位置 | 显示 |
|---|---|
| 网格卡片字形区 | 置灰小字 `U+1F44D`（放不下省略），名字行保留 |
| 网格卡片 title | 追加 `（当前字体不支持）` |
| 详情大预览 | 置灰 `U+XXXX` + 名字行下方黄色提示条「当前字体不支持」 |
| 效果预览 | 置灰 `U+XXXX`（不参与对齐参考） |

复制、所属标签、搜索全部不受影响（复制的是字符本体）。

### 5. 目的2 四象限提示（详情区）

复用目的1 检测 + 查 noto-cmap.json：

| 内嵌 Noto | 本机字体 | 提示 |
|---|---|---|
| 含 | 含 | 无需提示 |
| 含 | 不含 | 「此字符需 Noto Sans Symbols 2 字体，装它才能在别处显示」 |
| 不含 | 含 | v1 不提示（要报具体字体名需逐字体枚举，v1 不做） |
| 不含 | 不含 | 真豆腐块 → 替代显示 + 「设备无此字形」 |

判定：`notoHas` 查 noto-cmap.json（离线精确）；`本机含` = `checkRenderable(cp)`（豆腐块模板比对，空栈不含 Noto，判系统默认能否渲染）。只对详情区选中的单个字符检测。

## 数据流

```
fontTools → noto-cmap.json ─┐
                            ├─→ 详情区四象限提示
目的1 整条栈检测（canRender）─┘
          │
          ├─→ 能显示 → 正常渲染
          └─→ 不能显示 → 替代显示置灰码点 + 提示
```

## 性能

- 正/反向白名单内的字符零检测成本（直接判能渲染/不支持）——覆盖绝大多数标签。
- 白名单外的字符走模板比对：每字符 1 次空栈渲染（72px）+ 逐像素比对，异步分批预计算；结果缓存 `Map<字符, bool>`，翻页只算新字符。
- 豆腐块模板只生成一次（mounted + `document.fonts.ready` 后）。
- 触发时机：`document.fonts.ready` 后 + 选中标签/翻页后增量预计算。

## 边界与已知局限

- 正向白名单"系统必含"是保守假设：极端设备（无中文字体的嵌入式系统等）可能白名单内字符渲染失败且不替代 → 保持方块，可接受的降级（不误判）。
- 反向白名单只放"肯定豆腐块"（私有区/未分配码位）；西夏文等"大概率没有"的走模板比对，由系统实测判定（避免误判装了字体的用户）。
- 模板比对逐像素相等 → 判豆腐块："真实字形恰好等于 .notdef"几乎不可能；漏判（不同缺字形字符 .notdef 不同）实测低（私有区/西夏文/U+10FFFD 的 .notdef 与模板一致，系统 last-resort 统一）。
- 模板生成失败（用户装了私有字体致多私有区渲染不一致）→ 禁用检测，保守全判能渲染。
- 检测完成前默认"能渲染"（避免闪烁）。
- 双模字符测基础字形（变体选择符不影响字形命中）。

## 不做的事（YAGNI）

- 不内嵌全量 Unicode 字体（几十 MB，不现实）。
- 不做网格级 Noto 覆盖标注（离线 JSON 只在选中字符时用）。
- 不引入 JS 字体解析库（fontkit/opentype.js，需 npm，无 node 环境）。
- 不动 `lib/` 下任何文件。
