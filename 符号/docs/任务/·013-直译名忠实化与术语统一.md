# ·013 直译名忠实化与术语统一

日期：2026-09-18

## 一、定的规矩（这几条是本次的产出，以后照这个办）

### 1. 两层各司其职

**直译名 = 对 Unicode 官方英文名的忠实直译**，官方名再挫也照搬。
**优化过的通用叫法放富化层主名。**

判据是「官方名里的词，直译里有没有对应」，不是「读着别不别扭」。
「读着别扭」不是改直译的理由——那是在拿症状当病灶。

### 2. 别名的存废

判据是「**这个说法值不值得留**」，不是「搜索面能不能更大」。

- 留：旧名**用字形顶替了长串**（`à` 的旧名 `a带钝音符` 顶替了「拉丁小写字母A」）
- 不留：多出来的只是**不承载信息的成分**——背景词（`伸出舌头的脸` 里的「脸」）、虚词（`带`）、空格（`@ 符号`）、挫名（`O带低圆圈内部`）
- 不留：**断言了标准没规定的东西**（`O带斜线`——`STROKE` 不规定方向，字体设计者可以画成横/竖/斜，写死方向就是加意思）

⚠️ 判据不是「打旧名搜不到就补」——那样会把一堆挫名灌进别名（直译名里一大半是挫名）。

### 3. 承载词当背景

表情/手势类 emoji，**人体部位只是承载动作的背景**，人的关注点在动作上。
直译名保留它（忠实），**富化主名去掉它**：

```
😛  直译 伸出舌头的脸      主名 吐舌
🖖  直译 中指和无名指分开的举起的手   主名 瓦肯举手礼
🫰  直译 食指和拇指交叉的手         主名 比心
```

⚠️ **「的人」不属于这一类**（用户 2026-09-18 明确）——不要顺着推广。

### 4. 重量刻度

`THIN 极细 / LIGHT 细 / MEDIUM 中粗 / BOLD 粗 / VERY BOLD 特粗 / HEAVY 重 / VERY HEAVY 特重 / EXTREMELY HEAVY 极重`

两族各按字面（粗体族走「粗」，stroke 族走「重」），合成一条单调梯子。
**制表线例外**：直译保留「重」（`┃ 重竖线`），富化主名给通用叫法「粗」（`粗竖线`）。

### 5. 术语

**禁用「名字表」**（旧合称，把两份数据混成一个概念，「名字」什么都没指）。
改说 `官方名直译名.js` → **直译名**、`unicode官方名.js` → **官方英文名**。
要指两个就直接写「官方英文名 + 直译名」，**不另造统称词**。

## 二、引擎改动（`build_zh_translation.py`）

| 缺口 | 内容 |
|---|---|
| 修饰符词表 | `WITH`/`GRAVE`/`STROKE`/`HOOK`… 及长尾 160+ 词 |
| 倒序短语表 `STRUCT_PHRASE` | `RING ABOVE`→上方圆圈（英文后置、中文前置，逐词拼会反） |
| 字形对照 | 希腊字母名→字形（`LAMBDA`→Λ），**一律按官方名用大写** |
| 单 token 连字符键 | `OPEN-O`/`REVERSED-SCHWA` 必须放 `STRUCT_MAP`——`_rest_zh` 只在 n>1 时查短语表 |
| 空格 | 中英文之间不空格（`@符号` 不是 `@ 符号`） |

**验收指标**：`letter_zh(官方英文名)` 的输出 == 直译名里的值。

这 703 条原本**谁都复现不出来**——一次全量重算会把它们变成「拉丁大写字母A WITH GRAVE」这种半英文。
现在 **1117 / 1117（100%）**，重算逐字一致。

## 四、验过什么

- `datatool.py` 体检 + `check_group_keys.py` 可达性：通过
- 页面显示名：抽样 60+ 个，全对
- 页面搜索：12 条查询逐条核对输入框值后验证——新名、旧别名、直译名三条通道都通
- ⚠️ **直译名被主名盖住时仍可搜到**（搜索走直译名通道），只是详情区不显示。
  所以「直译名进别名」要解决的只是**显示**问题，优先级不高

## 五、验页面的两个手法

1. **先删遮挡 DOM**（语义标签树很长，`innerText` 会被它占满）
2. **搜索用真 UI 输入**：`fill('')` 在 Element Plus 上不可靠，要点进去全选删；
   另外首次访问会弹「页面说明」弹窗盖住搜索框

详见项目记忆 `symbol-page-verify-tips`。
