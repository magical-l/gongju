## 0. 一句话

把《太玄经》那 10 个符号的名字定死（九州 9 个统一成「九州·xx」、八十一首加「首」去繁、
单/双/四爻三档家族配齐），顺带查出并修掉一个藏了很久的**渲染错误**——`Segoe UI Symbol`
给这一段画的是 Unicode 早期提案的错版字形；再给编辑弹窗加了「直译名」的显示与修改。

## 1. 考证：这些符号到底谁是谁

起因是用户问「九州 9 个该叫什么」。**第一轮我把人带沟里了**——拿一份搜索摘要当证据，
还把 Unicode 的「叫法」转述成了「映射」，自相矛盾。用户当场否掉，要求看原始材料。

### 1.1 三份原始文件（都下到 `tmp/` 逐页核过）

| 文件 | 是什么 | 地址 |
|---|---|---|
| N2416 | 2002 年收录提案（Cook / Everson / Nylan） | `unicode.org/wg2/docs/n2416.pdf` |
| N2988 | 川幡太一：要求更正字符名 | `unicode.org/L2/L2005/05260-n2988-tai-xuan-jing.pdf` |
| N2998R | 日本：Annex P 注解（更正后逐条对应） | `unicode.org/L2/L2005/05281-n2998.pdf` |
| 官方码表 | U+1D300 区块 / 四象所在区块 | `unicode.org/charts/PDF/U1D300.pdf`、`U2600.pdf` |

### 1.2 结论（五条，逐条有出处）

1. **字形 → 三才**：一笔 = 天、二笔 = 地、三笔（三短横）= 人。
   出处：N2988 引《太玄·玄告》「一摸而得乎天、再摸而得乎地、三摸而得乎人」。
2. **Unicode 官方名叫反了**：它把「二笔」命名为 `HUMAN`、「三笔」命名为 `EARTH`
   （N2998R 原文：*tian for heaven, di for human, and ren for earth*）。
   **叫反的是名字，字形本身没错。**
3. **名字先写上面那一爻**。N2998R 逐条给出更正：
   `U+1D300 人`、`1D301 天人`、`1D302 地人`、`1D303 人天`、`1D304 人地`、`1D305 人人`。
   用官方码表字形逐格放大核过（1D301 = 上长横 + 下三短横，1D302 = 上二 + 下三，依此类推）。
4. **八十一首自上而下读「方州部家」**。不止码表——N2416 附录印了**晋代范望本刻本书影**，
   周首（一方一州一部二家）画成 4 行「实/实/实/断」、旁注坐标文字，第四行（家）断成两截。
   两份原始材料互证，所以**现有坐标是对的，没动**。
5. **叠字**：提案的中文首名用「双」标叠 —— `shuāngtiān`(双天) / `shuāngrén`(双人) /
   `shuāngdì`(双地)；**英文那边反而省成一个词**（`DIGRAM FOR HEAVEN` / `HUMAN` / `EARTH`）。
   所以「英文不叠字 → 中文也不该叠」推不出来。

### 1.3 双符对照表（本案的核心结论）

| 码位 | 官方英文名 | 官方码表字形（上→下） | 更正后 |
|---|---|---|---|
| U+1D300 | MONOGRAM FOR EARTH | 三短横 | **人** |
| U+1D301 | DIGRAM FOR HEAVENLY EARTH | 一长横 + 三短横 | **天人** |
| U+1D302 | DIGRAM FOR HUMAN EARTH | 二 + 三 | **地人** |
| U+1D303 | DIGRAM FOR EARTHLY HEAVEN | 三 + 一长横 | **人天** |
| U+1D304 | DIGRAM FOR EARTHLY HUMAN | 三 + 二 | **人地** |
| U+1D305 | DIGRAM FOR EARTH | 三 + 三 | **人人** |

## 2. 命名裁定

**两层两套词，别混**（用户明确纠正过一次）：

- **直译名**（`官方名直译名.js`）：忠实官方英文名，**错的也照搬**。MONOGRAM/DIGRAM/TETRAGRAM
  → **单爻 / 双爻 / 四爻**，属「爻系」——这是直译，不是我们命名。
- **富化层**（全局主名 / 语境名 / 别名）：**我们命名**，用「玄方州部家」那套（三方 / 九州 / 八十一家）。

| 层 | 值 |
|---|---|
| 直译名 · 单符 | `单爻·地`（𝌀；用户改的，比我的 `单爻·人` 更合「直译保留错说法」的口径） |
| 直译名 · 双符 | `双爻·天地` / `人地` / `地天` / `地人` / `地地`（保留 Unicode 错说法，只作搜索键） |
| 直译名 · 八十一首 | `四爻·中` / `四爻·周` …（**2026-09-20 新加的前缀**，此前只有裸首名） |
| 富化层 · 九州 9 个 | ⚌ 双天、⚍ 地天、⚎ 天地、⚏ 双地、𝌁 天人、𝌂 地人、𝌃 人天、𝌄 人地、𝌅 **双人** |
| 富化层 · 八十一首 | `一方一州一部一家·中首` …（尾部加「首」，去繁体） |

八十一首去繁实际 **32 条**：31 条「甲/乙」双写取简 + 无斜杠但整字繁体的 `裝→装`。
`四爻` 前缀的好处：搜「四爻」一次出全 81 个（子串匹配，短查询「中」不受影响）。

## 3. 字体错版：症状、根因、改法

### 3.1 根因

N2988 里有一句原文：

> *Note that N2416 mistakenly swaps the glyphs for U+1D301, U+1D302 and U+1D303 in page 21,
> but this has been corrected in Amendment 1.*

实测 `Segoe UI Symbol`（本机唯一覆盖该区段的系统字体）正是**没跟 Amendment 1 的那版**：

| 码位 | 官方码表 / Noto | Segoe UI Symbol |
|---|---|---|
| U+1D301 | 一长横 + 三短横 | **U+1D303 的字形** |
| U+1D302 | 二 + 三 | **U+1D301 的字形** |
| U+1D303 | 三 + 一长横 | **U+1D302 的字形** |

（U+1D304 / 1D305 两边一致。）

### 3.2 我在这上面翻过两次车

1. 先写成「Segoe **画反上下爻**」——不准确，是**三个码位互相错位**，不是简单翻转。
2. 接着把「字形以本页（与官方码表一致）为准」写进了简介——**用户指出本页自己也是错版**：
   当时字体栈里 `"Segoe UI Symbol"` 排在自带 `"Noto Sans Symbols 2"` **前面**，
   浏览器逐字回退先取到 Segoe。简介先后改了两版，最后一版才与事实对齐。

### 3.3 改法：字体栈改序

`Arial → Segoe UI Emoji → Noto Sans Symbols 2 → Segoe UI Symbol → Consolas`（去掉 Lucida），
`?v=` 同日改两次故用 `260920b`（项目里有 `?v=0229b` 先例）。改动落三处：
`符号.js` 的 `FALLBACK_SYMBOL_FONTS` + `buildFontStack`（去重）+ `initFontList`（去重）、
`符号.css:11` 的兜底栈（两边必须同步）。

**顺序只在「多个字体都覆盖同一个码位」时才起作用**，本题三个数：

- Noto ∩ Segoe UI Symbol = **2,169** 个码位 ← 现在改由 Noto 渲染（换栈的影响面）
- Noto ∩ Segoe UI Emoji = **715**，其中 emoji 区 **267** 个（🌍 🌕 一类）← 所以 Noto **不能**再往前放
- **Arial 必须留第一位**：它不含 emoji 字形，`☺ ♥ ▪ ©` 这类**双模字符**因此保持单色
  （把 emoji 放第一，这些会变彩色——已出对比图实测）

验证：页面计算出的栈渲染 U+1D301 = 笔画分布 `[1,3]`，与 Noto 参考一致；单用 Segoe 是 `[3,1]`。

### 3.4 顺带澄清的一件事

豆腐块检测**不受显示栈顺序影响**——它走另一条路（canvas + 硬编码的
`"__nonexistent__", serif` 栈，**故意不含自带 Noto**），代码里叫 `LOCAL_CACHE`
「本机渲染能力（不含 Noto）」，回答的是「复制到别处还看不看得见」。

## 4. 编辑弹窗新增「直译名」

### 4.1 缺口

`dev_server.py` 的 `sym_save` 里 `if entry:` **提前 return**，于是「已有富化条目的字符」
（比如这 5 个双爻）的直译名在界面上**根本改不了**。

### 4.2 改动（4 个文件）

| 文件 | 改什么 |
|---|---|
| `符号.html` | symbol 分支最上面加独立一块「直译名」+ 一行提示；序列时 `disabled` |
| `符号.js` | 新增 `rawZhNameOf`（**只查 `names`，不扫 patterns**）、状态、脏判断、`payload.zh`、内存同步 |
| `符号.css` | 新增 `.meta-editor-dialog .me-hint`（输入框下那行小字） |
| `dev_server.py` | `sym_save` 支持 `zh`（校验**前置**）、`zhname_set` 空值**删键**、空壳条目**删行** |

### 4.3 三个要害

1. **初值必须取原始值**：`lookupZhName` 未命中时会扫 `patterns` 返回**前缀**，
   拿它当初值一保存就把前缀固化成了条目。
2. **清空 = 删键**（回落 patterns / 官方英文名），**不写空名**——空名是静默的数据损坏。
3. **两个框打架**（用户裁定「拆开，各管各的」）：从前对「没有富化条目的字符」，
   全局主名会**退而写进直译名**，于是弹窗里两个框指向同一处存储——一个空一个有值，
   而且清空主名走不通（快照恒为空 → 判不出脏）。现在全局主名一律走富化层（没有条目就新建），
   旧路只留给外部脚本。
4. **空壳条目自动删行**：把主名/别名/各组/简介全清空后条目会只剩 `char`，
   那正是 `check_all` ④ 判的垃圾 → 前后端一起把它删掉（含一个只在删**末条**时才走到的
   尾逗号补正 `_fix_last_entry_comma`——走错会把文件写成非法 JS、页面白屏）。

## 5. 别名

- **删**：四象那 4 条 `MONOGRAM FOR GREATER YANG` 等——官方名其实是 `DIGRAM FOR …`
  （U+268A/B 才叫 MONOGRAM FOR YANG/YIN），这 4 条是**打错的字符串**，不对应任何真实名。
- **加**：按更正读法给英文名，**挂在「九州」/「三方」组下**（用户裁定用语境别名，
  接受「搜得到、但在别的标签下看不见」这个后果）：
  ⚌ `DIGRAM FOR HEAVEN`、⚍ `EARTHLY HEAVEN`、⚎ `HEAVENLY EARTH`、⚏ `EARTH`、
  𝌁𝌂𝌃𝌄𝌅 `DIGRAM FOR HEAVENLY HUMAN / EARTHLY HUMAN / HUMAN HEAVEN / HUMAN EARTH / HUMAN`、
  三方 ⚊ `MONOGRAM FOR HEAVEN`、⚋ `MONOGRAM FOR EARTH`、𝌀 `MONOGRAM FOR HUMAN`。
  **撞官方名不回避**——用户裁定：「撞名不要怕，这是正确的，那个官方名才是错的」。
- **我误判过一次**：𝌯 那 6 条 `Tetragram for Meeting`，我以为是官方名的大小写变体（零贡献），
  实际官方名是 `TETRAGRAM FOR GOING TO MEET`——那 6 条是 **Nylan 译本的英文首名**
  （直译名用疏/童/毅那一套的英文原版），是**同义词不是重复**，留着。
- **真该删的是另一批**：按正确判据重扫全库，抓到 4 条官方名的小写变体
  （`keyboard` / `printer` / `lozenge` / `interrobang`，查询侧本来就折小写 → 零贡献）。
  删完 `◊` 成空壳 → `drop_symbols` 整条移除（它的显示名本来就取自直译名「菱形」，不受影响）。

## 6. 经验教训

1. **别拿搜索摘要当原始材料。** 第一轮我引「Annex P 表格」就是从一个搜索摘要来的，
   转述还错了，被要求「拿原始文件来」。三份 PDF 下下来逐页读完，结论才对上。
2. **字体能画出字形 ≠ 画对了。** 本机 87 个太玄经码位有两个字体都覆盖，谁赢只看栈顺序。
   核字形要用 **unicode.org 官方码表**，别信系统字体——`Segoe UI Symbol` 这一版就是错的。
3. **改字体栈之前先算三个数**：和下一名的重叠（影响面）、和 emoji 的重叠（会不会把彩色抢成单色）、
   谁必须打头（`Arial` 管双模字符的单色形态）。凭「哪个字体更正确」直接往前搬会踩第二个数。
4. **「两个框指向同一处存储」是设计债**，会在弹窗里以「一个空一个有值、还清不掉」的形式冒出来。
   发现时该问「它们是不是同一处」，而不是去补回显。
5. **写进用户文案前先验证那句话本身。** 我两次把还没核实的字体事实写进简介
   （先「画反上下爻」、后「以本页为准」），两次都得回头改。
6. **术语分层要问清是哪一层**：`单爻/双爻/四爻` 是**直译名**（跟官方英文名走），
   `三方/九州/八十一家` 是**富化层**（我们命名）。我把两层混着看，报了一个不存在的「文档冲突」，
   被用户纠正。
