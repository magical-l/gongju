# CSS 风格指南（从 layout.css 提取，讨论中）

## 一、单行 vs 多行规则集

**判断标准：长度 + 语义紧密度。**

- 短 + 属性关系紧密 → 单行（与声明条数、选择器个数无直接关系）
- 长（选择器多或声明多导致）→ 自然换行，多行
- 含嵌套子规则 → 必须多行

括号内空格统一：`{ display: inline; }`（有空格），不写紧凑形式。缺空格视为 typo。

## 二、选择器策略

核心原则：**选择器结构服务于语义表达**。连接起来读得通、是一个完整意思，就连；中间某层没有独立存在的意义，就不拆成嵌套。

| 形式 | 使用场景 | 示例 |
|------|---------|------|
| 逗号合并 | 语义并列/同义，且样式相同 | `.items-x-space-between, .items-x-mutex` |
| `&` 嵌套 | 语义上下级/递进/修饰补充 | `.items-go-x { &.items-from-right {} }` |
| 链式连接 | 多个类拼接成一个完整语义，拆开则中间层语义空洞 | `:not(.grid).items-single-line` |
| 分离独立 | 语义无关的概念 | `.items-from-left` 和 `.items-go-x` 分开 |

## 三、规则集排序与分组

**排序逻辑：从大到小、从基础到派生、从常用到罕见、从通用到具体。**

以上是总体原则。具体某个 CSS 文件里各组规则依此排列。layout.css 的组序只是该文件的具体案例，并非全局固定模板。

全局可复用的点：
- 定制化的放在最后（如 layout.css 的预设布局）

**组内排序：** 先定义基础规则，再定义修饰组合。


## 四、注释风格

### 分隔标记

横线长度对应层级高低，但层级不设严格数字划分，依语义和逻辑区分即可。

```
/* ======================== 一级板块 ======================== */
/* ------ 二级子类 ------ */
```

### 块注释（描述规则意图）

```css
/*
 * 标题：这是什么
 * 适用于：xxx、xxx
 * 注：重要提醒
 */
```

### 行内注释位置

- 解释**为什么用这个属性** → 放在属性**上方**
- 解释**为什么是这个值** → 放在属性**后面**（行内）

```css
/* 适配grid子元素 */           ← why property
justify-self: start;

flex-direction: unset;/* 重置避免困惑 */  ← why value
```

当"为什么用这个属性"和"为什么用这个值"是同一件事时，选一个位置即可，不纠结。

### "已被覆盖"注释

某些类组合本应定义，但实际被已有规则覆盖、无需额外声明。在这些组合**本该在的位置**，用注释掉的代码块标注，写明为何被注释：

```css
/* 已被覆盖，无需声明
.items-go-x.items-from-left
.items-go-x.items-from-right
*/
```

若需说明被谁覆盖：`/* 已被 .items-go-x 覆盖，无需声明 */`

### 用词规范

- "适配" — 让特性在特定场景下正确工作
- "已被覆盖，无需声明" — 组合结果正确，无需额外规则
- "保持物理语义" — 轴交换但视觉效果不变
- "确保" — 语义保证
- 全中文，CSS 术语不翻译（flex、grid、gap、RTL 等）

## 五、属性简写

`place-*` 系列简写优先于拆开的 `justify-*` + `align-*`：

- `place-self: center;` 优于 `justify-self: center; align-self: center;`
- `place-content: stretch;` 优于 `align-content: stretch; justify-content: stretch;`（已执行）
- `place-items: center;` 优于 `justify-items: center; align-items: center;`（已执行）

两个轴向值相同时用简写，不同时当然拆开。

## 六、选择器对称补全

修饰组合即使"已被覆盖"，也应当显式写出注释块，保持结构对称、防止遗漏。

```css
.items-go-y {
    /* 已被覆盖，无需声明
    &.items-from-top {}
    */
    /* 显式从下到上 */
    &.items-from-bottom { ... }
}
```

而非只写活跃规则、漏掉已被覆盖的对称项。
