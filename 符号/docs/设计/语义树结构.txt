语义树结构

一棵树，两段
	前几个根是**机械轴**：文字系统 / 官方分类 / 区块 / emoji（绘文字）。它们按编码事实分组，**不作组键**。
	其后是**语义根**，按意思分组。**默认落点**是第一个语义根（打开页面时选中的那个）。

严格层级，没有多父
	一个节点只能有一个父。跨分支的概念**不靠"多父"表达**，改用这个模式：
		**两个同名节点 + 字符级双挂**——同一个字符挂进两处的同名节点。
	例：月相在天文与占星各建「月相」节点，8 个字符双挂；行星符号同理。
	这符合下面的「标签 = 关键词」哲学。

标签 = 关键词
	一个符号的含义可以来自任何文化语境，**可以挂多个标签**。
	例：扑克牌 🃢🃣 承载"未成年"牌义、🃥 承载"老年"牌义 → 挂进「人/未成年人」「人/衰老、老人」是**正确**的（表达含义，不是被当成类别），**不得移除**。
	所以看到「这个字符不该在这」时，先问：它在**这个语境下**有没有那个意思？有，就是对的。
	同理 😀 同时挂「表情、表达」+「脸」；🧝 挂「人物角色」+「神话、传说、外星人」——**是加标签，不是移走**。

	**兄弟节点之间也双挂，不是二选一**：基督教下拆出「十字架 / 东正教 / 叙利亚诸教会」后，
	`☦` 同时挂「十字架」和「东正教」，`♰♱` 同时挂「十字架」和「叙利亚诸教会」。
	判据是**两句话都真**：它是十字架 ✓，它也是东正教/叙利亚的符号 ✓——两条都成立就两条都挂。
	（2026-09-22 用户纠正：初版把这些字符在兄弟节点间**独占**分配了，是错的。）

	**按「可能落在哪一类」双挂**（2026-09-23）：钟面 `🕐–🕧` 是 **12 小时制、官方名不带 AM/PM**
	（`ONE O'CLOCK`…`TWELVE-THIRTY`）——`🕐 一点` 既能指凌晨一点、也能指下午一点，于是 `下午`
	和 `夜晚` **两边都挂**。双挂本来就是用来表达「这个字符可以指几种情况」的，
	不是「分不清所以随便放」。
	⚠️ 但挂了要付账：按这个口径 `夜晚` 会收 12 个钟面里的 10 个（19 点到次日 5 点就是半天），
	数字没错、可夜里就成了大杂烩 —— 用户当场收口成只留 `🕛十二点 / 🕧十二点半`（午夜）。
	**双挂的边界是「会不会这样用」，不是「有没有可能」。**

一个标签要能被想找它的人说出口
	判一个标签该不该存在，问一句：**想找它的人会不会把这个词说出口？**
	过得了的：「带圈的 1」「上标的 2」「A 加个方框」—— 都是人会说的话。
	过不了的：**「合字」**。它是印刷术语（ligature 的译名），日常没人这么说；
	看 `㌀` 的人想的是「方块里写着 アパート」，看 `㎏` 想的是「单位符号」，
	看 `㍿` 想的是「株式会社」——**没有一个会想到"合字"**。
	（2026-09-23：`变体符号/合字` 据此删除，305 个码位。数据也支持 ——
	其中 **303 个已有别的语义标签**能找得到，只有 2 个真靠它。）

	⚠️ **边界清不清楚是症状，"有没有人从它出发"才是病。**
	删它之前我连续两轮在「给它找一个干净的定义」（先提精简 305→222，再提一个都不错、只补 2 个缺口），
	两次都是**从现状倒推名单**，不是从定义推。定义再干净，也救不了一个没人会主动去的格子。

子标签必须是父标签的子集概念
	严格属种关系。所以「emoji」这个根**没有子标签**（"emoji" 不可再分），
	只有「emoji-text 双模」——那是"有 text/emoji 双模式的字符"，是 emoji 的**真子集**。

一个标签要收全这个领域
	判据：**想找这个领域的东西的人，在它下面能不能一次找齐**——不用去好几个标签下到处翻。
	「光学」里既要有光学的量，也要有器件（🔭🪞🔍）、现象（🌈）、光源（💡🕯🔦🏮🪔）；
	太阳虽是天体、家在「自然/星星」，光学里也该有一份。
	⚠️ **「收全」不是「沾边就收」**。先问"它原本属于谁"，再问"它能不能进这里"——
	为填满一个节点做**外围搜刮**，是把字符从更好的归宿里捡走
	（·019 的教训：为填「风水堪舆/道教」把 📿念珠 🪷莲花 捡进道教，却没看一眼佛教当时
	连念珠、莲花座都没有）。边界是**这个字符本身就是这个领域的**，不是"跟这个领域沾过边"。
	反例：📸闪光灯（摄影）、🔅亮度符号（UI）、🌅日出（景观）、🪟窗（建筑）都不进「光学」。

	⚠️ **「收全」是在"这个领域内"收全，不是把同名不同领域的东西拉进来。**
	`数学/括号、定界符` 只收数学里用的括号（`⟦⟧⟨⟩` 一系）；`〈《(⁅『` 是标点括号，
	归 `语言、文字/标点符号`，**不进数学** —— 进去不是"自足"，是多余。
	（2026-09-24 用户定）

	**方向性：宽域收全，窄域不收。** 判"该不该挂"前，先看**收方**是哪种域：
	· **宽域**（按"这东西是什么"分，如 `数学/几何/方形`）—— 该收全所有叫这个名字的形状，
	  哪怕它们另有用途或另有老家。所以 `▀▄█` 这些**制表符块元素**也加挂进了 `方形`。
	· **窄域**（按"这东西干什么用"分，如 `技术符号/制表符/方块`）—— 只收本用途的，
	  不因为"名字也叫方块"就把几何的 `□▢▣` 拉进来。
	两者名字撞了（都叫"方块"），但**该挂的方向只有一个**，不是互相挂。
	（2026-09-24 用户定 E 项时确立）

按「形」的正交根（箭头 / 装饰、花纹）
	有两个根**故意不按语义收**，按的是一个**正交的外观轴**——字符可以同时在别处有正经家，
	这是设计使然，不是"挂错了"。写法照「箭头」根：intro 里一句话说清"按形找从这里进"。
	· 「箭头」——官方名含 ARROW 的箭头/箭头帽字符。619 个，无子节点。
	· 「装饰、花纹」——有人会拿去当装饰花纹用的图形。263 个，无子节点。

	判据问的是「**有没有更近的路**」，不是「它是不是这个意思」：
	  想找它的人会不会直奔某个现成节点？（要个方块 → 数学/几何/方形；要箭头 → 箭头根）
	  会 → **不收**；不会（不知道有这东西，或知道想要却不知道去哪找）→ **收**。
	分界不在"有没有语义"——十字架语义极强、但有人戴它当项链；对勾语义很弱、却没人拿它当花纹。
	**分界在"语义是不是功能性的"**。

	⚠️ **别问「它算不算花纹」**（2026-09-24 实测）：这问题的答案是"算"——
	铺开预览一做，几乎什么都好看，连高棉数字符 `᧠` 都排得整整齐齐。
	所以收的标准只能是**排除**，三条：
	  ① **显示不出来**（本机无字体，渲染成方框）——机器可判
	  ② **在"说事"**（货币符、日期标记、数字符、问号叹号这类功能符号）——多半可判
	  ③ **排开扎眼**（把字符横向排 8 次看着乱）——**只有眼睛能判**
	⚠️ **单个字符看不出价值**（竖线 `།` 就是根竖线），**排成一排才是它作为花纹的样子**
	（`།` 排一排 = 竖条纹）。这跟"按最小重复部分看复杂度"是同一件事：
	有对称结构的按单元算（`✿` 八瓣 → 一瓣），无对称的整个算（`༄` 藏文旋涡 → 一团卷线，眼花）。

	收完它会有几百个成员、跟「自然/植物」「数学/几何」大面积重合——**这是设计使然，不是数据脏了**。

	**正交根也可以分子节点，按「两个正交的轴」挂。**（2026-09-25 给「装饰、花纹」立，别处要
	分子节点时可照这个套路）：
		· **身份轴**（它是什么）：`文字纹`——来自具体文字系统，或字形本身就是「字」
		· **形状轴**（它长什么样）：圆形纹 / 方形纹 / 三角纹 / 线形纹 / 波浪纹 / 云纹 / 点状纹 /
		  星形纹 / 植物纹 / 动物纹 / 人形纹 / 心形纹 / 交叉纹 / 网格纹
	**一个字符两个轴都挂**，形状类之间也不互斥——这正是「标签 = 关键词」该有的样子
	（`།` 同时是「文字纹」和「线形纹」；`✢` 同时是「星形纹」和「交叉纹」）。
	⚠️ **别把子节点当分类**——它们不是互斥的抽屉，是可以叠加的标签。

	⚠️ **判据要挑「看一眼就答得出」的。** 这轮的教训：先试「能不能当花纹用」，**卡死**——
	那要想象使用场景，而想象是可塑的（"说不定有人用呢"），几乎什么都过关。
	换成「**主体是什么形状**」就成了纯描述题，不用想象任何场景。

	⚠️ **判形状看「单字符」，不看「重复排」。** 曾想用「重复起来围不围出格子」判网格纹，
	但**任何交叉重复起来都会形成格子**（`✕✕✕✕` 也是）——判据作废。
	正解是**单字符内部有没有**：`🙨` 一个方块里自带网眼 → 网格纹；`✕` 自己没格子 → 交叉纹。
	（"重复排"仍是**给人看**的好办法——单个竖线 `།` 看不出价值，排一排就是竖条纹。
	它适合判"好不好看"，不适合判"是什么形状"。）

	⚠️ **别拿数据字段当结论。** `A8FA` 的通用类别写着 `Po`（标点），但它是**天城文脱字符**，
	实际不占宽度、叠在前一个字上——**渲染环境里实测一次，胜过查十个字段**。

别名不只是别名
	它还收纳「太小 / 琐碎 / 边界模糊」的子级概念。例：「娱乐场地和表演」的别名里有「马戏团」「杂耍」——
	它们不够格单独成节点，但得能被搜到。

人物角色 = 人在特定角色的行为或装扮中
	判断标准：**能不能给这个人一个可称呼的身份**。
	职业 = 身份、运动员 = 身份、新娘 = 身份；下跪者 / 站立者 / 桑拿者 = **没有身份**，不是人物角色。
	配套：**通用人** = 无属性的中性人（站 / 跪这类中性姿态归「人」根本级）；未成年 / 老人 = 人生阶段；
	**性别与年龄正交分开**，不合成一个维度。

拆分按「意思」，不按「来源」
	反例（按来源拆，错）：数学/数学符号 当初按 Unicode 官方分类 Sm 批量扫入，但 **Sm 是"编码层"分类，不等于"语义上有数学用途"**——里面大量是 STIX / Elsevier 出版社的字形抢救品，只有字形价值，没有数学义。
	正解（按意思拆）：从数学符号里分出子节点「**备用字形**」，判据 = **属于 Unicode 数学区(Sm) + 无活跃数学用途**。
	命名也按意思：叫「备用字形」不叫「备用数学符号」（后者会被读成"次要的数学符号"）。

	同一条原则也管语境名的判重：看**意思**不看字。
	「男人划船」（水上运动里的这件事）与「划船男人」（运动的人里的这个人）是两个正交的轴，**两条都留**，拼接名拼成「男人划船、划船男人」是期望行为。

往一个节点里捡字符时
	**先问"它原本属于谁"，再问"它能不能进这里"。** 只问后者，就会把它从一个更好的归宿里"捡走"。
	（2026-09-23 实证：·019 为填满「风水堪舆 / 道教」做了一轮**外围搜刮**，把 `📿念珠` `🪷莲花`
	`🕯蜡烛` 捡进道教，**却没看一眼佛教** —— 佛教当时只有 8 个，连念珠、莲花座都没有。
	不是判断错，是**没进入判断**：任务轴钉死在易经/风水/道教上。）

	**通用物不构成任何一家的特征。** 判据是问一句：
	**这个字符在同类的其他节点里是否同样成立？** 成立 → 别挂。
	`🕯蜡烛` 基督/佛/道三家都点 → 挂哪一家都不说明什么，只会让那个节点变脏；
	`🪷莲花`「坐莲」的恰恰是佛菩萨、莲花座是佛教核心 → 归佛教；
	`📿念珠` 道教全真派确有「流珠」→ 可以双挂。

根的顺序
	机械轴恒在最前，语义根其后。根级排序只在**非机械轴根之间**做（页面树节点 hover 显示 ▲▼）。
	改根顺序会**改变默认落点**，不是纯显示问题。

改这棵树时的注意
	改标签名要**同步组键**，否则语境名静默回退到兜底链、不报错。页面改有兜底（dev_server.py 自动同步），**手工改数据文件没有**。
	删节点前先确认没有字符只挂在那里。
	标签树的成员归属是**唯一权威**——直译名只提供兜底名，不决定归属。
