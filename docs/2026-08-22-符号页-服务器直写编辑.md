## 设计决策

- **保存接口**（页面→服务器，POST `/symbol-api/save`，成功 `{"ok":true,"message"}`）：
  - `add` / `move`：成员移动/添加 → `标签.json`（复用 apply_ops 逻辑，不影响 `标签.txt`）
  - `tag`：改名（children key 换）/ 别名（alias 整体替换）→ `标签.json` + **同步 `标签.txt`**（tab 缩进行重写，保留 pending 挂起标记）
  - `sym`：`entry` 提供 → 写 `符号数据.js`（页面已路由好）；`name` 提供 → 写 `中文名.json`（仅非 SYMBOLS 字符改名）
- **符号改名路由**（页面判断）：字符在 SYMBOLS → 页面改好 entry 整体发；不在且只改名 → 发 name 写 `中文名.json`；不在但要加别名 → 新建最小条目（组键=字符首个标签名）发 entry。
- **API 路径用纯 ASCII**（`/symbol-api/...`）：`http.server` 的 `self.path` 是请求行按 latin-1 解码的，中文路径（/符号/...）变乱码，字符串比较必失败。这是本功能踩的最深坑。
- **端口探测用 connect 而非 bind**：Windows 允许 127.0.0.1 与 0.0.0.0 双绑定同一端口，bind 探测会把被 VS Code Node 服务占的 52331 误判为空闲，导致绑定后连接被 0.0.0.0 抢占、实际不可达。
- **数据文件写回保留原换行**（`_read_lines` 检测 CRLF/LF），git diff 干净（小编辑不产生全文件噪音）。
- **页面先发服务器→成功才改内存**：移动/添加沿用 applyOp；`saveSymbolMeta` 因 entry 需在发请求前改好，失败用 JSON 快照回滚（已有条目还原、新建条目移除）。
- **左树刷新用 `treeVersion` 反应式计数**：TAGS.roots 是模块级非响应式变量，treeRoots computed 会缓存，改名/增删后直接改对象不触发重渲染——bump 计数强制重算。顺带修复了「左树计数不随内存改动刷新」的旧遗留。
- **旗序列符号 ✎ 隐藏**：旗序列（双码位）改名若走 name 路由会改写首码位的 `中文名.json`（如区域指示符），属数据破坏；entry 路由会造无意义双码位条目。
- **ops 面板保留**（用户明确：先留着不碍事）：移动/添加仍 push 记录，成为被动日志；apply_ops.py 不再参与页面流程但保留文件。
