## 0. 起点：112 个的杂物抽屉

「装饰、花纹」是第 28 个语义根，112 个成员、**无子节点**、`src: draft`（最早草稿树留下的，从没整理过）。
别名挂着「纹章、纹样、花样、徽章」——四个词没有一个能覆盖里面装的东西。

查下去发现：Unicode 那个叫「印刷装饰符号」(Dingbats, U+2700–27BF) 的区块里**六成不是装饰**
（✂剪刀 ✈飞机 ✉信封 ✊拳头 ❤心形 ❶带圈数字 ➔箭头 ➕加号）。而这个根收的，恰是其中被手工挑出的中间段——
**它一直在做"挑出真装饰"这件事，只是判据从没写下来过**。

## 1. 判据的确立：四轮反复，前三轮全被推翻

### ① 用户最初的提议：按「是否对称 / 有没有方向性 / 是否可以无缝重复」分 —— **否**

三条理由，各自独立成立：
- **说得出？** 官方名里根本没有"对称性""可平铺"这两个概念（没有一条名字含 SYMMETRIC），得靠肉眼判，且判起来模糊（`✳` 是旋转对称还是镜像对称？）
- **方向性说得出口，但信息已经在名字里**：`朝西北叶子`、`旋转朝西南`、`朝左火箭` 全是官方名原文，搜"朝左"直接出，再聚一个节点是把名字抄第二遍
- **结构上就不可能**：三维度互相交叉（`🙾` 棋盘格 = 对称 + 无方向 + 可铺满），而这个树「严格层级，没有多父」

### ② 我提「两条硬线」（不收具象图像 / 不收功能符号）—— **被更好的判据取代**

用户换了立足点：**「有没有人会拿它去当装饰花纹用」**——从字符出发改成**从用户出发**。
但这条判据**天生不封顶**（⭐☀♥⚡ 做设计的什么都往版面上铺），于是补上关键的第二句：

> **收那些「用户可能想不到有这么一个符号」，或者「能想到但很难通过其他途径找到」的符号。**

**判据落在「有没有更近的路」，不在「它有没有语义」。**
十字架有极强语义，但有人戴它当项链；对勾语义很弱，却没人拿它当花纹——**分界不在有没有语义，在语义是不是功能性的**。

### ③ 我主张「几何类全收」—— **被用户当场推翻**

按「有人会用」推下去，`■●▲◆◇░▒▓` 全该进，装饰根会涨到 472。用户一句点破：

> 要排除掉非常明显、众所周知的那些，因为那些符号，用户可以通过另外的途径得到，比如几何形状、箭头这些。

**这一句同时判掉了两件事**：几何类不该收（「数学/几何」是更近的路），`꧁꧂` 该收（它埋在「语言、文字/标点符号」下，想找花纹的人翻不到）。

### ④ 用户再进一步：**「太复杂的图案铺开来会眼花」，且「对称/有规律的图案要按最小重复部分看复杂度」**

**这是最终判据的成型。** 它把我前面否掉的"对称性"救回来了——**不是当分类格子，是当"铺开会花眼吗"的判据**：

| 字符 | 对称结构 | 最小重复单元 | 铺开 |
|---|---|---|---|
| `✿` 八瓣花 | 8 重旋转 | 1 个花瓣 | 清爽 |
| `❅` 三叶雪花 | 3 重旋转 | 1 个叶瓣 | 清爽 |
| `༄` 藏文旋涡 | **无对称** | **整个字符** | 眼花 |

**落成一句话**：装饰根 = **正交字形轴**（跟「箭头」根同构），
判据 = **铺开后不花眼**，而"不花眼"来自**最小重复单元简单**。
排除线三条：**显示不出来 / 在说事（功能符号）/ 排开扎眼**——前两条机器可判，第三条靠眼睛。

## 2. 实施

### 2.1 定范围 + 勾叉归位（112 → 103）

- **走 10 个**：`✓✔✗✘`（拿它在说事，标"对/错"）+ `🙬🙭🙮🙯` 火箭（画的是具体器物，铺开还是一堆火箭）

  - ⚠️ 用户裁定 **`✕✖` 双挂进去**——官方名是 `MULTIPLICATION X`（乘号），但视觉上就是叉，人们拿它当"错号/关闭"用，**两句话都真就两条都挂**

  加了主名（叉号 / 叉号按钮 / 对勾按钮），直译兜底就不进拼接名了

## 3. 经验教训

### 3.1 审阅工具：visual companion（brainstorming skill 的）

用户提议用它——**它在"人要看一眼才能定"的场合很好用**：

```bash
<superpowers>/skills/brainstorming/scripts/start-server.sh     # Windows 下要 run_in_background
# → 返回 {url(带?key=…), screen_dir, state_dir}
# 写 HTML 到 screen_dir，用户在浏览器点选
```

**三个坑**：

1. **事件不在 `state_dir/events` 里**（文档说在那里）。这个版本把事件**打到 stdout**
   （`fs.appendFileSync` 那段没生效）。**读 `server-info` 同目录、或读启动它的后台任务输出文件**。
   ⚠️ 我照文档读 `events` 文件，读了个空，白等用户一轮。
2. **全文档模式（`<!DOCTYPE` 开头）服务器"原样服务 + 注入 helper"**，能完全控制样式——
   205 个字符排网格必须走这条路（片段模式只有 `.options/.cards` 那几种预设样式）。
3. **点击只改 CSS 不会上报**。helper 只监听带 `data-choice` 的元素，且 `toggleSelect` 只管样式。
   要拿到结果必须**自己调 `window.brainstorm.send()`**——最稳的是**每次 toggle 都发完整状态**，
   不依赖用户记得点"提交"。

**一个 bug**：`.guess`（我预判该删的粉框）和 `.del`（用户标的红）是两套独立样式，
取消时只摘 `.del`，底下粉底还在，永远回不到白色。**修法：一交互就 `classList.remove('guess')`。**

### 3.2 判据「排开看」是这轮最有价值的产出

单个竖线 `།` 看不出任何价值；**排成一排就是竖条纹**——那正是花纹。
**"重复排"不是辅助手段，它就是判据本身**，跟用户说的"按最小重复部分看复杂度"是同一件事。

**推论**：**别问「它算不算花纹」**。实测这一问的答案是"算"——
一铺开几乎什么都好看，`᧠`（高棉数字符）都能排得整整齐齐。
所以收的标准只能是**排除**：显示不出来 / 在说事 / 排开扎眼。**这也把用户的工作量从"逐个判"降到"扫一眼挑刺眼的"。**

### 3.3 判据要立成文档，不能只活在对话里

`✓028` 那轮立的「领域自足」「方向性：宽域收全、窄域不收」是**按语义**的；
这轮立的「按形的正交根」是**按外观**的——两种根并存，得在 `语义树结构.txt` 里说清，
否则下一个人看到 `装饰、花纹` 跟 `数学/几何` 大面积重合，会以为数据脏了。

### 3.4 还没做的账（留给后续）

- **`BINDU`/`PADA`/`SURYA`/`PURNAMA`/`CAKRA`/`RERENGGAN` 这批实词没译**。
  它们是梵语/爪哇语的实词（点/句/太阳/满月/轮/装饰），却被 `译名词表.py` 的 **`KEEP`** 当"转写名"保留，
  于是直译名成了 `巽他标点BINDU SURYA` 这种天书，而且**静默漏报**（不在 `待译清单.py` 的 b 节里）。
  修法：挪进 `WORD` + `set_zh` 回填。**这是独立一轮的活。**
- **其他文字系统没扫**（中东/非洲/美洲/欧洲），按停机门收在这里。
