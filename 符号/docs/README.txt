符号页文档

简述
	会有「完成」的一天吗？会 → 任务；不会 → 设计。
		任务：放在“任务/”目录下。一次性的工作项，做完就关。读者是接下这个任务的人
		设计：放在“设计/”目录下。长期成立的规则与由来。读者是要改这块东西的人。
	一次工作通常出两份：任务 记这一轮做了什么（关闭后冻结），设计 记做完之后现在是什么样（后续任务继续更新它）。
	数据层的设计文档是 符号/数据说明.md，暂时不纳入本目录。

任务文件命名
	<状态字符><3 位序号>-<摘要名>.txt
		例：·001-详情标签不显示全路径.txt
	状态字符：
		! 阻塞
		· 未开始
		… 进行中
		✓ 已完成
		✗ 已取消
	状态字符在最前。序号补零到 3 位、单调递增、永不重用。
	2026-09-16 之前的历史任务沿用当日原名「日期-主题.md」，不带状态字符也不带序号，
	格式未迁移（它们是完整叙述，不是紧凑条目）。读的时候两者平等，按需要的年代取。
	正文的「进度」是唯一真相，文件名里的字符是它的速记，推进时一起改。

旧编号
	todo.txt 时代用的是分类内编号：功能 1-5 / 优化 1-29 / bug N / 数据清理 N，四套并行。
	它只在那一个文件内有参照，与本目录的序号无关，已废弃、不再恢复。
	承接了旧条目的任务文件里写有一行「旧编号：xxx」。要按旧编号找：
		grep -rl "旧编号：优化 21" 符号/docs/任务/

文件内容
	固定头四行：
		进度：未开始 | 进行中 | 阻塞 | 已完成 | 已取消
		优先：可选。表示是否优先，优先任务可以插队。不写表示普通优先级。
		创建：YYYYMMDD
		验收标准：要能回答「怎样算做完」。
	其余正文自由，常见小节：背景、相关代码锚点、重现方法、设想、猜测、调查结果、方案、风险、经验教训等。
	正文按时间追加，不就地改写：猜测被推翻要留着（猜是 X → 查证：不是，原因是 Y），删掉的话下一个人会把 X 再猜一遍。

关闭任务
	1 正文写清结论，补一行版本号（commit message 里也记）
	2 该沉淀的知识写进 设计/。
	3 改状态字符、正文进度改成终态
	第 2 步最容易漏。判据：这条结论在下一个任务里还会用到吗？

和记忆的分工
	本目录放规则、约束、由来、结论，按需读。
	记忆放判断和指针，索引每次会话无条件载入，所以要小。
	判据：这条知识换个页面还成立吗？成立 → 记忆；绑死在本页 → 设计/。

如对本文件的规定有异议，先参考《规定由来.txt》看看现有规定是否已过时。平时不用读。
